# Naming the shared Aggregate Agent behavior definition

**Date:** 2026-10-21. **Status:** Source research and naming recommendation. No implementation or parent-plan changes.

## Recommendation

Use `AggregateAgentNodeDefinition` for the proposed shared declaration, with constructor `makeAggregateAgentNodeDefinition` and type `IAggregateAgentNodeDefinition`. It references the canonical agent release and declares per-row behavior state, initialization, decisions and retry/delay policy. Both `AggregateAgentNode` and `AggregateAgentBackendNode` consume it. This is a proposed name and interface, not an existing export.

`AggregateAgentSessionDefinition` is understandable given existing repository vocabulary, but less precise for this design: the shared behavior runs in either Node host, while the existing Agent Session owns the browser application facade. This recommendation follows the current ownership split; it does not require renaming ordinary Aggregate/Service session definitions. [Node owner](../../packages/core/src/AggregateAgentNode/AggregateAgentNode.ts#L56-L59), [Agent Session facade](../../packages/core/src/agent/types.ts#L114-L129), [browser Session construction](../../packages/browser/src/makeAggregateAgentSession.ts#L14-L35).

| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `AggregateAgentNode` owns local commands, the authoritative selected baseline, optimistic resources and publication. Its constructor receives a declaration separately from its database and runtime inputs. | A declaration configuring behavior inside either Node naturally names the Node abstraction. | `IAggregateAgentSession` is a thin execution/lifecycle facade over one transient Node. `makeAgentSessionHost` owns application execution and lifecycle, rather than Node command/resource facts.             | Calling shared Node behavior a Session definition would suggest a broader relationship to the facade than the new design needs. [Session type](../../packages/core/src/agent/types.ts#L114-L129), [host responsibilities](../../packages/browser/src/agentNodeBrowser/makeAgentSessionHost.ts#L26-L36).                                                                                                                                                                                                            |
| `IAggregateAgentRelease` already fixes system/Aggregate/agent/session identity, query database, selections and contracts. It contains no autonomous behavior.                                                | Keep this declaration as the canonical release and reference it once from the Node definition. Do not duplicate the selection/contract registry or overload `AgentRelease` with host configuration. [Release shape](../../packages/core/src/agent/types.ts#L28-L45).                                                                                                                                                                                                                                               |
| Today the Node and Session both receive the release through a field named `sessionDefinition`.                                                                                                               | Existing field names explain the earlier naming suggestion; they do not establish that the proposed behavior declaration is already implemented. [Node constructor](../../packages/core/src/AggregateAgentNode/AggregateAgentNode.ts#L96-L109), [Session constructor](../../packages/browser/src/makeAggregateAgentSession.ts#L15-L34).                                                                                                                                                                            |

## Proposed separation

| Declaration or owner                               | Responsibility                                                                                                                                                  |
| -------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `AggregateAgentRelease`                            | Canonical versioned visibility, model/selection identity and permitted commands.                                                                                |
| `AggregateAgentNodeDefinition`                     | Shared per-row behavior state schemas, initialization, decision program and retry/delay policy, referencing that release.                                       |
| `AggregateAgentNode` / `AggregateAgentBackendNode` | Chosen execution host, producer, synchronization, state storage and scheduling implementation. Browser state is transient; backend state/deadlines are durable. |
| `AggregateAgentSession`                            | Browser application execution/lifecycle facade exposing its current Node.                                                                                       |

Proposed authoring shape:

```ts
const purchasesAgentNodeDefinition = makeAggregateAgentNodeDefinition({
  agent: purchasesAgentRelease,
  behaviors: { purchase: purchaseBehavior },
});
```

The definition remains cold and portable. Host choice belongs to instance creation/configuration, with one chosen host for a given behavior instance as agreed in the parent discussion. Browser/backend storage, credentials, transport, runtime acquisition and alarm APIs remain host wiring. A definition shares behavior code; it does not itself provide shared state, single-owner enforcement or host handover. These are design implications, not claims of current runtime support.

If adopted, replace the proposed `AggregateAgentSessionDefinition` name outright in the affected design rather than keeping two aliases. Preserve existing `sessionName` where it identifies the declared command/admission session; the new definition name alone is no reason to rename protocol identity fields. The current release explicitly retains `sessionName`. [Release identity](../../packages/core/src/agent/types.ts#L35-L44).
