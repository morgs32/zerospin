# QRK User release replay and payload adaptation

Investigated 2026-11-11 against Zerospin `cc180bbab7` and the installed QRK framework version `43.1.3`. QRK's local Worker accepted the authored SystemSpec, then hit an older User release's missing reverse payload adapter during materialization. A second, distinct failure affects V12-only Brick modules when their commands reach older registered releases.

## What local storage and the Worker show

- The generated SystemSpec hash was `68728917130197ced0c296fe029dfa73960ff8f8212f19c1067a1aa18b9f20c7`, identical to the latest accepted local snapshot. Comparing immutable facts across all four locally accepted snapshots found zero mismatches. The QRK backend typecheck and all 23 tests passed. `makeSystem` validates declarations and bindings, and `acceptSystemSpecTx` checks immutable portable facts. Neither runs retained command materialization. [System declaration validation](../../packages/core/src/system/make/makeSystem/makeSystem.ts#L102), [spec acceptance](../../packages/system-worker/src/SystemRepo/acceptSystemSpec/acceptSystemSpecTx.ts#L12), [immutable compatibility check](../../packages/system-worker/src/SystemRepo/acceptSystemSpec/checkSystemSpecCompatibility.ts#L51), [QRK test log](/tmp/qrk-zerospin-nov11.log).
- The local AggregateChain had admitted and finalized through aggregate index 124. The adopted canonical V9 history ended at 122. The replay cursors were V9=122, V10=122, V11=124, V12=0. Index 123 is a V11 `updateBrick@6` for `swatch-and-icon` with a successful original outcome. Index 124 is a successful V11 `updateSiteSettings@3`. `AggregateVersionRepo.catchupMaterialization` logged “Missing down adapter for updateBrick” around the same reload that printed “system spec accepted.” A V12 replay cursor at zero is insufficient evidence to name a V12 failure. [Local Worker log](/tmp/qrk-plan068-restored-dev.log#L153), [AggregateChain replay fanout](../../packages/system-worker/src/AggregateChain/AggregateChain.ts#L151), [ordered replay reads](../../packages/system-worker/src/AggregateChain/readReplayPage.ts#L15).
- V9 retained 19 release-local `aggregate-contract-unsupported` outcomes for V10 commands that V10 and V11 supported (15 `setRowAlignment@1`, four `setRowPreferredWidth@1`). V9 lacks those Actor grants. Those outcomes advanced replay. Index 123 is a different failure because V9 and V10 both expose `updateBrick` and reach its adaptation path. [QRK V9 Actor](../../../qrk.sh/apps/zerospin/src/aggregates/user/actors/userActorV9.ts), [QRK V10 Actor](../../../qrk.sh/apps/zerospin/src/aggregates/user/actors/userActorV10.ts), [release-local refusal classification](../../packages/system-worker/src/AggregateVersionRepo/utils/executeAggregateCommandTx.ts#L89).

## Why the V11 command stalls V9 and V10

QRK registers User releases 9 through 12 with 9 canonical. The App session binds Aggregate and Actor 12. AggregateChain routes original execution to the admitted command's own `aggregateVersion`. Its canonical selection determines which release supplies the adopted replay history. A candidate can finalize an original without promotion. [QRK registry](../../../qrk.sh/apps/zerospin/src/system.ts), [QRK App session](../../../qrk.sh/apps/app/zerospin/userSessionDefinition.ts), [admission and original delivery](../../packages/system-worker/src/AggregateChain/AggregateChain.ts#L467), [adopted canonical history](../../packages/system-worker/src/AggregateChain/adoptCanonicalAggregateHistory.ts#L7).

V9 binds `updateBrick@4`, V10 binds `@5`, V11 binds `@6`, and V12 binds `@7`. Replaying V11's command on V9 or V10 requires crossing `6 → 5`. V6 inherited V5's payload unchanged and omitted that edge's `down`; V5 already defines identity `5 → 4`. The SDK supplies validated forward identity when `up` is omitted and requires an explicit reverse adapter. The missing edge emits `contract-payload-adapter-missing`, which escapes the replay transaction without materializing a release-local outcome or advancing the cursor. The existing handbook specifically calls for explicit identity reverse adapters for unchanged payloads. [QRK V5 edge](../../../qrk.sh/apps/zerospin/src/aggregates/user/contracts/brick/UpdateBrickV5.ts), [QRK V6 edge](../../../qrk.sh/apps/zerospin/src/aggregates/user/contracts/brick/UpdateBrickV6.ts), [ordinary edge construction](../../packages/core/src/contracts/make/constructContractRelease.ts#L470), [payload traversal](../../packages/core/src/contracts/decodeAndAdaptPayload/adaptPayload/adaptPayload.ts#L76), [release execution resolution](../../packages/system-worker/src/AggregateVersionRepo/utils/resolveAggregateExecution.ts#L101), [replay execution policy](../../packages/system-worker/src/AggregateVersionRepo/utils/executeAggregateCommandTx.ts#L89), [handbook](../../docs/content/handbook/versioning-and-deployment.md#add-functionality-through-a-new-release).

Adding the explicit identity `down` on V6 preserved the payload shape and produced a byte-identical compiled SystemSpec matching the locally accepted hash. The post-fix Nx target passed typechecking and all 23 tests. Actual Chain rows 123 and 124 decoded and adapted to V9, V10 and V12. The ordinary payloads from all 124 positions in the V9 Archive prefix and AggregateChain tail decoded and adapted to V12. These checks establish the codec path. Recovery still requires the existing AggregateVersionRepos to materialize and publish through the retained prefix. [Portable spec compilation](../../packages/core/src/system/make/makeSystemSpec.ts#L138), [replay materialization](../../packages/system-worker/src/AggregateVersionRepo/replayCommands/replayCommand.ts#L13).

## V12-only module IDs need a separate release policy

V12 expands Brick module IDs to Behance and Buy Me a Coffee. Its `addBrick@7` and `updateBrick@7` down adapters reject those IDs explicitly with `brick-module-release-required`. In an offline probe against the installed SDK, both Behance commands produced `contract-payload-adapter-failed` when decoding into V11. `runAuthoredCallback` wraps that typed failure, and the error exits `resolveAggregateExecution` before `executeAggregateCommandTx` has an execution contract. The same ordinary edge is required for V9 and V10. `GenerateBrickSpecExternal@5` declares an equivalent reverse refusal for the payload/outcome pair. Source inspection shows it takes the external adapter failure path. No external continuation was exercised. [Add adapter](../../../qrk.sh/apps/zerospin/src/aggregates/user/contracts/wall/AddBrickContractV7.ts#L11), [update adapter](../../../qrk.sh/apps/zerospin/src/aggregates/user/contracts/brick/UpdateBrickV7.ts#L87), [recorded external adapter](../../../qrk.sh/apps/zerospin/src/aggregates/user/contracts/brick/GenerateBrickSpecExternalV5.ts#L84), [callback error handling](../../packages/core/src/execution/runAuthoredCallback.ts#L36), [recorded external adaptation](../../packages/core/src/contracts/decodeAndAdaptExternalCommandInput.ts#L76).

The framework already knows how to advance when a valid admitted command is unsupported by the executing release. It needs a way to distinguish an intentionally unrepresentable payload from a broken adapter if QRK is to keep these releases consuming one Chain and enable V12-only writes. A framework change should preserve source declaration, authority and input validation, then record the executing release's existing unsupported outcome for a narrowly defined intentional reverse refusal. Keep absent adapters, malformed adapter results, and unexpected failures on the error path. Verify a V12-only original and older release-local refusal followed by a supported command on the same history. Account for follow-up commands on the skipped Brick and their effect on older release state. The existing refusal implementation explicitly keeps adapter failures separate, so making every adapter failure a refusal would hide the V6 declaration bug. [Plan 291](../archive/plans/291-plan-contract-support-refusals.md), [Aggregate adapter regression cases](../../packages/system-worker/tests/aggregate-adapter-failures/aggregate-adapter-failures.workerd.spec.ts#L1292), [Service adapter regression cases](../../packages/system-worker/tests/service-adapter-failures/service-adapter-failures.workerd.spec.ts#L546), [replay execution policy](../../packages/system-worker/src/AggregateVersionRepo/utils/executeAggregateCommandTx.ts#L89).

The 43.1.1 browser refresh fix handles unavailable exact release bindings. The 43.1.2 catalog work preserves the reviewed QRK legacy catalog and rejects immutable conflicts before durable writes. Neither changes reverse payload adaptation or the replay refusal policy. [Browser refresh commit](https://github.com/morgs32/zerospin/commit/a921a5d80cb7e8543f01fc8ce0782df45c96fb92), [catalog migration commit](https://github.com/morgs32/zerospin/commit/0ab58f40d2a10aedbdf383519f1c98963d7a8c83), [catalog preflight commit](https://github.com/morgs32/zerospin/commit/8a6515257f38004a757e637460cff1c57eba7bed).

## Implementation and verification

Ordinary and recorded external down adapters now return the SDK's
`DownAdapterRefused` sentinel for valid inputs they cannot represent. The
Aggregate and Service replay paths validate the source input and authority before recording
their existing release-local unsupported outcome. Original execution and
missing, broken, asynchronous, or invalid-output adapters still fail without
advancing materialization. QRK uses the signal in the two ordinary Brick
adapters and the recorded external adapter that reject V12-only module IDs.
[Authoring guide](../../docs/content/handbook/versioning-and-deployment.md#add-functionality-through-a-new-release).

- The focused Aggregate and Service Workerd suites passed all 55 tests.
  They cover continued replay after a refusal and no materialization on an
  adapter fault. The recorded external refusal retained its observation and
  made no provider request.
- An isolated SQLite run of the patched `AggregateVersionRepo.materializeCommandTx`
  used the real QRK releases, the 122-command V9 Archive prefix, and the two
  finalized AggregateChain commands at indices 123 and 124. V9, V10, and V11
  restored their available retained output and reached index 124. V12
  materialized the full 124-command prefix. An appended Behance add finalized
  on V12 at 125. V9, V10, and V11 each recorded
  `aggregate-contract-unsupported` with no model operations and successfully
  materialized a supported add at 126. The run opened retained storage read-only
  and executed writes against fresh in-memory databases. Repeating the same
  replay with the down adapter removed or throwing left V9, V10, and V11 at
  index 124 without an outbox row for 125. The check covered materialization
  and did not exercise Chain fanout or publication acknowledgements.
- The compiled SystemSpec was byte-identical to the locally accepted snapshot.
