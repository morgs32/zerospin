## Finding

**External work does not intrinsically need a framework receiving address.** Zerospin runs an opaque authored `external.request({ payload })`; it retains declaration identity, frozen payload and outcomes so unfinished work can recover. Its recorded continuation returns to the originating admission chain. The chain still executes the command's retained release and replays finalized input through other versions normally. Returning to that chain does not require every replay to execute in the original VersionRepo. [Request invocation](../../packages/core/src/contracts/externalExecution/executeExternalRequest.ts), [source declaration resolution and child reconstruction](../../packages/system-worker/src/externalOperations/readPreparedExternalCommand.ts), [ordered execution](../adrs/005-ordered-original-execution-and-finalized-replay.md).

The superseded design combined external execution with addressed command delivery. Shopping used a no-op external purchase request to reach a different aggregate. That was a choice of orchestration mechanism, not evidence that external effects inherently need destination metadata. The [handoff](../archive/handoffs/2026-10-14-handoff-opaque-external-work.md) corrected this research's earlier proposal to restrict continuation execution to the exact originating VersionRepo. [Historical addressed decision](../adrs/010-source-owned-addressed-async-continuations.md), [replacement decision](../adrs/012-opaque-external-work-and-originating-chain-continuations.md).

## Current boundary

1. **Source identity comes from the containing repo.** The physically separate aggregate/service databases retain `asyncOperations`; the work schema contains no `receivingAddress` or redundant emitter tuple. System name, origin and child identity are required because only original execution stores work. Pending declarations resolve within the source release. [Work schema](../../packages/system-worker/src/externalOperations/externalOperationsDbConfig.ts), [local resolution](../../packages/system-worker/src/externalOperations/readPreparedExternalCommand.ts#L40-L58), [aggregate runner](../../packages/system-worker/src/AggregateVersionRepo/AggregateVersionRepo.ts), [service runner](../../packages/system-worker/src/ServiceVersionRepo/ServiceVersionRepo.ts).
2. **Only original execution persists external work.** Replay drops async output before preparation. Authoritative output readers and replica projections carry model operations only. Filtering preserves authored `operationIndex` values; validation accepts safe nonnegative strictly increasing indexes and checks command/chain-position association instead of requiring dense array ordinals. [Aggregate preparation](../../packages/system-worker/src/AggregateVersionRepo/utils/prepareAggregateOutput.ts), [service preparation](../../packages/system-worker/src/ServiceVersionRepo/utils/prepareServiceOutput.ts), [model output readers](../../packages/system-worker/src/externalOperations/readOperationOutput.ts), [aggregate projection](../../packages/system-worker/src/aggregateProjection/applyEvaluatedCommands/bindProjectionCommand.ts), [service projection](../../packages/system-worker/src/serviceProjection/prepareServiceProjectionOccurrence.ts).
3. **A response and its outbox entry commit atomically.** `responseRecordedAt` distinguishes a valid JSON-null response from pending work. `externalFailure` records a terminal outcome without a child; the first committed response or failure wins. Authors own request retryability, bounds and provider idempotency. A process lost before recording may repeat the request. Delivery recovery remains independent and uses recorded evidence without repeating provider work. [Recording and recovery](../../packages/system-worker/src/externalOperations/makeExternalOperationQueue.ts), [retry decision](../adrs/011-author-owned-external-request-retries.md).
4. **Recorded continuation delivery proves the complete child.** Aggregate/service chain context and the command's retained release identify the original VersionRepo. Reconstruction uses frozen payload, response, origin and System name with that repo's identity; it requires neither a current external declaration nor the originating command row. Exact retained retries recover before fresh admission checks. [Concrete proof](../../packages/system-worker/src/externalOperations/verifyExternalCommandDeliveries.ts), [reconstruction](../../packages/system-worker/src/externalOperations/readPreparedExternalCommand.ts), [aggregate admission](../../packages/system-worker/src/AggregateChain/admitExternalCommands/admitExternalCommands.ts), [service admission](../../packages/system-worker/src/ServiceChain/admitExternalCommands/admitExternalCommands.ts), [authority decision](../adrs/008-ordinary-and-recorded-continuation-authority.md).

## Shopping's authored read-only quote

The command/query checkout cutover co-owns carts and purchases in the user aggregate. Checkout freezes line identities, product IDs and quantities, then schedules local `getExternalPurchaseQuote`. Its external request calls Marketplace's read-only `quotePurchase` query through the configured authenticated SystemApi. The continuation validates and stores pricing before scheduling payment. No receiving-address or command-emission framework is required. [Checkout](../../examples/shopping/src/zerospin/aggregates/user/contracts/checkoutServerV1.ts), [opaque quote request](../../examples/shopping/src/zerospin/aggregates/user/contracts/getExternalPurchaseQuoteV1.ts), [combined research](shopping-command-query-checkout.md).

The app-owned lazy capability layer obtains the configured API endpoint and secret at invocation time, keeping credentials out of persisted payloads. The backend requires `SHOPPING_ZEROSPIN_API_URL` and `ZEROSPIN_SECRET_KEY`. [Capability](../../examples/shopping/src/zerospin/ShoppingSystemApi.ts), [configured layer](../../examples/shopping/src/zerospin/ShoppingSystemApiLive.ts), [configuration](../../examples/shopping/zerospin.config.ts).

## Evidence and limits

The now-removed runtime acceptance script exercised production procedures, original/replay persistence, sparse model indexes, frozen proof, terminal outcomes, recovery and frozen authored request payload. Shopping's updated contract and configured Worker checks exercise read-only quotation before payment; see the combined checkout research for current evidence. These are contained runtime checks, not provider delivery, deployment or application browser verification. Changed fixed schemas require empty affected storage; no compatibility decoder, row translation or local/live reset was introduced.
