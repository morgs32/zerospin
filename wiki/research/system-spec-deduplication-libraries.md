# SystemSpec deduplication libraries

**Date:** 2026-11-03

**Scope:** Primary-source review and temporary local experiments with Mentor Mailbox's detached, 4,296,541-byte SystemSpec. No repository dependencies or implementation were changed by this research.

## Recommendation

Do not adopt any investigated library as an unrestricted JSON storage codec. `compress-json` achieves the right kind of structural deduplication and a large reduction, but silently corrupts valid property names. `json-deduper` also deduplicates detached values, but fails a round trip of the actual SystemSpec. `devalue` and `flatted` primarily deduplicate object identity, so they do not remove the duplicated definitions across separately compiled release snapshots. These conclusions concern the tested versions below; they are not claims that every serialization library has these defects.

Prefer removing repeated model definitions at their owning SystemSpec representation, using explicit versioned references to a single owner-local definition. That is an architectural recommendation, not an implementation or compatibility plan. Preserve each immutable declaration and its lineage; do not drop retained releases to shrink the input. The current compiler already gives contracts an owner-local registry, while releases are compiled separately. [SystemSpec compiler](../../packages/core/src/system/make/makeSystemSpec.ts)

## Candidate findings

- **compress-json 3.4.0:** Structurally interns encoded arrays, objects, values and key schemas, including equal detached objects. The default does not sort keys, so equal values with different insertion orders need not share a representation. Its synchronous JavaScript codec has browser/ESM/CommonJS entry points, no runtime dependencies, BSD-2-Clause licensing, and 51,440 unpacked npm bytes. The registry's latest release is dated 2025-09-21. Browser/Worker execution was not tested here. [Encoder source](https://github.com/beenotung/compress-json/blob/master/src/memory.ts), [package metadata](https://registry.npmjs.org/compress-json/3.4.0)
- **devalue 6.0.3:** By default the encoder's reference map keys objects by identity, not structural content. Its customizable identification operation would still require us to supply structural identity. It rejects objects with an own `__proto__` property. Its README explicitly excludes serialization-format stability between releases as a goal. MIT, no runtime dependencies, 135,025 unpacked bytes; released 2026-10-13. [Encoder](https://github.com/sveltejs/devalue/blob/main/src/stringify.js), [format goals](https://github.com/sveltejs/devalue#non-goals), [package metadata](https://registry.npmjs.org/devalue/6.0.3)
- **flatted 3.4.4:** The reference map keys objects by identity and also interns equal strings. It preserves the reserved-key probe below, but the detached real spec becomes larger. ESM/CommonJS/browser variants, ISC, no runtime dependencies, 38,501 unpacked bytes; released 2026-07-30. [Encoder/decoder](https://github.com/WebReflection/flatted/blob/main/esm/index.js), [package metadata](https://registry.npmjs.org/flatted/3.4.4)
- **jsonpack 2.0.0:** Dictionaries compress keys and scalar strings/numbers; this is not general equal-subtree interning. Its valid-key and numeric failures below exclude it for arbitrary JSON. Browser/ESM/CommonJS support, MIT, no runtime dependencies, 16,993 unpacked bytes; released 2026-06-20. [Implementation](https://github.com/rgcl/jsonpack/blob/main/index.js), [package metadata](https://registry.npmjs.org/jsonpack/2.0.0)
- **@mattkrick/json-deduper:** A real MIT repository, declaring version 0.0.1, with structural hashing via `JSON.stringify` and optional string/number deduplication. Both compression and decompression mutate their inputs. The tested official master commit is `16562b17138d80e9c122787fa6eb705703b75a8b`, dated 2019-07-10; its advertised scoped npm package returned HTTP 404 on this research date. Source experiments used that commit, bundled only in `/private/tmp`; the package declares a `tslib` peer dependency. [Compression](https://github.com/mattkrick/json-deduper/blob/16562b17138d80e9c122787fa6eb705703b75a8b/src/compress.ts), [mutation contract](https://github.com/mattkrick/json-deduper/blob/16562b17138d80e9c122787fa6eb705703b75a8b/README.md), [package](https://github.com/mattkrick/json-deduper/blob/16562b17138d80e9c122787fa6eb705703b75a8b/package.json)
- **@jsonjoy.com/json-pack 18.30.0:** A broader Node/browser serialization suite for MessagePack, CBOR, JSON and other formats. Its documented format support does not establish automatic structural interning of equal detached subtrees, so it was not benchmarked as a substitute for that requirement. Apache-2.0, 1,027,416 unpacked bytes and ten direct runtime dependencies; released 2026-09-08. Package size covers the entire suite, not a tree-shaken codec. [Current monorepo documentation](https://github.com/streamich/json-joy/tree/master/packages/json-pack), [package metadata](https://registry.npmjs.org/@jsonjoy.com%2fjson-pack/18.30.0)

Unpacked npm sizes include declarations and other shipped files; they are not browser bundle sizes. Release dates describe observed publication activity, not correctness or support guarantees. The unscoped name `json-dedup` also returned npm HTTP 404; this does not establish that no similarly named project exists.

## Actual payload experiment

Input was parsed from `/private/tmp/plan028-system-spec.json`, ensuring repeated definitions were detached objects rather than shared identities. Official npm tarballs were extracted without running install scripts. Timings are medians of five local Node 24 runs, including serialization of each codec's output and parsing before decode. Input-clone preparation for the mutating deduper was outside the timed section. These are bounded local measurements, not production Worker benchmarks.

- JSON: **4,296,541 bytes**, encode **11 ms**, decode **20 ms**; exact round trip.
- devalue: **3,672,261 bytes**, **80 / 47 ms**; exact round trip of this payload.
- flatted: **4,535,491 bytes**, **68 / 233 ms**; exact round trip of this payload.
- compress-json: **103,514 bytes**, **92 / 208 ms**; exact round trip of this payload, but fails valid JSON below.
- jsonpack: **1,264,398 bytes**, **204 / 39 ms**; exact round trip of this payload, but fails valid JSON below.
- json-deduper, default options: **285,990 bytes**, **92 / 2.7 ms**; **round trip fails on this payload**. With `strings: true`, 265,764 bytes and the same numeric loss. With `numbers: true`, ordinary numeric values are corrupted and repeated encodings also differed.

Default tested encodings were repeatable for the same input and insertion order. This does not establish canonical encoding across key order, releases or runtimes. Temporary evidence: `/private/tmp/plan028-json-libraries/benchmark.mjs`, `benchmark.json`, and `json-deduper-benchmark.json`.

## Correctness and decoder boundaries

**compress-json has two independent valid-JSON failures.** A JSON-parsed own `__proto__` property is lost and becomes the decoded object's prototype because the decoder constructs `{}` and assigns `o[k] = v`. This did not modify global `Object.prototype` in the probe. Separately, its comma-joined key-schema cache conflates `["a,b", "c"]` with `["a", "b,c"]`: `{first:{"a,b":1,c:2},second:{a:1,"b,c":2}}` round-trips with both children equal to the first. This is silent data corruption without prototype keys. [Decoder](https://github.com/beenotung/compress-json/blob/master/src/core.ts), [schema cache](https://github.com/beenotung/compress-json/blob/master/src/memory.ts)

Separate compress-json probes passed for `constructor`, `toString`, empty keys, pipe-containing keys/strings, reference-looking strings, null, booleans, empty containers, zero, negative numbers, finite fractions, `1e308`, `5e-324`, NUL and Unicode. Passing the normal spec is insufficient: authored JSON Schema property names can contain the failing keys.

**json-deduper fails existing schema facts.** Its default positive-integer encoding computes `2k + 1`; `Number.MAX_SAFE_INTEGER` loses precision and becomes an even reference index. The actual spec's `sendInvitationEmail` payload schema `deliveryAttempt.maximum` therefore becomes `undefined` after decoding. A finite `1e308` becomes null after serialization; `strings: true` throws on `"__proto__"`, `"constructor"` or `"toString"` because its string cache is a normal object. Default reserved-property-name and comma-schema probes passed. [Number encoding and caches](https://github.com/mattkrick/json-deduper/blob/16562b17138d80e9c122787fa6eb705703b75a8b/src/compress.ts), [reference decoding](https://github.com/mattkrick/json-deduper/blob/16562b17138d80e9c122787fa6eb705703b75a8b/src/decompress.ts)

**jsonpack fails additional valid inputs.** Each of the property names `__proto__`, `constructor` and `toString` causes a TypeError. Its `1e308` round trip produces `1.0000000000000008e308`. These were independent local probes against the published 2.0.0 package. [Published implementation](https://registry.npmjs.org/jsonpack/-/jsonpack-2.0.0.tgz)

The codecs are not SystemSpec validators or hash authenticators. For example, compress-json accepts an out-of-range reference as `undefined`, and a recursive reference overflows the stack; json-deduper also accepts out-of-range references as `undefined`. An outer JSON parser does not validate these internal references. A general compact codec would need bounded reference/depth/expansion validation, then the actual SystemSpec schema and content-hash checks. Hash checking after decode detects changed content; it does not prevent decoder resource exhaustion. Keep those concerns distinct. [compress-json decoder](https://github.com/beenotung/compress-json/blob/master/src/core.ts), [json-deduper decoder](https://github.com/mattkrick/json-deduper/blob/16562b17138d80e9c122787fa6eb705703b75a8b/src/decompress.ts), [current SystemRepo validation](../../packages/system-worker/src/SystemRepo/acceptSystemSpec/acceptSystemSpecTx.ts)
