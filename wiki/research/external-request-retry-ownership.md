# External request retry ownership

**Date:** 2026-10-13  
**Scope:** Current Zerospin source, installed Effect implementation and first-party documentation. Provider calls and actual Durable Object process termination are outside this research.

> **Ownership update, 2026-10-15:** The lifecycle descriptions below record the earlier VersionRepo request/observed-command design. Plans 195/196 moved pending request execution and atomic external observation/admission into AggregateChain and ServiceChain. The intermediate observed-command outbox, FIFO allocator and remote proof paths were removed. See [current recovery ownership and crash-boundary research](chain-external-recovery-and-delivery-ownership.md). Historical verification results below remain evidence of their recorded source revision. Request retry ownership and the distinction between `externalOutcome` and `commandOutcome` still apply.

## Findings

1. **Authors can express their own retry policy already.** Both external factories accept an arbitrary request Effect producing their response codec's type. Effect supplies bounded retries, predicates and schedules. Its schedule state exists only during the live runtime; another invocation begins that policy again. [Aggregate factory](../../packages/core/src/contracts/make/makeAggregateExternalContract.ts), [service factory](../../packages/core/src/contracts/make/makeServiceExternalContract.ts), [Effect retry documentation](https://effect.website/docs/v4/error-management/retrying), [Effect schedule persistence](https://effect.website/docs/v4/scheduling/using-schedules).

2. **The previous automatic loop defeated bounded author policies.** Before this cutover, the producer caught request, resolution, codec and recording failures and wrote a new `nextRunAt` using `retryDelayMs`, without classifying failures or limiting invocations. Exhausted author retry policies therefore restarted. The current cut deletes that loop, the deadline column and retry-delay declaration/spec fields. [Producer runtime](../../packages/system-worker/src/externalOperations/makeExternalOperationQueue.ts), [external constructor](../../packages/core/src/contracts/make/constructContractVersion.ts), [SystemSpec projection](../../packages/core/src/system/project/projectContractSpec.ts).

3. **The durable outcome is the correct stopping boundary.** Original work remains pending until a response or producer failure commits. The first outcome is immutable. A response and its continuation outbox entry commit in one synchronous transaction; failure commits without creating a child. JSON null is a valid response, so the recording timestamp distinguishes it from unfinished production. The originating command retains its already-finalized result. [Lifecycle schema](../../packages/system-worker/src/externalOperations/externalOperationsDbConfig.ts), [response/failure recording](../../packages/system-worker/src/externalOperations/makeExternalOperationQueue.ts), [original aggregate finalization](../../packages/system-worker/src/AggregateVersionRepo/utils/makeEvaluatedAggregateCommand.ts).

4. **Recovery does not require a deadline on every operation.** The existing shared alarm registry schedules durable wakes. Recovery selects original work without either outcome and excludes recorded failures/responses. In-memory reservations prevent overlapping live invocations; current-row eligibility checks prevent stale recovery snapshots from restarting settled work. Alarm ownership also covers precommit callbacks and the recorded-child delivery handoff. [Alarm registry](https://github.com/morgs32/zerospin/blob/ece535eaf7f5d7fa5838347d45e490733c61bd5f/packages/system-worker/src/makeAlarmRegistry/makeAlarmRegistry.ts), [recovery runner](../../packages/system-worker/src/externalOperations/makeExternalOperationQueue.ts).

5. **An unrecorded provider outcome remains uncertain.** A provider may act before process loss or local recording failure. Recovery can repeat the request if neither outcome was retained. Cloudflare alarms are at least once and may restart after unexpected termination; an Effect schedule cannot recover its old in-memory budget. Authors own provider idempotency and reconciliation. This is an accepted limitation, not an exactly-once guarantee. [Cloudflare alarms](https://developers.cloudflare.com/durable-objects/api/alarms/), [Effect schedules](https://effect.website/docs/v4/scheduling/using-schedules).

6. **Timeout and retry ownership are separate.** Retain author-configurable `timeoutMs`, defaulting to 30 seconds, around one complete invocation including retry waits. A captured timeout is terminal. Authors can configure a longer total deadline or put shorter per-attempt deadlines inside their Effect. [Constructor default](../../packages/core/src/contracts/make/constructContractVersion.ts), [request timeout](../../packages/system-worker/src/externalOperations/makeExternalOperationQueue.ts), [Effect deadline guidance](https://effect.website/docs/v4/scheduling/cookbook).

7. **Settlement must survive ordinary Effect interruption.** Installed Effect can skip a plain recovery handler when an interruptible fiber is interrupted. Restore interruption for production and validation, then protect the terminal transaction and required alarm cleanup. Keep receiver delivery interruptible. A failed failure transaction leaves work pending and preserves both Causes. [Installed interruption implementation](../../packages/system-worker/node_modules/effect/src/internal/core.ts), [producer settlement](../../packages/system-worker/src/externalOperations/makeExternalOperationQueue.ts).

8. **The cut also affects accepted definitions.** SystemRepo retains JSON whose schemas derive from SystemSpec. Removing the retry-delay field changes that stored contract alongside VersionRepo producer columns. The pre-release cut requires empty affected SystemRepo and VersionRepo storage, with no translation or compatibility decoder. [Accepted-definition schema](../../packages/system-worker/src/SystemRepo/acceptedDefinitions/AcceptedDefinitionSchema.ts), [SystemRepo storage](../../packages/system-worker/src/SystemRepo/systemRepoDbConfig.ts).

## Verification

The implementation and required verification are complete in [Plan 147](../archive/plans/147-plan-author-owned-external-retries.md). The existing runtime acceptance script (`scripts/verify-plan140.mjs`, removed 2026-10-17) passed all eight groups using production procedures and local in-memory SQLite. Its async group proves author exhaustion stays terminal across alarms and recreated runners, first-outcome guards, concurrent live non-overlap, recorded-null child reconstruction, alarm handoffs and interruption/timeout finalizer settlement. A recreated runner checks retained-state recovery; it does not exercise actual Durable Object eviction or a real provider.

The scoped framework/consumer build, lint and type graph, all 19 existing Workerd tests, the existing inference acceptance file, regenerated schema capture, formatting and whitespace checks passed. Six existing Explorer UI warnings and Nx Cloud access code 401 remain; local verification passed. No new verification files or compatibility paths were introduced.
