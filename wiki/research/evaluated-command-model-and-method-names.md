# Evaluated Aggregate commands and method names

**Date:** 2026-10-15  
**Status:** Research and design recommendation. Plan 200 implementation is on hold. No production changes or verification are part of this note.  
**Scope:** Current working-tree Aggregate execution, publication, original acknowledgement and projection. The working tree already includes the four embedded-context removals; this is a source snapshot, not a claim that unfinished Plan 200 has passed verification. [Current operation schema](../../packages/system-worker/src/AggregateVersionChain/evaluatedAggregateCommand.ts#L9-L23).

## Main finding

**Use one evaluated-command value throughout transactional finalization, its reply, pending publication and immutable history.** `IEvaluatedAggregateCommand` is a useful name. A literal extension of the admitted command is a coherent model and eliminates a current reconstruction step, but it changes stored data: today's `IAggregateExecutionPacket` is a selected command context plus committed output, not the full command. This choice must be explicit rather than hidden inside a rename. [Admitted command](../../packages/core/src/contracts/CommandSchema.ts#L100-L123), [shared output](../../packages/system-worker/src/AggregateVersionChain/evaluatedAggregateCommand.ts#L25-L45), [current reconstruction](../../packages/system-worker/src/AggregateVersionRepo/utils/retainEvaluatedCommandTx.ts#L16-L32).

Today `finalizeAggregateOccurrence` already creates a complete `AggregateFinalCommandSchema`: it spreads the admitted command and adds the release-local `commandOutcome` and `dispositionChainHash`. `retainAggregateResultTx` then selects eleven output fields, changes `id` to `commandId`, and separately attaches the operations and execution timestamp. That second shape is saved and returned. The two domain values are an implementation choice, not two independently required lifecycles. [Final command schema](../../packages/core/src/contracts/CommandSchema.ts#L154-L173), [construction](../../packages/system-worker/src/AggregateVersionRepo/utils/makeEvaluatedAggregateCommand.ts#L21-L41), [selection and return](../../packages/system-worker/src/AggregateVersionRepo/utils/retainEvaluatedCommandTx.ts#L20-L58).

## Recommended shared value

Use **evaluated Aggregate command** for a command together with one Aggregate release's final `commandOutcome` and ordered operations. For the literal extension proposed in the conversation:

```text
IEvaluatedAggregateCommand =
  complete admitted Aggregate command
  + non-null commandOutcome
  + dispositionChainHash
  + executionStartedAt
  + ordered operations
```

Keep the command's canonical `id`; remove the publication-only conversion to `commandId`. Keep the original encoded payload, source `contractVersion`, `externalOutcome`, owner identity and source `aggregateVersion` unchanged. Those fields are present on the current complete command and absent from today's selected publication shape. Copying them into pending publication and immutable history is an actual fixed-schema expansion. It buys a single complete domain value and removes manual field selection; it also copies admitted data that AggregateChain already retains into every release's history and complete pending fanout rows. [Complete command](../../packages/core/src/contracts/CommandSchema.ts#L100-L123), [AggregateChain retained columns](../../packages/system-worker/src/AggregateChain/aggregateChainDbConfig.ts#L10-L31), [current shared publication shape](../../packages/system-worker/src/AggregateVersionChain/evaluatedAggregateCommand.ts#L48-L62), [history and fanout sharing](../../packages/system-worker/src/AggregateVersionChain/aggregateVersionChainDbConfig.ts#L5-L18).

The pending publication value returned by `materializeCommandTx` is already the value returned by `finalizeCommand`; a retry recovers that same output from local pending publication or AggregateVersionChain history. There is no need for a second reply-only evaluated-command wrapper. Construct the shared evaluated command once, encode/store it, return it, and retain that value on AggregateVersionChain. AggregateVersionRepo must continue owning only its pending publication and materialization progress. [Transactional return](../../packages/system-worker/src/AggregateVersionRepo/materializeCommandTx.ts#L33-L48), [original return/recovery](../../packages/system-worker/src/AggregateVersionRepo/finalizeCommand/finalizeCommand.ts#L56-L65), [commit return](../../packages/system-worker/src/AggregateVersionRepo/finalizeCommand/finalizeCommand.ts#L95-L112), [pending/history recovery](../../packages/system-worker/src/AggregateVersionRepo/readEvaluatedCommand/readEvaluatedCommand.ts#L31-L68), [immutable append](../../packages/system-worker/src/AggregateVersionChain/appendEvaluatedCommandsTx.ts#L147-L161).

Do not have the raw evaluator promise this final value. Resource application can still reject an otherwise successful evaluation; only after the savepoint resolves can the enclosing transaction choose Success with operations or Failure with an empty operations array. The existing ordering is substantive and must survive the vocabulary change. [Application after evaluation](../../packages/system-worker/src/AggregateVersionRepo/utils/executeAggregateCommandTx.ts#L47-L68), [final outcome selection](../../packages/system-worker/src/AggregateVersionRepo/utils/makeEvaluatedAggregateCommand.ts#L21-L33), [Failure operations](../../packages/system-worker/src/AggregateVersionRepo/materializeCommandTx.ts#L42-L48).

## Original execution and replay stay distinct

One admitted command can have an evaluated command in each Aggregate release. `finalizeCommand` requires the original command's `aggregateVersion` to equal the bound AggregateVersionRepo release. Replay instead selects the AggregateVersionRepo's own release, requires an already recorded original `commandOutcome`, clears that outcome from its evaluation input and runs its own contract/guards. Therefore an evaluated command's `commandOutcome` describes that release's evaluation; AggregateChain continues retaining the original `commandOutcome`. [Original release check](../../packages/system-worker/src/AggregateVersionRepo/finalizeCommand/finalizeCommand.ts#L40-L49), [replay release selection](../../packages/system-worker/src/AggregateVersionRepo/replayCommands/replayCommand.ts#L24-L43), [replay authority and fresh outcome](../../packages/system-worker/src/AggregateVersionRepo/utils/readAggregateCommandTx.ts#L34-L38), [outcome reset](../../packages/system-worker/src/AggregateVersionRepo/utils/readAggregateCommandTx.ts#L52-L73), [AggregateChain outcome retention](../../packages/system-worker/src/AggregateChain/recordOriginalCommandOutcomeTx.ts#L91-L98).

Do not overwrite the preserved command's `aggregateVersion` with the evaluating release during replay. The former identifies the source command; the latter is supplied by the bound AggregateVersionRepo/AggregateVersionChain context. A full-command model must document that distinction. Today execution resolution already takes `executionAggregateRelease` separately from the command, and AggregateVersionChain resolves the publishing release from its bound key. [Resolution interface](../../packages/system-worker/src/AggregateVersionRepo/utils/resolveAggregateExecution.ts#L17-L34), [publication release](../../packages/system-worker/src/AggregateVersionChain/AggregateVersionChain.ts#L268-L293).

External descriptions belong only to original evaluation: replay removes them before preparation and ID allocation while preserving authored model `operationIndex` values. Complete pending requests are reconstructed by AggregateChain with parent command identity/Origin and the original command's release. This remains valid with an evaluated-command name and does not require repeating those fields inside operations. [Replay filtering](../../packages/system-worker/src/AggregateVersionRepo/utils/prepareAggregateOutput.ts#L23-L45), [external ID allocation](../../packages/system-worker/src/externalOperations/prepareExternalOperation.ts#L37-L67), [pending request context](../../packages/system-worker/src/AggregateChain/recordOriginalCommandOutcomeTx.ts#L99-L113).

## The seam worth removing

The useful simplification is the **two-step construction of final command, then selected publication record**. Have `makeEvaluatedAggregateCommand` produce the one agreed representation, including operations and `executionStartedAt`; make `recordEvaluatedCommandTx` own SQL encoding/insertion and `materializationHead`, without reshaping the domain value. This removes the temporary full final-command representation followed by manual projection. Keep resource application inside its savepoint and final publication/head recording in the enclosing synchronous transaction. [Current orchestration](../../packages/system-worker/src/AggregateVersionRepo/materializeCommandTx.ts#L33-L48), [current constructor](../../packages/system-worker/src/AggregateVersionRepo/utils/makeEvaluatedAggregateCommand.ts#L21-L41), [current projection/write mixture](../../packages/system-worker/src/AggregateVersionRepo/utils/retainEvaluatedCommandTx.ts#L20-L58).

Do not automatically merge `prepareAggregateOutput` and `applyAggregateOutputTx` as part of naming. Their present order freezes all original external descriptions before applying model mutations, and their effects sit inside the savepoint; changing that order would be a further behavioral decision. Removing the redundant final representation is enough to deepen the current interface without broadening this design discussion. [Preparation/application order](../../packages/system-worker/src/AggregateVersionRepo/utils/executeAggregateCommandTx.ts#L38-L65), [external preparation](../../packages/system-worker/src/AggregateVersionRepo/utils/prepareAggregateOutput.ts#L23-L47).

**Recommendation:** adopt `IEvaluatedAggregateCommand` and a literal complete-command extension if that is the chosen data model; rename the three questioned methods by their actual work; remove the final-command-to-selected-publication reshaping. Keep additional `dispositionChainHash` validation deferred, and do not generalize this into a shared Aggregate/Service evaluated-command abstraction in this change.
