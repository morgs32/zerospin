# Factory-owned Actor specs: review against Plans 266 and 267

**Researched:** 2026-10-25 against current Zerospin source, [Actor ownership work](../archive/plans/268-plan-factory-owned-actor-specs.md), [completed Plan 266](../archive/plans/266-plan-independent-contract-version-specs.md) and [completed Plan 267](../archive/plans/267-plan-aggregate-chain-registration.md). This is a source-based design and verification review. No implementation, tests, builds, storage changes or deployment were performed for this research.

**Implementation context:** Plan 268 is now carried onto [PR #70](https://github.com/morgs32/zerospin/pull/70), which renames Actor and Contract factory APIs/result types to Release. The source citations below pin the original review commit so renamed or removed files remain auditable. The active plan uses the current Release names.

**Source baseline:** commit `8724ae821d4a2fbf3b925586ef6d622822d0945b`, after Plan 267 completed. The review also examined Plan 268 before implementation and incorporated its corrections into that active plan.

## Assessment

1. **Keep the proposed ownership change.** Actor construction already validates the complete declaration and captures selections. Moving portable metadata capture to that point makes the Actor own one immutable snapshot, just as Contract and Agent factories do. Owner Release construction can reuse it. This changes the capture point, not the durable acceptance unit. [Aggregate construction](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/aggregateActor/make/makeAggregateActorVersion/makeAggregateActorVersion.ts#L283-L350), [Service construction](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/serviceActor/make/makeServiceActorVersion.ts#L160-L222), [Contract snapshot construction](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/contracts/make/constructContractVersion.ts#L285-L358).
2. **The plan is architecturally compatible with both completed plans, but its verification contract needs tightening.** The important gaps are an explicit factory-versus-compiled Actor representation boundary, an Actor-bearing pre-refactor hash oracle, and a regression proving eager Actor capture does not finalize Contract lineage. These are additions to the narrow refactor, not reasons to introduce another spec model. [Factory Actor schema](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/declaration/ReleaseSpecSchemas.ts#L36-L64), [compiled Actor schemas](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/system/SystemSpecSchema.ts#L14-L22), [current compiler](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/system/make/makeSystemSpec.ts#L24-L65).
3. **Plan 267 is now complete.** Its final design deliberately separates physical Repo registration from Aggregate membership. Earlier wording in archived Plan 266 about preserving the formerly combined AggregateChain transaction is historical overlap, not the final registration contract. Follow completed Plan 267 and current source. [Final startup/failure contract](../archive/plans/267-plan-aggregate-chain-registration.md#startup-and-failure-behavior), [recorded outcome](../archive/plans/267-plan-aggregate-chain-registration.md#implementation-and-verification-results).

## 1. There are two existing Actor metadata representations

1. **Factory/Release capture contains selected Contract specs.** `projectActorFacts` currently emits `contracts[commandName] = contract.spec`, along with exposed Model specs, identity/claims schemas, pattern source and captured selections. The Aggregate and Service leaf schemas accept those full selected Contract specs and preserve their different authentication policies. The current Release builders invoke those projectors, then clone and recursively seal the complete owner metadata. [Actor facts and authentication](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/system/project/projectActorSpec.ts#L14-L69), [Actor capture schemas](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/declaration/ReleaseSpecSchemas.ts#L36-L64), [Release capture](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/declaration/makeReleaseSpecs.ts#L55-L89).
2. **Compiled SystemSpec contains numeric contract bindings.** `SystemSpecSchema` deliberately overrides the Actor leaf's `contracts` field with `Record<string, VersionSchema>`. `compileOwner` lowers each embedded Actor's full selected specs to version numbers and separately collects complete own-version Contract specs in `owner.contractVersions`. This avoids repeating full Contract metadata in every compiled Actor while retaining exact declaration bindings. [Compiled schemas](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/system/SystemSpecSchema.ts#L14-L49), [compiler lowering](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/system/make/makeSystemSpec.ts#L14-L18), [Actor lowering and codec inventory](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/system/make/makeSystemSpec.ts#L54-L71).
3. **Plan 268's proposed canonical types are appropriate for factory ownership.** Exporting `IAggregateActorSpec` and `IServiceActorSpec` beside the existing Actor capture schemas preserves the current Release metadata contract. Those types must not be treated as interchangeable with the compiled Actor values inside `ISystemSpec`. They differ at `contracts`, even when every other field is equal. [Existing capture schemas](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/declaration/ReleaseSpecSchemas.ts#L36-L64), [compiled Actor field replacement](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/system/SystemSpecSchema.ts#L14-L22), [SystemSpec type derives from the final schema](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/system/types.ts#L42).
4. **Required clarification:** `actor.spec` must equal the corresponding `release.spec.actors[name]` by JSON value. It must not be compared directly to `systemSpec.services[name].releases[version].actors[name]` or its Aggregate counterpart. The latter must equal the same Actor facts with contract values lowered to numeric versions. The Release's existing whole-value clone means reference equality between its embedded Actor and `actor.spec` is unnecessary. [Release clone/seal](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/declaration/makeReleaseSpecs.ts#L55-L89), [compiled Actor transformation](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/system/make/makeSystemSpec.ts#L54-L65).
5. **Recommendation:** retain these existing two stages for this change and name their roles clearly in Plan 268 and its tests. Moving numeric bindings into Actor construction would require changing the existing Release capture schemas and compiler contract, exceeding an ownership-only refactor. No current caller or acceptance requirement demands that redesign. [Factory projection's actual consumers](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/declaration/makeReleaseSpecs.ts#L13-L15), [current compiler input](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/system/make/makeSystemSpec.ts#L20-L26).

## 2. Actor construction must not become a Contract finalization point

1. Plan 266 separates immutable **own-version metadata** from mutable-before-composition runtime **lineage connectivity**. A Contract factory captures one version's `.spec`; `makeSystem` closes the complete participating graph only after all System validation succeeds. Finalization traverses both `.previous` and `.next`, and a later upgrade of a finalized node is refused. [Contract own spec](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/contracts/make/constructContractVersion.ts#L292-L328), [finalization traversal](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/contracts/make/constructContractVersion.ts#L84-L103), [successful System validation then finalization](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/system/make/makeSystem/makeSystem.ts#L95-L113), [upgrade refusal](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/contracts/make/constructContractVersion.ts#L389-L397).
2. The proposed Actor builders can safely capture each selected `contract.spec` before System composition because they need no lineage traversal and no finalization state. They must neither call `finalizeContractLineage` nor require `isContractFinalized`. `makeSystemSpec` must remain the consumer that refuses compiling an unfinalized graph; Actor construction must not acquire that requirement. [Current Actor projection uses own specs](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/system/project/projectActorSpec.ts#L20-L23), [compiler finalization guard](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/system/make/makeSystemSpec.ts#L24-L51).
3. **Required regression:** construct an Actor selecting Contract V1; construct a later Contract V2 before `makeSystem`; verify the Actor snapshot stays unchanged and still selects V1; compose a System and verify its owner inventory includes the reachable V1/V2 own specs while the compiled Actor binding remains V1; verify a subsequent upgrade is refused. This exercises the exact ordering changed by Plan 268. The existing general lineage test does not include an Actor. [Existing lineage regression](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/system-worker/tests/repo-names/repo-names.spec.ts#L205-L281), [compiler's both-direction traversal](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/system/make/makeSystemSpec.ts#L24-L51).
4. An Actor exposure never grants fresh-command support. Owner factories still require each Actor contract instance to be the registered owner implementation, and the final SystemSpec schema checks that compiled Actor versions match the addressed Release's contract bindings. Preserve those checks. [Aggregate exact membership](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/aggregate/make/makeAggregateRelease.ts#L241-L247), [Service exact membership](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/service/make/makeServiceRelease.ts#L133-L139), [compiled binding validation](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/system/SystemSpecSchema.ts#L98-L106).

## 3. Preserve whole-snapshot acceptance and cross-Release Actor meaning

1. SystemRepo retains complete `{ hash, spec }` snapshots in `acceptedSystemSpecs`. Actor comparisons are temporary internal entries keyed by owner namespace, owner name, Actor name and Actor version. Owner Release version is deliberately absent, so a reused Actor version cannot silently change between enclosing Releases or after a deployment omits old declarations. Contract facts are compared separately by command name/version within the owner namespace. [Temporary comparison keys](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/system-worker/src/SystemRepo/acceptSystemSpec/acceptSystemSpecTx.ts#L10-L58).
2. These checks compare **compiled Actor values**, including numeric contract bindings, because their source is the complete compiled SystemSpec. They do not independently accept `actor.spec`, and Plan 268 must not add per-Actor rows, hashes, acceptance RPCs, prerequisite callbacks or caches. A repeated whole hash writes nothing; conflicts refuse the whole incoming snapshot before its one insert. [Snapshot validation, comparison and insertion](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/system-worker/src/SystemRepo/acceptSystemSpec/acceptSystemSpecTx.ts#L61-L121).
3. Inside an authored System, `validateActorVersions` also requires repeated occurrences of the same Actor name/version under one owner to refer to the same canonical Actor object. Adding `.spec` must not replace this rule with structural equality or weaken the factories' instance provenance checks. Structural equality is the durable comparison policy across executable bundles; it is not permission to replace canonical declaration identity within one construction graph. [Within-System Actor identity checks](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/system/make/makeSystem/validateActorVersions.ts#L5-L46), [Aggregate canonical instance declaration](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/aggregateActor/make/makeAggregateActorVersion/makeAggregateActorVersion.ts#L36-L43), [Service factory's canonical object construction](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/serviceActor/make/makeServiceActorVersion.ts#L198-L223).
4. Preserve the existing whole-snapshot Actor conflict test, including conflict after omission and its no-new-snapshot assertion. Exercise `.spec` at the Actor/Release integration seam separately; do not turn the acceptance test into individual Actor acceptance. [Existing historical Contract and Actor conflict scenario](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/system-worker/tests/repo-lifecycle/repo-lifecycle.workerd.spec.ts#L499-L591).

## 4. Eager capture is a real observation and failure-timing change

1. Today, Actor construction validates runtime declarations and captures selections, then returns a frozen executable object. JSON Schema conversion for Actor identity and authentication occurs later when an enclosing Release is constructed. Moving conversion to Actor construction means unprojectable or non-JSON metadata is rejected earlier, before a completed Actor is returned. Plan 268 already acknowledges this and should test one representative failure at that new boundary. [Current Aggregate construction tail](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/aggregateActor/make/makeAggregateActorVersion/makeAggregateActorVersion.ts#L313-L350), [Service construction tail](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/serviceActor/make/makeServiceActorVersion.ts#L172-L222), [currently later JSON conversion/strict decoding](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/system/project/projectActorSpec.ts#L25-L69).
2. The “same SystemSpec and hash” promise means the same stable authored metadata produces the same compiled result. It cannot also promise to observe later mutations to caller-owned schema annotations between Actor construction and Release construction: earlier capture intentionally fixes the earlier value. Keep callback/codec identity, but do not make dynamic post-construction metadata mutation an implicit compatibility requirement. This is an inference from the changed observation point, not an observed runtime failure. [Current late conversion](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/system/project/projectActorSpec.ts#L25-L31), [current schema documents are JSON values](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/declaration/ReleaseSpecSchemas.ts#L10-L13), [current own metadata sealing](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/declaration/sealOwnedMetadata.ts#L3-L14).
3. Strictly decode the new portable value through the existing named Actor schema, detach the complete decoded value, then recursively seal that detached metadata. Cloning before sealing prevents the recursive freeze from reaching shared runtime capabilities or aliased nested metadata. `sealOwnedMetadata` skips already-frozen objects, so beginning from a complete clone also avoids accidentally trusting a merely shallow-frozen nested object as recursively sealed. [Actor schema fields](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/declaration/ReleaseSpecSchemas.ts#L36-L64), [recursive seal's early return](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/declaration/sealOwnedMetadata.ts#L4-L13).
4. Keep runtime authentication, authorization, guards, query DBs and selection execution outside the cloned metadata graph. Current projection emits identity schemas, pattern source, model facts and selection definitions; it does not serialize execution callbacks. The spec immutability guarantee remains structural, not executable-code immutability. [Portable fields](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/system/project/projectActorSpec.ts#L14-L69), [Aggregate executable fields](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/aggregateActor/make/makeAggregateActorVersion/makeAggregateActorVersion.ts#L332-L350), [Service executable fields](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/serviceActor/make/makeServiceActorVersion.ts#L198-L222).
5. Capture selections once and use those captured definitions in the spec. Selection capture performs database/model identity validation and returns executable bind/query capabilities alongside the portable definition. Copying the entire captured selection would include those capabilities; selecting only its definition preserves the present format. [Captured selection result](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/models/make/makeQueryDbVersion.ts#L322-L334), [capture routine](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/models/make/makeQueryDbVersion.ts#L456-L479), [current definition-only projection](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/system/project/projectActorSpec.ts#L34-L37).

1. Aggregate has both an erased `IAnyAggregateActorVersion` surface and a precise generic `IAggregateActorVersion`. Service has an erased interface and a precise inline factory return type. All four surfaces need the required family-specific spec property. Generic names/versions, credentials, claims, selected models/contracts and Effect requirements must retain their current inference; derive spec types from the data schemas rather than recursive factory `ReturnType` inference. [Aggregate precise return](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/aggregateActor/make/makeAggregateActorVersion/makeAggregateActorVersion.ts#L153-L190), [Service precise return](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/serviceActor/make/makeServiceActorVersion.ts#L112-L142), [existing shared data schemas](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/declaration/ReleaseSpecSchemas.ts#L36-L64).
2. Attach the Aggregate spec inside `constructAggregateActorVersion`, not only its public wrapper. The update helper calls that constructor directly with explicit inherited fields and merged maps. Service updates call `makeServiceActorVersion` with explicit inherited fields; neither path should copy a predecessor's `.spec` into new authored inputs. An update gets a freshly captured spec for the new version and must leave the predecessor snapshot unchanged. [Aggregate update construction](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/aggregateActor/updateAggregateActorVersion.ts#L121-L157), [Service update construction](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/serviceActor/updateServiceActorVersion.ts#L76-L125).
3. Preserve Aggregate's default callable authorizer, Service's optional authorizer and Service guard ownership. These executable fields stay outside the spec and remain authoritative during execution/admission. [Aggregate default injection](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/aggregateActor/make/makeAggregateActorVersion/makeAggregateActorVersion.ts#L226-L239), [Service optional callback and guards](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/serviceActor/make/makeServiceActorVersion.ts#L191-L222).
4. Preserve **current** generic inference rather than promising a broader type repair. In particular, the precise Aggregate Actor result currently exposes authentication credentials as `Schema.Codec<unknown, unknown>` even though construction infers a credentials codec. Plan 268 should not turn spec capture into an unrelated credential-type redesign. Its capability freeze assertions should compare pre/post status: caller-owned codecs or callbacks may already be frozen, so a universal assertion that they are unfrozen would be incorrect. [Existing precise authentication type](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/aggregateActor/make/makeAggregateActorVersion/makeAggregateActorVersion.ts#L174-L177), [current Aggregate wrapper retention](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/core/src/aggregateActor/make/makeAggregateActorVersion/makeAggregateActorVersion.ts#L332-L350).

## 6. Plan 267 is compatible and has no Actor-specific prerequisite

1. The child constructor derives `makeSystemSpec({ system }).hash`, awaits physical registration before its first local PRAGMA, then initializes and activates. That calculation will naturally consume the new Actor snapshot through the unchanged SystemSpec compiler. Do not add per-Actor readiness, async metadata resolution, an override hash or another registration argument. [Factory startup](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/system-worker/src/makeMigratableDORepo/makeMigratableDORepo.ts#L277-L315).
2. Current `SystemRepo.registerRepo` requires the retained whole hash and upserts only physical metadata. AggregateChain separately awaits `SystemRepo.registerAggregate` first during activation, before recovery holds and queue wakeups. The two commits deliberately describe different durable facts. Actor metadata ownership provides no reason to restore the former combined transaction or change these failure semantics. [Physical registration](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/system-worker/src/SystemRepo/registerRepo/registerRepo.ts#L27-L49), [Aggregate activation](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/system-worker/src/AggregateChain/AggregateChain.ts#L375-L397), [membership procedure](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/system-worker/src/SystemRepo/registerAggregate/registerAggregate.ts#L8-L19), [final Plan 267 failure contract](../archive/plans/267-plan-aggregate-chain-registration.md#startup-and-failure-behavior).
3. Shared-file overlap is coordination work: Plan 268's Actor acceptance scenario and Plan 267's registration assertions occupy the same existing lifecycle file; glossary and AuthoredSystem are shared documentation. Build on the final Plan 267 content and preserve its real activation, idempotence, hash refusal and membership-failure assertions. Do not rewrite those assertions to older registration semantics. [Actor acceptance case](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/system-worker/tests/repo-lifecycle/repo-lifecycle.workerd.spec.ts#L499-L591), [registration case](https://github.com/morgs32/zerospin/blob/8724ae821d4a2fbf3b925586ef6d622822d0945b/packages/system-worker/tests/repo-lifecycle/repo-lifecycle.workerd.spec.ts#L594-L710).

## 7. Tighten the verification contract before implementation

1. **Add an independent Actor-bearing preservation oracle.** Existing Contract lineage and canonical-hash regressions do not include Actors. Repeated hashing and key-reordering checks prove determinism, not preservation of the pre-refactor Actor-bearing value.
