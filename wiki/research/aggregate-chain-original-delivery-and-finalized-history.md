# AggregateChain original delivery and finalized history reads

**2026-11-19.** Source comparison for [PR #176](https://github.com/morgs32/zerospin/pull/176), from `0b65fcce2f` to `79be3266de`.

## How an original finishes

`AggregateChain.finalizeCommandOutbox` selects the oldest admitted command with a null `outcome`, resolves `AggregateVersionRepo` by the command’s `aggregateVersion`, and awaits `finalizeCommandSubscriber.receive([command])`. The reply contains the evaluated command. `recordOriginalCommandOutcomeTx` checks its identity, stores the returned `outcome`, and advances `finalizedThroughIndex` in the same transaction. That reply supplies the Chain with the result for the command it just sent. This protocol already existed on the PR base. [Base outbox](https://github.com/morgs32/zerospin/blob/0b65fcce2f262473ed03a29308d157b5b3acaa95/packages/system-worker/src/AggregateChain/AggregateChain.ts#L236-L294) · [Pending row](https://github.com/morgs32/zerospin/blob/79be3266def11102a18696808be3245d85582bf8/packages/system-worker/src/AggregateChain/readPendingAggregateCommand.ts#L6-L22) · [RPC call](https://github.com/morgs32/zerospin/blob/79be3266def11102a18696808be3245d85582bf8/packages/core/src/outbox/makeOutboxDelivery.ts#L232-L271) · [Acknowledgement transaction](https://github.com/morgs32/zerospin/blob/79be3266def11102a18696808be3245d85582bf8/packages/system-worker/src/AggregateChain/recordOriginalCommandOutcomeTx.ts#L45-L120)

The addressed Repo still reads during execution. For a fresh original at position N, `validateCommandIdentity` calls `AggregateChain.getAggregateCommand(N)` to compare the admitted input. Then `catchup(N - 1)` pulls earlier finalized commands if the Repo is behind. For a redelivery after its execution committed, the Repo can recover the evaluated command from its pending publication row or its own `AggregateVersionChain.getEvaluatedCommand(N)` and return it again. ## When AggregateChain fetches history

Once the canonical release acknowledges published progress, `adoptCanonicalAggregateHistory` records one release and its covered index and deletes local command rows through that index. For an adopted position, `readAggregateCommand` calls that release’s `AggregateVersionChain.getEvaluatedCommand`, and `readReplayPage` calls its `getEvaluatedCommandPage`. Newer positions come from local rows. Replay pages stop at `finalizedThroughIndex`. These reads predate PR #176. Another caller reads the source command when admitting a command continuation. [Adoption](https://github.com/morgs32/zerospin/blob/0b65fcce2f262473ed03a29308d157b5b3acaa95/packages/system-worker/src/AggregateChain/adoptCanonicalAggregateHistory.ts#L16-L37) · [Exact read](https://github.com/morgs32/zerospin/blob/0b65fcce2f262473ed03a29308d157b5b3acaa95/packages/system-worker/src/AggregateChain/readAggregateCommand.ts#L29-L57) · [Replay page](https://github.com/morgs32/zerospin/blob/0b65fcce2f262473ed03a29308d157b5b3acaa95/packages/system-worker/src/AggregateChain/readReplayPage.ts#L29-L80) · [Continuation](https://github.com/morgs32/zerospin/blob/79be3266def11102a18696808be3245d85582bf8/packages/system-worker/src/AggregateChain/AggregateChain.ts#L503-L520)

## What PR #176 changed

- **Address resolution.** The outbox still addresses the same Repo by release. In a split deployment, `AggregateVersionRepo.getRepo` now calls the registered owner release Worker’s `getAggregateVersionRepo(key)`. When the local namespace binding is present it uses `getByName`. [Original dispatch](https://github.com/morgs32/zerospin/blob/79be3266def11102a18696808be3245d85582bf8/packages/system-worker/src/AggregateChain/AggregateChain.ts#L311-L340) · [Repo resolution](https://github.com/morgs32/zerospin/blob/79be3266def11102a18696808be3245d85582bf8/packages/system-worker/src/AggregateVersionRepo/AggregateVersionRepo.ts#L151-L175)
- **One new exact read during down-adaptation.** When a receiving Repo needs to replay an ordinary System command against an older contract and remote preparation is configured, it passes the Aggregate identity, index, command ID and receiving release to `AggregateChain.prepareAggregateReplayAdapter`. The Chain reads exactly that finalized position with `readReplayPage(N - 1, N)`, checks the command ID and outcome, then sends the retained payload and `finalizedAt` to the recorded source release’s adapter. This lookup serves replay conversion. [Receiving Repo](https://github.com/morgs32/zerospin/blob/79be3266def11102a18696808be3245d85582bf8/packages/system-worker/src/AggregateVersionRepo/replayCommands/replayCommand.ts#L79-L106) · [Exact finalized read](https://github.com/morgs32/zerospin/blob/79be3266def11102a18696808be3245d85582bf8/packages/system-worker/src/AggregateChain/AggregateChain.ts#L613-L637) · [Source request](https://github.com/morgs32/zerospin/blob/79be3266def11102a18696808be3245d85582bf8/packages/system-worker/src/aggregateReplayAdapter/dispatchAggregateReplayAdapter.ts#L62-L119)

**Design discussion.** The November 19 interview raised a per-command locator as one possible way to serve historical reads. The code reviewed here uses a single adopted-prefix boundary. Any need for a per-command locator depends on which historical reads the proposed design keeps and where their inputs will live.
