# Decoded value naming audit

Date: 2026-10-15. All 52 primary naming findings below have been implemented across 50 source files. The broader prefix candidates and decode result containers remain research recommendations outside this change.

## Finding

The original `recorded` binding is now `decodedExternalOutcome`. `recorded` describes the external outcome's retention history, while this binding holds the result of decoding `externalOutcome`. The neighboring `decodedPayload` already makes that distinction explicit. The adjacent `response` binding is now `decodedExternalResponse`. [Source: `decodeExternalCommandInput.ts:23–57`](../../packages/core/src/contracts/decodeExternalCommandInput.ts#L23).

The convention being audited is the user's requested `decoded<SpecificThing>` naming for a local decoded value. It is not a TypeScript syntax error. The relevant [local pattern index](../patterns/index.md) and [shared naming index](../../../wiki/skills/use-morgs32-wiki-patterns/references/patterns/index.md#naming) do not establish a blanket requirement to prefix every schema validation result. The tables therefore distinguish vague or misleading names from broader consistency candidates.

Apply the prefix to local bindings while preserving domain and public property names: `return { payload: decodedPayload, externalOutcome: decodedExternalOutcome }`. The external response remains under the `success` property. These recommendations do not rename schema or API fields.

## Scope and exclusions

The audit reviewed searched direct schema-decoder bindings and named decoder helpers across `packages/`, with additional searches of `examples/`, `scripts/`, and `fragment/`. `packages/core` and `packages/shapes` received a focused decoder-binding pass. This is a source audit of the current working tree, not a formal guarantee that every indirect decoder or alias has been found. The original audit was read-only. Implementation verification is recorded below.

- Already explicit bindings such as [`decodedPayload`](../../packages/core/src/contracts/decodeExternalCommandInput.ts#L23), [`decodedProps`](../../packages/core/src/models/make/makeModelVersion.ts#L307), and [`decodedProps`](../../packages/core/src/aggregate/make/makeAggregateRelease.ts#L174) follow the requested form.
- Direct returns, discarded validation results, callback property values, codec constructors such as [`Schema.decodeTo`](../../packages/core/src/contracts/operationCodecs.ts#L207), and immediate [destructuring of decoded output](../../packages/core/src/contracts/prepare/prepareAggregateExternalInvocation.ts#L51) do not introduce a vague local decoded-value binding.
- A decode can validate an encoded representation without converting it into the domain representation. [`prepareExternalOperation`'s `payload`](../../packages/system-worker/src/externalOperations/prepareExternalOperation.ts#L41) is validated with `Schema.Json` and remains wire data. [`decodeNodeResource`](../../packages/core/src/Node/decodeNodeResource.ts#L8) returns `IEncodedResourceShape` and preserves encoded column bytes; its callers' `resourceRow` is not an unqualified decoded resource. Preserve representation words such as `encodedIdentity`, and do not mechanically call those values `decodedIdentity`.
- Trivial scalar validation bindings such as [`name`](../../packages/core/src/serviceActor/make/makeServiceActorVersion.ts#L160), [`commandName`](../../packages/core/src/contracts/make/constructContractVersion.ts#L332), and extracted fields do not have the same ambiguity as the primary findings. If a literal universal prefix rule is adopted, these would need a separate decision.
- [`adapted`](../../packages/core/src/contracts/decodeAndAdaptPayload/adaptPayload/adaptPayload.ts#L65) is mutable state that moves through multiple payload adapters and decodes. `adaptedPayload` would clarify the subject; the lifecycle role is real here.
- Mixed remote-result / decoded-row locals such as [`readEvaluatedCommand`'s `retained`](../../packages/system-worker/src/AggregateVersionRepo/readEvaluatedCommand/readEvaluatedCommand.ts#L37) and [`readCommandResult`'s `retained`](../../packages/system-worker/src/ServiceVersionRepo/readCommandResult.ts#L37) are not direct decoder-result bindings throughout their lifetime. [`validateSessionAdmission`'s `validated`](../../packages/system-worker/src/SystemRepo/sessionWebSocketTickets/validateSessionAdmission.ts#L34) comes from `validateLock`.
- [`encodeExternalResponse`'s `encoded`](../../packages/core/src/contracts/externalExecution/encodeExternalResponse.ts#L22) could be `encodedResponse` for matching specificity. This is an encoder naming observation, outside the decoded-value findings.
