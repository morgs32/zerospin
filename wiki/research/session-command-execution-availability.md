# Session command execution availability

Source review, 2026-11-13. Scope: current Aggregate and Service browser sessions.

## Answer

There is no connected browser Session API that directly executes an Actor command and asynchronously returns its authoritative `outcome`. The connected `executeCommand` feature was deliberately removed without a replacement submit/wait API; the current browser facade and Aggregate and Service session types expose no such method. Sources: [completed Plan 271](../archive/plans/271-plan-remove-connected-session-command-execution.md#problem-and-agreed-behavior), [browser facade](../../packages/browser/src/browserSession/types.ts#L29), [Aggregate session type](../../packages/core/src/aggregateSession/types.ts#L194), [Service session type](../../packages/core/src/serviceSession/types.ts#L145).

The ordinary path is `stageAggregateSessionCommand` or `stageServiceSessionCommand`, imported from `@zerospin/sdk/browser`. Each receives `{ session, contractName, payload }`, evaluates the contract and commits local optimism and a Session command synchronously, and returns an `IResult`. The `success.stagingOutcome.result` is the local result, not the authoritative execution `outcome`. The Session handles later background delivery and reconciliation. Staging success does not establish Node retention, admission or authoritative execution. Sources: [SDK exports](../../packages/sdk/src/browser/index.ts#L11), [Aggregate staging](../../packages/core/src/aggregateSession/stageCommand/stageAggregateSessionCommand.ts#L22), [Aggregate staging transaction](../../packages/core/src/aggregateSession/stageCommand/stageAggregateSessionCommandTx/stageAggregateSessionCommandTx.ts#L32), [Service staging](../../packages/core/src/serviceSession/stageServiceSessionCommand.ts#L23), [Service staging transaction](../../packages/core/src/serviceSession/stageServiceSessionCommandTx.ts#L40), [command guide](../../docs/content/guides/write-commands.md#understand-what-each-successful-call-means).

Use live queries to observe domain state and the Session failure subscription for later refusals; the browser path does not expose a generic promise for the retained authoritative `outcome`. A standalone session has no server admission or server-confirmed execution. Sources: [command guide](../../docs/content/guides/write-commands.md#submit-a-command-and-query-its-domain-state), [later failures](../../docs/content/guides/write-commands.md#present-later-failures), [standalone sessions](../../docs/content/handbook/sessions-and-synchronization.md#retain-identity-for-the-whole-lifetime).

## Other execution capabilities

The administrative `SystemApi.executeAggregateCommand` and `SystemApi.executeServiceCommand` accept System commands from the exact owner release's System grants, and asynchronously return the original command's retained `ICommandOutcome`. For example, `executeDirectServiceCommand` admits the System command, invokes `ServiceVersionRepo.awaitCommandResult` at its `serviceIndex`, and returns the retained `outcome`. This is an administrative capability, not a Session Actor command. Aggregate authorization also receives a restricted `executeCommand` for registered System contracts. Sources: [typed facade](../../packages/core/src/utils/getSystemApi/makeSystemApi.ts#L89), [administrative RPC types](../../packages/core/src/systemApi/ISystemApiRpc.ts#L24), [Service execution](../../packages/system-worker/src/executeDirectServiceCommand/executeDirectServiceCommand.ts#L11), [Aggregate authorization](../../packages/system-worker/src/AggregateVersionRepo/authorizeAggregateSession/authorizeAggregateSession.ts#L109).
