# Effect v4 in Shopping release Worker bundles

**Date** 2026-11-20

**Scope** Local Wrangler artifacts from MOR-491/MOR-490 for Shopping's `user@3` Aggregate release and `marketplace@1` Service release. Paired Wrangler dry runs used their generated entrypoints and attached SystemSpec text. Standalone esbuild builds isolated follow-up opportunities. The experiments measured compilation and bundle size.

## Recommendation

Use public Effect subpaths in the shared modules reached by the two release Workers. Start with `import * as Schema from 'effect/Schema'` and `import * as Effect from 'effect/Effect'`, then apply the same pattern to other Effect namespaces that survive in the output. Keep the runtime codecs, Effect programs, and deployment checks while making this change. Changing root and feature imports saved **257–259 kB of JavaScript** and **74–75 kB gzip** per Worker in paired Wrangler dry runs. [Effect's import guide](https://effect.website/docs/v4/getting-started/importing-effect#namespace-imports), [Effect 4.0.2 exports](https://github.com/Effect-TS/effect/blob/effect%404.0.2/packages/effect/package.json), [esbuild tree shaking](https://esbuild.github.io/api/#tree-shaking)

## What esbuild can remove

Effect's root index re-exports namespace objects using `export * as`. In the pinned esbuild 0.28.1 control, importing the root namespace causes esbuild to materialize an export object with members the caller never uses. With public subpath imports and static property access, esbuild can resolve individual members. Root imports retain whole public APIs for namespaces such as `Schema`. In the Worker comparison, direct root subpaths removed `NetAddress.js` and `Cron.js`. [Effect's root index](https://github.com/Effect-TS/effect/blob/effect%404.0.2/packages/effect/src/index.ts), [esbuild reproduction of namespace re-export retention](https://github.com/evanw/esbuild/issues/1420)

In minimal minified browser ESM controls, exporting a function that runs `Effect.runSync(Effect.succeed(value))` went from **85,176 B raw / 29,783 B gzip** with the root import to **25,001 B / 8,910 B** with the subpath. A separate fixture combining `Effect.runSync` and a `Schema.Struct` decode measured **292,454 B / 91,704 B** with root imports and **74,722 B / 24,994 B** with direct imports on Effect 4.0.2. On Effect 4.1.4, the same fixture measured **362,205 B / 116,694 B** and **73,542 B / 24,738 B**, respectively. esbuild 0.28.1 and 0.28.2 produced matching fixture sizes. The 4.1.4 fixture still benefits from the import change. [Effect 4.0.2 exports](https://github.com/Effect-TS/effect/blob/effect%404.0.2/packages/effect/package.json), [Effect 4.1.4 published package](https://registry.npmjs.org/effect/-/effect-4.1.4.tgz)

The paired Wrangler 4.127.1 dry runs used esbuild 0.28.1, the generated entrypoints from the supplied source maps, and the original attached SystemSpec text. The rebuilt baseline JavaScript matched the original files by SHA-256. An in-memory esbuild hook changed the imports in reached framework and example modules. The numbers below are JavaScript bytes, gzip bytes, and attributable Effect bytes, in that order. Temporary measurements are under `/private/tmp/zerospin-effect-wrangler.K7BZUE`. [Wrangler bundling](https://developers.cloudflare.com/workers/wrangler/bundling/)

- Shopping Aggregate. Schema-family root imports only **963,443 / 284,654 / 288,020 B**. All root subpaths **882,679 / 258,017 / 214,805 B**. Root and feature subpaths **866,057 / 252,727 / 198,374 B**.
- Marketplace Service. Schema-family root imports only **959,123 / 283,655 / 288,538 B**. All root subpaths **876,802 / 256,714 / 214,199 B**. Root and feature subpaths **860,240 / 251,498 / 197,767 B**.

The Schema-family change alone saved about **160 kB raw and 42 kB gzip** per Worker. With root and feature subpaths, `Schema.js` and `SchemaAST.js` contribute about **46.6 kB** per Worker, down from about 113 kB. The JSON Schema document generator still contributes about 11.2 kB per Worker. These dry runs establish size savings. Typechecking and execution in Workerd remain to be verified.

## Follow-up opportunities

The follow-up comparisons started from the root and feature subpath rewrites. Temporary stubs removed behavior to measure reachability. The portable projection probes used standalone esbuild 0.28.1 on the generated entrypoints. Reproduction scripts `/private/tmp/mor491-effect-subpath-follow-up.mjs` and `/private/tmp/mor491-effect-projection-bound.mjs`.

1. **Measure OTLP after the import change.** Both Workers statically reach `WorkerTelemetryLive` and `exportTelemetryBatch`, even when the deployment has no OTLP configuration. The original Wrangler builds attribute about 31.8 kB raw to Effect's HTTP and observability directories combined. A paired Wrangler dry run with a diagnostic no-op for `exportTelemetryBatch` saved another **33,838 B raw / 11,178 B gzip** in the Aggregate and **35,649 B / 11,994 B** in Marketplace. These figures measure removal of delivery. A replacement transport would use some of that space. If delivery is a deploy-time choice, a generated entrypoint can exclude the transport when it is disabled. If binding overrides must remain available at runtime, measure a smaller transport using the existing JSON payload builder and preserving time bounds, delivery behavior and credential-safe diagnostics. [Telemetry selection](../../packages/system-worker/src/repoServices/WorkerTelemetryLive.ts#L38), [OTLP transport](../../packages/system-worker/src/exportTelemetryBatch/exportTelemetryBatch.ts#L14)
2. **Keep Schema and Effect on the command execution path.** Release Workers decode claims and retained commands, adapt versioned command payloads, validate executable operation outputs, and encode result and failure values. Author programs use Effect services, scopes and typed failures. Portable JSON Schema describes the encoded side and may approximate runtime checks. Using it as the execution codec would need an explicit replacement for both directions of transformation and for replay and outcome behavior. [Payload adaptation](../../packages/core/src/contracts/decodeAndAdaptPayload/decodeAndAdaptPayload.ts#L42), [Contract evaluation](../../packages/core/src/contracts/evaluateContract.ts#L51), [Result codecs](../../packages/core/src/contracts/resultCodec.ts), [Release Layer](../../packages/core/src/execution/provideReleaseLayer.ts#L23), [Effect JSON Schema semantics](https://effect.website/docs/v4/schema/json-schema)
3. **Revisit declaration projection only after removing namespace retention.** `verifyNativeRelease` compares executable release, model, contract, and Actor declarations to the attached SystemSpec after finalizing contract lineage. `configureOwnerReleaseRuntime` separately validates the attached spec and its content hash. After the subpath changes, removing all three reachable `makeSystemSpec` calls saved about 6.4 kB raw and at most one Effect byte. Command execution still reaches `Schema.toJsonSchemaDocument` through `assertReadProjection` and `encodeShape` for JSON fields. A second diagnostic also bypassed rendering those fields. The generator then disappeared and Effect attribution dropped another 18.7 kB raw in each Worker. Any redesign must preserve read-projection compatibility and the executable declaration checks. If re-projection moves to preflight, preserve the native-to-portable match for the exact Worker candidate, along with hash and registration checks. The CLI checks source object identity in its own load graph. [Release verification](../../packages/owner-release-worker/src/ownerReleaseRuntime.ts#L45), [Worker configuration](../../packages/system-worker/src/workerConfiguration/workerConfiguration.ts#L126), [Repo registration](../../packages/system-worker/src/makeDORepo/makeDORepo.ts#L271), [Read projection check](../../packages/core/src/contracts/readProjection.ts#L232), [Shape encoding](../../packages/shapes/src/encodeShape.ts#L112), [CLI source check](../../packages/cli/src/deploy/loadOwnerReleaseSources.ts#L92)

Confirm the import change with both Wrangler release dry runs and the existing Workerd paths for original execution, replay, and telemetry. Compare the emitted JavaScript, gzip and attributable Effect bytes with the same build inputs. Keep the attached SystemSpec and its matching release identity in that comparison. [Generated release entrypoint](../../packages/cli/src/deploy/utils/writeOwnerReleaseEntrypoint.ts#L120), [Wrangler dry-run output](https://developers.cloudflare.com/workers/wrangler/bundling/)
