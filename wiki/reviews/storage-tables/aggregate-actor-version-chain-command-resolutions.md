## Physical scope and represented fact

AggregateActorVersionChain is bound to `systemId / aggregateId / aggregateName / aggregateVersion / actorName / actorVersion / actorPath`. One `commandResolutions` row records the exact original producer/recipient and private refusal-or-success decision owned by the public exposed command at `aggregateIndex`.

The relation is **immutable private history**, not another queue, acknowledgement, current capability, diagnostic log or canonical `outcome` store. It contains neither successful result values nor `outcome.finalizedAt`. The admitted command and full `outcome: { result, finalizedAt }` remain with their established Aggregate owners. Fixed actor Origin kind/name/version derive from the immutable bound Chain owner; they need no copied columns here.

The producer retains a resolution only for a complete producer belonging to the bound actor name/version and selected identity. Original full encoded claims are copied, including values outside actorPath. Commands from another actor/identity, Agent/System commands and commands without a producer tuple do not acquire a private resolution in this Actor Chain.

## Every column

All six fields are inserted once by `appendExposedCommands` from AggregateActorVersionRepo's complete pending publication. Supported code never updates them. The first five columns are non-null; `failure` alone is nullable. There are no SQL defaults or synthesized ID/timestamp columns.

| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `aggregateIndex` | Required integer primary key and foreign key to `exposedCommands.aggregateIndex`. The append writes it with the parent; joined retry/browser readers use the relationship and private recovery uses its captured-position bound.                   | Retain the parent association. Sharing the parent's key is not a redundant independent ID. Removing it loses which command owns the private resolution and whether it falls at or before snapshot N. No repeated command ID, name, hash or delta is needed in the child.                                                               |
| `nodeId`         | Required original producer Node identity. Private prefix and replay queries select by Node; replay/live disclosure compares the exact Node. Publication validation requires a nonempty string.                                                     | Retain. Multiple Nodes can share actor, session and claims; none of those facts derives this independent producer identity. Without it, private results from separate submission streams become indistinguishable. It is not a WebSocket connection ID.                                                                                |
| `pushIndex`      | Required producer-local admitted submission position, validated as a positive safe integer. Private recovery orders and proves the contiguous prefix with it; browser replay advances private progress independently of public Aggregate progress. | Retain. Other producers/System commands interleave in `aggregateIndex`, so public position cannot derive private order. Removing it loses gap detection and exact private resolved progress.                                                                                                                                           |
| `sessionName`    | Required original named session definition, validated as nonempty. The actor owner is shared by different session definitions, and transient connection locks are not immutable historical recipient identity. Browser/public-command construction reads it only after recipient filtering; duplicate comparison retains it exactly.             | Retain the exact private refusal. This affects the recipient's command result; it is not optional delivery diagnostics.                                                                                               |

`claims` has application-defined string keys and values; the fixed table does not define a second credential schema. Each authored actor's existing claim contract determines the encoded values. `resolveActorIdentity` extracts only the actor identity-schema fields for the canonical path; it cannot reconstruct omitted non-path claims. Structural equality avoids treating JSON property order as a different Origin.

### Nested failure fields

When `failure` is non-null, the complete existing public-error envelope is retained for its admitted recipient. Its name does not make the refusal visible to other recipients.

| Field     | Meaning, null/absence and removal consequence                                                                                                                                    |
| --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `_tag`    | Required literal `ZerospinError`, the shared public error discriminator. This is not the canonical outcome branch's `Failure` tag. Retain the existing error protocol.           |
| `code`    | Required stable machine-readable error code. Removing it loses exact error recognition.                                                                                          |
| `scope`   | Optional `contract`, `actor` or `aggregate` error namespace. Omission is valid; the bound Actor owner cannot infer which error namespace produced this refusal.                  |
| `message` | Required readable refusal text, frozen at finalization. A later declaration's text is not a replacement for that recorded message.                                               |
| `status`  | Required numeric status or null when no numeric public status is supplied. Null is not a success marker or missing resolution.                                                   |
| `extra`   | Required JSON error payload; JSON null is valid. Preserve the declared structured error details used by local typed recognition, without inventing additional generic subfields. |

These fields belong to one shared refusal value. None is copied from the parent public command or derivable from its selected delta/hash. No new Actor-specific failure representation is recommended.

### Absence, success and immutable association

The two null boundaries mean different things:

1. No child row: this Actor publication owns no private resolution. It does not imply canonical Success or an unresolved command.
2. Child with `failure = null`: this Actor publication owns that producer submission's successful resolution.
3. Child with supplied `failure`: this Actor publication owns that producer submission's refusal.

Successful commands need rows even when they carry no successful result value and change no selected resources: otherwise private resolved progress would stall. There is no need for a new success flag, timestamp, resolution ID or lifecycle discriminator.

The parent insertion seals either its exact child or the child's absence. Identical retries compare the joined public command and resolution-or-null. Attaching a child later, removing/changing private ownership, or altering refusal data is a conflicting publication; there is no independent resolution insertion RPC, queue or acknowledgement.

## Constraints and local recovery

`aggregateIndex` is both primary key and foreign key: at most one resolution per existing public command, with no orphan child. Its reference descriptor's `unique: true` supplies optional one-to-one inverse-relation metadata. It does not add a redundant SQL UNIQUE index to the primary key: integer reference rendering returns the primary-key column before the separate unique branch.

`commandResolutions_node UNIQUE(nodeId, pushIndex)` enforces one resolution per original producer submission and supports Node-local push ordering. Adding session or claims to that uniqueness would permit multiple records for one Node position, weakening the existing admission invariant. SQL non-null/key constraints do not themselves enforce nonempty text, positive pushes or complete-recipient semantics; append's shared publication codec supplies those checks. No extra index or persisted prefix counter is justified by this review.

`getResolvedThrough` considers the requested Node's rows only through captured Aggregate position N, in push order. It rejects any session/full reconstructed-Origin mismatch and requires pushes `1..resolvedThrough` without gaps. It must not silently filter mismatching identities out and then treat a shortened prefix as valid. Browser recovery separately checks a requested private cursor against the retained prefix and requires each newly recovered private push to be next. Full claims remain necessary even when every row shares actorPath.

Snapshot capture fixes resources and materialization checkpoint N together. After pending publication through N and exact history-checkpoint comparison, private recovery is bounded by that same N. Public replay/live delivery joins the optional resolution, checks exact Node/session/full Origin and reveals only its nullable failure; claims and producer metadata stay off public command frames. A newer public history tip cannot relabel the snapshot or advance its private prefix.

## Reader simplification finding and implementation

At review time, `getResolvedThrough` called `readExposedCommands({ resolutionsOnly: true })` for Actor private progress. That selected and decoded complete parent commands, including historical `delta`, although the prefix loop consumed only private resolution information. The redundant work was observed in source; no measured production latency or data-loss defect was claimed.

The user subsequently approved the cleanup in [Plan 208](../../archive/plans/208-plan-direct-actor-resolution-prefix-read.md). The Actor branch now queries `commandResolutions` directly by exact Node and `aggregateIndex <= N`, orders by push index and decodes the retained private rows. Every row still passes the existing exact session/full reconstructed-Origin and contiguous `1..resolvedThrough` checks. Mismatching identities are not filtered away.

The obsolete Actor private-prefix WHERE/order branches were removed from `readExposedCommands`. Its joined public/retry reader remains because those consumers need public fields. The Agent private-prefix path keeps its existing flat storage/decoding behavior. No schema, public interface, queue, index, retention or socket-lifecycle change was introduced. Plan 208 owns verification and completion evidence for this follow-up.

## Commit, acknowledgement and retention

AggregateActorVersionRepo commits resources, materialization head and complete pending public/private publication in one synchronous transaction. AggregateActorVersionChain subsequently appends the public command and optional resolution in its own synchronous transaction. A later page failure rolls back earlier inserts from that page, including both relations.

The outbox acknowledges only after a successful receiving RPC envelope, then deletes the exact pending page indices. A lost reply, rejected append, interruption or failed acknowledgement deletion retains complete pending messages for an identical retry. Retained private rows survive that acknowledgement. Broadcast occurs after the append commit; send failure closes the individual connection and does not undo retained resolution or publication acknowledgement.

No supported code updates, deletes, prunes or expires Actor `commandResolutions`. Retain them for the lifetime of the bound physical Actor Chain. Browser delivery, socket close, source subscriber progress and private `resolvedThrough` are not deletion receipts. Deleting rows independently of public history would break private recovery and change the sealed publication seen by retries. No TTL, Node retirement or release-retirement cleanup policy is currently implemented for this table.
