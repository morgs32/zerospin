## Written implementation

ServiceNode commands now has exactly nodeIndex, id, pushIndex, commandName,
payload, stagingOutcome, failure, serviceIndex, dispositionChainHash and exposedDelta.
SQL copies of contractVersion, serviceName, actorName, actorVersion, sessionName
and claims are removed. Original reconstruction receives the immutable bound
definition and retained producer: fixed Service/Actor/session names and complete
encoded claims come from that identity, while source contractVersion comes from
the exact selected contract. Complete original protocol input remains intact for
retry, return, subscription, pending/unresolved recovery and outbound dispatch.

New-original admission validates an own selected registry entry, matching embedded
canonical commandName and exact incoming version before allocation or insertion.
Full reconstructed retry comparison occurs before current readiness/blocked/
allocation gates; changed full claims, identity, version, original payload bytes
or staging evidence still conflict. Exact retries retain coordinates even at
allocation exhaustion. No compatibility alias, alternate version or SQL claim
projection is introduced.

Both immutable append phases and all five key/unique constraints remain. Phase
readers require coherent original/final fields and positive safe coordinates,
rejecting impossible mixed rows without a stored discriminator. Foreign final
names may be outside selected original contracts. Typed SQL exposedDelta retains
the complete selected value and maps to unchanged wire delta. Original result/
completedAt, nullable private failure, historical selected changes and final
position/hash remain retained evidence.

ServiceNode guard advances from 16 to 17 and requires empty affected storage.
Its six-column metadata and command-derived append/producer/first-gap private
progress remain unchanged, as do resource/final/checkpoint/admission transactions,
receipt-only admission/rewind, coherent capture, full-generation reset and close/
drain fences. Aggregate, Agent and replica physical storage/guards remain
independently owned; preservation comparisons are unrun. No migration, added reset
path or reset invocation is introduced.

Typed browser refusal mappings, README, ADR 003, glossary and focused architecture/
pattern prose are updated. Existing assertions require no raw Service-row or seed
edits for this cutover. All type/lint/test/build/acceptance, formatting,
documentation/link/citation/frontmatter/whitespace/obsolete-reference checks,
source-range/hash refresh, independent implementation verification and preservation
comparisons remain deferred. No new test, fixture, runner or configuration is
created. This implementation does not verify Plan 232 or complete another table

## Original review record

**Reviewed:** 2026-10-16 against then-current source, including uncommitted Plan 232, with independent lifecycle and column-design reviewers. Exactly this ServiceNode table occurrence is reviewed. Metadata, session replicas, selected resource tables and admission/exposure protocols are dependencies, not additional completed table reviews. All verification remains deferred.

**Verdict: simplify sixteen stored columns to ten; retain two immutable append phases.** Remove contractVersion, serviceName, actorName, actorVersion, sessionName and claims from SQL rows. Reconstruct complete original input from the immutable bound Service identity and exact selected contract. Rename SQL delta to exposedDelta while preserving transport delta. New-original admission must validate own selected contract membership, canonical command name and exact source version before the version can be derived safely.

The proposed columns are:

```text
nodeIndex, id, pushIndex, commandName, payload, stagingOutcome,
failure, serviceIndex, dispositionChainHash, exposedDelta
```

At original review time this was an unimplemented recommendation and commands still had sixteen fields; ServiceNode's six-column metadata and guard 16 are written under active [Plan 232](../../archive/plans/232-plan-service-node-derived-progress-and-checkpoint.md), with verification deferred. This review does not verify that implementation. AggregateNode's eleven-column command model is not copied: its standalone admission permits per-command claims to differ, whereas ServiceNode always binds complete claims to one retained identity.

## Physical scope, row meaning and lifetime

[serviceNodeCommands](../../../packages/core/src/ServiceNode/serviceNodeTables.ts#L21-L53) declares physical commands in the ServiceNode database. The connected browser Service SharedWorker owns persistent IndexedDB-backed SQLite and constructs ServiceNode over it. The actual production construction search found no ServiceNode Native or standalone host. Ordinary reopening retains the same complete identity/definition binding and command generation. Closing ServiceNode fences and drains admitted SQL/delivery work before storage closes; it does not delete commands. [Browser construction and binding](../../../packages/browser/src/ServiceNode/makeServiceWorkerRuntime.ts#L95-L204), [persistent storage](https://github.com/morgs32/zerospin/blob/41b548a019ff1e08f65f60c9459e0908a80c64f5/packages/browser/src/Node/openNodeStorage.ts#L8-L54), [close boundary](../../../packages/core/src/ServiceNode/ServiceNode.ts#L153-L166).

One row is immutable original input retained by ServiceNode or a separately appended final exposure. It is a local delivery/recovery journal, not mutable pending command state, an admission receipt, canonical outcome storage or telemetry.

1. ServiceNode.accept invokes original admission inside the serialized SQL transaction. A new original receives nodeIndex and pushIndex and retains complete staging input. An exact original retry compares every immutable input member, returns retained original/final records and allocates nothing. A final-only ID cannot become a new original. [Transaction owner](../../../packages/core/src/ServiceNode/ServiceNode.ts#L420-L440), [original admission](../../../packages/core/src/ServiceNode/acceptServiceOriginalTx.ts#L34-L112).
2. ServiceNode.receiveCommand invokes final retention inside its transaction. The final receives a new nodeIndex and Service position/hash and may belong to a foreign producer. Exact final equality and occupied ID/position/name checks precede insertion. Final history, selected resource changes, matching-original admission proof and materialization checkpoint commit together. An old missing final at or below an installed baseline may still be retained without reapplying resources; only a newer final advances resources/head. [Final retention](../../../packages/core/src/ServiceNode/retainServiceFinalTx.ts#L35-L131), [receive transaction](../../../packages/core/src/ServiceNode/ServiceNode.ts#L576-L601).
3. ServiceChain admission receipts and subscriber acknowledgements never delete either phase. Unresolved recovery and requested pending receipts correlate the phases by canonical ID. Plan 232 derives allocator maxima and the first-gap private final prefix from this retained generation history. [Snapshot recovery](../../../packages/core/src/ServiceNode/ServiceNode.ts#L311-L381), [derived maxima](../../../packages/core/src/ServiceNode/readServiceNodeIndexes.ts#L6-L18), [private prefix](../../../packages/core/src/ServiceNode/readServiceNodeOutcomeIndex.ts#L8-L27), [delivery acknowledgement](../../../packages/core/src/Node/makeNodeSubscriptions.ts#L103-L117).
4. Whole-generation connected baseline replacement is the command deletion boundary: it rotates nodeId, clears commands/resources, installs captured resources/checkpoint and resets admission/pause atomically. It retains the verified identity fingerprint and definition; it does not reinterpret old commands under a changed lock. Reset attachment acknowledgements occur outside SQLite. [Replacement orchestration](../../../packages/browser/src/ServiceNode/makeServiceWorkerRuntime.ts#L295-L325), [generation replacement](../../../packages/core/src/ServiceNode/ServiceNode.ts#L632-L687).

## Every column and constraint at original review

There are sixteen fields. nodeIndex is the integer primary key; id and commandName are required text. The thirteen other fields are nullable to represent phase-specific absence. The primary key, nullable unique pushIndex and serviceIndex, and partial unique original-ID/final-ID indexes provide five key/unique constraints. An ID may intentionally appear once in each phase. No foreign key, declared default, expiry, SQL AUTOINCREMENT declaration, phase CHECK, positive-safe-index CHECK or hash CHECK is present. Writers supply coordinates explicitly; integer-primary-key behavior is not the domain allocator.

## Structured values

1. **claims:** its declared structure is the whole string-keyed claims record with unknown values; there is no reduced subject-only projection. Complete claims remain part of the bound identity and original protocol after SQL normalization. [Full JSON identity hashing](../../../packages/core/src/Node/sessionKey.ts#L16-L29) validates JSON and canonicalizes the entire identity; it does not authorize discarding unrecognized claim members from reconstructed commands. Ordinary attachment and verified replacement require the same fingerprint. [Definition construction](../../../packages/browser/src/ServiceNode/makeServiceNodeDefinition.ts#L7-L23), [attachment/replacement checks](../../../packages/browser/src/ServiceNode/makeServiceWorkerRuntime.ts#L95-L137).
2. **stagingOutcome.result / completedAt:** result is the original successful local JSON value, including a valid JSON null; completedAt is the encoded timestamp from DateFromString. A null result member is distinct from absent stagingOutcome on a final row. Keep immutable original evidence separately from mutable replica undo/replay state. [Staging schema](../../../packages/core/src/contracts/StagingOutcomeSchema.ts#L3-L8).
3. **failure:** retain `_tag`, code, optional scope, message, nullable status and complete JSON extra. These are the public error envelope, without internal recognition metadata. Nullable failure cannot replace complete retry evidence or identify Success/Failure. Service privacy filtering uses full claims and exact producer/session context; other recipients receive null. [Failure schema](../../../packages/error/src/matchZerospinErrorCode.ts#L27-L36), [Service disclosure](../../../packages/core/src/serviceSession/filterServiceBrowserCommand.ts#L44-L69).
4. **delta / proposed exposedDelta:** retain both upserted and deleted arrays. Each upsert retains id, modelName, version, createdAt, updatedAt and authored resource properties; each deletion retains modelName/id. IDs and model names identify the changed resource; timestamps/properties preserve the historical selected value. The model version is derivable under a fixed bound definition, but remains in the settled shared complete-resource envelope rather than introducing a Node-only compressed delta representation. Keep exact versions and the existing model/property validation before resource mutation. Empty arrays are valid and do not remove the final position/hash/failure record. [Delta schema](../../../packages/core/src/models/ActorDeltaSchema.ts#L8-L11), [complete resource schema](../../../packages/core/src/models/EncodedResourceSchema.ts#L8-L20), [deletion references](../../../packages/core/src/aggregateSession/AggregateActorCommandSchema/ResourceSchema/ResourceSchema.ts#L7-L10), [atomic validated application](../../../packages/core/src/Node/applyNodeResourceDeltaTx.ts#L12-L77).

## Reviewer reconciliation and limits

Both independent reviewers recommend the same ten-column shape and identify full Service-bound claims as the distinction from Aggregate's eleven-column model. Both require selected original contract validation before source-version derivation, complete reconstructed retry/privacy/dispatch behavior, two immutable phases and historical selected output. Both recommend direct delta-to-exposedDelta storage naming and coherent phase readers without another discriminator.

No ordinary supported-path lifecycle failure was established. The missing selected-contract check must be repaired as part of version normalization; impossible mixed SQL rows expose a reader-integrity gap, not an observed runtime failure. Existing readers and ADRs are context, not reasons to retain duplicated columns.
