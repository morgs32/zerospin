# AggregateVersionRepo.aggregateVersionChainOutbox

**Updated:** 2026-10-15. [Plan 199](../../archive/plans/199-plan-aggregate-ordered-operations-union.md) implemented one ordered operations union; [Plan 200](../../archive/plans/200-plan-aggregate-operation-context.md) implements full evaluated commands and removes repeated embedded context. Plan 200 is implemented and required verification is complete.

**Verdict:** Retain this complete pending delivery. The source resource changes or retained Failure, materialization head and complete evaluated command commit in the same synchronous transaction. Delete its publication only after AggregateVersionChain durably retains that command. Subsequent exact recovery reads AggregateVersionChain history without reevaluation.

## Current representation

1. The shared **16-column** `evaluatedCommandShape` retains the full admitted input with canonical `id`, plus `outcome`, `dispositionChainHash` and one ordered `operations` union. Its fields are `aggregateIndex`, `id`, `commandName`, `payload`, `externalOutcome`, `contractVersion`, `aggregateId`, `aggregateName`, `aggregateVersion`, `origin`, `nodeId`, `sessionName`, `pushIndex`, `outcome`, `dispositionChainHash` and `operations`. Full admitted input retention supersedes the earlier eleven-column recommendation; it is an explicit maintainer decision to use one honest command value across finalization, delivery and history.
2. `outcome` is `{ result: Success | Failure, finalizedAt: Date }`. Only `result` contains `_tag` and success/failure content. The source samples finalization once and uses the same Date for model application, outcome construction and subsequent projection. There is no separate Aggregate execution-start column. An admitted command's original release stays in `aggregateVersion`; the executing release comes from the bound AggregateVersionRepo/AggregateVersionChain.
3. Model members have `{ operationIndex, modelName, modelVersion, resourceId, operationName, body }`. External members have `{ operationName: 'external', operationIndex, externalContractName, externalContractVersion, payload, externalCommandId }`. Their shared authored order and sparse `operationIndex` remain; replay filters external emissions before ID allocation and never renumbers model entries. A retained Failure has no operations.
4. Parent `id` and `origin` supply embedded command lineage/authority. The original bound release supplies external `aggregateVersion`. AggregateChain's `recordOriginalCommandOutcomeTx` validates full immutable admitted input, retains the original outcome and constructs complete standalone pending requests atomically. It does not retain full evaluated-command history or recreate requests on matching duplicate outcomes. Standalone pending requests, standalone canonical model operations and unrelated Service storage remain complete; Service shares the new outcome shape.
5. AggregateVersionRepo constructs `IEvaluatedCommand` once, writes it and returns the same value through `finalizeCommand`. `readEvaluatedCommand` recovers the full value from pending publication or `AggregateVersionChain.getEvaluatedCommand`. AggregateVersionChain compares complete evaluated commands on duplicate append and retains `commands` independently of actor/agent subscriber progress. Both fanout queues deliver directly from retained commands; acknowledgement advances the corresponding subscriber cursor without deleting commands or maintaining another payload table. Aggregate projections bind/apply model operations with parent `id` and `outcome.finalizedAt`; external descriptions never authorize requests from history.

## Verdict

**Retain the table.** One row is the complete output of one locally committed AggregateVersionRepo occurrence, awaiting durable publication to the same release's AggregateVersionChain. It is a **complete pending delivery**, not permanent execution history, an external-request queue or an acknowledgement marker. Its second reader supports exact original/replay result recovery while publication remains pending. Deletion after publication is correct even when AggregateChain has not received the original RPC reply: AggregateVersionChain history then owns exact recovery.

**Combine the two operation columns.** The current table has 12 top-level columns, but there is no independent lifecycle justifying separate `operations` and `externalOperations` arrays: both are written by the same transaction, published in the same packet, acknowledged together and deleted together. Store their contents in one ordered `operations` union of model mutations and external-operation descriptions. That produces an 11-column row while preserving every required output fact. Aggregate projections select model mutations; AggregateChain selects external descriptions when retaining pending requests.

Keep `operationIndex` on every union member. Replay removes external emissions before preparation, so the remaining model operations can have gaps. Array offsets must not become authored operation positions. Preserve encoded values, stable external command IDs and complete packet equality on retries.

The initial review incorrectly treated both separate columns as necessary because both kinds of output were necessary. The maintainer corrected that representation error. The complete-message requirement applies to the whole row; it does not require a separate column per output kind. Four nested fields also repeat local packet/owner context; that secondary recommendation is recorded separately below.

## Physical scope, row meaning and lifecycle

One physical AggregateVersionRepo database is bound to `systemId / aggregateId / aggregateName / aggregateVersion`. Model resources, `materializationHead` and this outbox share that database. AggregateVersionChain has a separate database despite using the same identity dimensions. The packet therefore omits owner identity, aggregate release routing and admitted payload; publication acquires AggregateVersionChain using `this.key`.

- [Owner name](../../../packages/system-worker/src/AggregateVersionRepo/aggregateVersionRepoName.ts#L7-L12), [resource/config composition](../../../packages/system-worker/src/AggregateVersionRepo/AggregateVersionRepo.ts#L76-L85), [same-key publication](../../../packages/system-worker/src/AggregateVersionRepo/AggregateVersionRepo.ts#L150-L164).

1. Before an occurrence commits, it has no outbox row. `materializeCommandTx` enforces contiguous local progress, executes the release's program within its business savepoint, finalizes `commandOutcome`, then inserts one complete packet and advances the checkpoint in the same synchronous outer transaction. In current storage, a public Failure advances progress with both operation arrays empty; an infrastructure failure aborts the transaction. No successful materialization commit omits packet creation; acknowledged publication can later delete the packet.
   - [Occurrence checks](../../../packages/system-worker/src/AggregateVersionRepo/utils/readAggregateCommandTx.ts#L28-L73), [materialization](../../../packages/system-worker/src/AggregateVersionRepo/materializeCommandTx.ts), [business savepoint](../../../packages/system-worker/src/AggregateVersionRepo/utils/executeAggregateCommandTx.ts#L38-L84), [packet/checkpoint retention](../../../packages/system-worker/src/AggregateVersionRepo/utils/retainEvaluatedCommandTx.ts).
2. The stored packet is immutable while pending. The sole producer inserts; there is no update, retry counter, status transition or diagnostic writer. More occurrences can commit while publication is unavailable, so the table can hold multiple ordered packets. The existing `aggregateIndex` supplies queue order without a separate FIFO allocator.

3. Original finalization and replay reception acquire `aggregateVersionChainOutbox.producerLease` before production and explicitly run `aggregateVersionChainOutbox.wake()` on producer exit. Activation directly runs local catch-up and explicitly wakes publication on exit, including when no new rows are produced. These exit-preserving finalizers schedule delivery even when later work fails after earlier publication commits. Per-queue serialization preserves page order. RPC runs outside SQL and the materialization execution permit; original return does not wait for publication, projection or external requests.
   - [Replay production and activation wake](../../../packages/system-worker/src/AggregateVersionRepo/AggregateVersionRepo.ts#L187-L231), [original production and explicit wake](../../../packages/system-worker/src/AggregateVersionRepo/AggregateVersionRepo.ts#L240-L264), [producer wake](../../../packages/system-worker/src/makeOutboxQueue/makeOutboxQueue.ts#L267-L304), [serialized delivery](../../../packages/core/src/outbox/makeOutboxDelivery.ts#L324-L338), [fresh original return](../../../packages/system-worker/src/AggregateVersionRepo/finalizeCommand/finalizeCommand.ts#L73-L108).
4. Publication decodes the complete packet and calls `AggregateVersionChain.appendExecutionPackets`. AggregateVersionChain arms its independent fanout recovery, validates exact duplicate packets and contiguous new positions, and atomically retains history plus complete actor/agent fanout messages. Its successful reply does not require projection delivery to have completed.
   - [Packet decoding/publication](../../../packages/system-worker/src/AggregateVersionRepo/AggregateVersionRepo.ts#L119-L165), [publication RPC](../../../packages/system-worker/src/AggregateVersionChain/AggregateVersionChain.ts#L268-L295), [duplicate equality](../../../packages/system-worker/src/AggregateVersionChain/appendEvaluatedCommandsTx.ts#L64-L73), [atomic publication](../../../packages/system-worker/src/AggregateVersionChain/appendEvaluatedCommandsTx.ts).
5. Only after a successful publication RPC envelope does AggregateVersionRepo transactionally delete the exact delivered page. It does not delete AggregateVersionChain history, wait for all actor/agent acknowledgements, or wait for AggregateChain's original `commandOutcome` retention. Those are separate durable facts with separate owners.
   - [Envelope before acknowledgement](../../../packages/core/src/outbox/makeOutboxDelivery.ts#L286-L294), [exact page deletion](../../../packages/system-worker/src/makeOutboxQueue/makeOutboxQueue.ts#L213-L229).
6. A duplicate original first checks local materialization progress. If already committed, `readCommandResult` reads the pending packet, or calls the same-key AggregateVersionChain after pending deletion. It validates packet/index and authoritative admitted-input association. Missing/unavailable history fails without reevaluation, resampling timestamps or allocating new external command IDs.
   - [Early duplicate and permit recheck](../../../packages/system-worker/src/AggregateVersionRepo/finalizeCommand/finalizeCommand.ts#L56-L108), [pending/history lookup](../../../packages/system-worker/src/AggregateVersionRepo/readEvaluatedCommand/readEvaluatedCommand.ts#L31-L68), [input association](../../../packages/system-worker/src/AggregateVersionRepo/validateCommandIdentity.ts).

Original and replay both produce rows in this table. A replay row records the receiving release's own model output and `commandOutcome`; it does not merely copy the original outcome. Replay discards external emissions before preparation or ID allocation. AggregateVersionRepo never executes requests from this table. AggregateChain first retains `commands.commandOutcome` and complete pending request rows, then owns request execution. The frozen external-operation descriptions must survive publication because AggregateVersionChain supplies exact original replies after local deletion. Their contents remain required in the proposed union; a separate array is unnecessary and is not another runnable request backlog.

## Structured values in current storage

### `origin` and `commandOutcome`

`origin.kind` selects the settled authority union. Actor adds `actorName`, `actorVersion` and complete `claims`; Agent adds `agentName` and `agentVersion`; System has no further fields. Names/versions identify the authored authority, while claims retain the submitted claim values used for recipient identity filtering. They cannot be derived from this AggregateVersionRepo's release. Null claim values, if authored, remain claim data rather than absent authority. Removing the variant tag or substituting the producer tuple would change authority semantics.

`commandOutcome._tag` selects `Success.success` (any JSON, including explicit null) or `Failure.failure`. Both contain non-null `recordedAt`, sampled when finalizing the occurrence and preserved on retry. A Failure contains `_tag: 'ZerospinError'`, `code`, optional `scope` (`contract`/`actor`/`aggregate`), `message`, nullable numeric `status`, and JSON `extra`. Missing scope means no scoped classification; null status means no status value; null success/extra are valid JSON. The complete failure is required for exact outcome transport and private failure projection, rather than only its code. These canonical variants are retained; this table introduces no new failure fields.

## Recorded finding: one lifecycle, one ordered `operations` column

**Maintainer direction, 2026-10-15:** replace the split arrays with one ordered union. Retain the ten non-operation columns and one non-null `operations` JSON column. Each element represents either a model mutation or an external-operation description, with its original `operationIndex`. A Failure has an empty union; a success may also have an empty union. A replay packet has no external variants and may retain sparse indexes. The union records authored output order rather than grouping entries by consumer.

The current preparation phase already traverses one mixed authored sequence and produces model/external entries in that order. `applyAggregateOutputTx` splits them into two arrays, and `retainAggregateResultTx` persists both in the same packet. Replacing that split does not introduce a new delivery responsibility or require an independent acknowledgement.

- [Ordered preparation](../../../packages/system-worker/src/AggregateVersionRepo/utils/prepareAggregateOutput.ts#L23-L45), [current split](../../../packages/system-worker/src/AggregateVersionRepo/utils/applyAggregateOperationsTx.ts#L22-L44), [single packet/transaction](../../../packages/system-worker/src/AggregateVersionRepo/utils/retainEvaluatedCommandTx.ts), [whole-page acknowledgement](../../../packages/core/src/outbox/makeOutboxDelivery.ts#L286-L294).

This changes the shared execution-packet representation, not only one SQL declaration. An implementation must update these responsibilities together:

| Component                                                            | Required behavior with the ordered union                                                                                                                                                                                                                 |
| -------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| AggregateVersionRepo preparation/application/retention               | Preserve mixed output order and original indexes; apply model mutations only; persist the complete encoded union with resources/refusal and checkpoint. Never invoke external requests.                                                                  |
| `AggregateExecutionPacketSchema` and `aggregateExecutionPacketShape` | Define one union array in `operations` and remove the separate `externalOperations` field. The outbox, AggregateVersionChain history and complete fanout messages reuse this representation.                                                             |
| `AggregateVersionChain.appendExecutionPacketsTx`                     | Validate union variants, increasing nonnegative safe `operationIndex` values, association and model/external identities; require no output for Failure; compare complete packets for duplicate publication; commit complete history and fanout together. |
| `AggregateChain.acknowledgeOriginalFinalization`                     | Validate the complete original reply, retain exact `commandOutcome`, and select external variants to insert complete pending requests in the same transaction. Preserve existing exact-outcome retry behavior and do not recreate deleted requests.      |
| Aggregate projections                                                | Select model variants, apply them with parent `executionStartedAt`, preserve sparse operation indexes and private completion/hash behavior, and never invoke or enqueue external requests.                                                               |
