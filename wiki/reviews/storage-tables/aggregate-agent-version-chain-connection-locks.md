# AggregateAgentVersionChain.connectionLocks (removed)

**Original review:** 2026-10-16 against uncommitted source after the intermediate Plan 211 history change and before Plan 212. The two-column SQL/full-lock inventory and conditional cleanup findings below are historical. They do not describe current Agent storage or command authority.

**Current decision:** remove the Agent connection table without replacement SQL, copied capability/installation state or a revocation registry. The exact owner-release-bound Agent declaration supplies selected public capabilities; the trusted attachment supplies variable observer admission and phase. Agent definitions and Origin have no independent version. AggregateAgentVersionChain retains public exposedCommands plus its fixed Node Repo acknowledgement, with no private completion history/cursor or ordinary browser command-submission capability.

Full initial lock/Origin validation and whole authored-lock equality remain mandatory. The lock still contains ordinary contract definitions; those definitions confer no observer submission API. Capability reads validate the full Aggregate owner/Agent/session/issued-and-resumed Node attachment and use configured System synchronously. A nonempty observer Node binds ticket/resume, not command production. Invalid, malformed, unavailable or repinned Agent context must fail closed without selecting another owner release.

Installation writes only attachment state. Disposal invalidates attachment authority before closing the original accepted socket and attempts both if either fails. Failed installation/notices/sends, invalid state and onError must use that disposal path. Replay/live handoff cannot restore disposed observer authority. Actor SQL capabilities/private recovery are separate, and Service observers retain their own phase/Node replay-liveness boundary.

## Historical physical owner and represented fact

The physical AggregateAgentVersionChain is bound to `systemId / aggregateId / aggregateName / aggregateVersion / agentName / agentVersion`. There is no Node partition or actor path. Activation resolves that exact authored Agent projection and Aggregate release before returning the Agent database config.

Before Plan 212, one row associated a validated full Agent lock with one Partyserver connection ID. It is **connection authorization state**, not application resources, retained commands, a checkpoint, pending delivery or subscriber progress. The row was immutable until socket disposal. Its presence was required by the capability reader, but that usage did not establish a distinct fact requiring SQL persistence.

## Original admission, readers and lifecycle

1. `SystemApi.openAgentSession` constructs the exact authored Agent lock and requests a bound ticket. SystemRepo validates Agent/release/session/full-lock equality. Ticket consumption and forwarding supply trusted admission; forwarding removes caller-supplied Zerospin headers and reconstructs the owner/Origin/producer/lock headers from that admission.
2. Agent `onConnect` strictly decodes the full lock and identity, requires the bound Agent/release and a non-null producer, and requires `isEqual(makeAggregateSessionLock(agent), lock)`. There is no per-connection choice of model subset or contract versions.
3. `installConnection` encodes/inserts `{ connectionId, lock }`, then calls `connection.setState` with `awaiting-resume` admission without an intervening yield. SQL and attachment installation cannot share a transaction. The attachment retains Aggregate ID/name/version, actual Origin, session, issued Node and replay phase; resumed state additionally holds the Node and any pending command-admission claim.
4. Messages require attachment Aggregate binding and a retained capability row. Agent reads compare the copied lock's session/Origin with owner/attachment and project only model keys/command versions. Broadcast also reads capabilities. Replay checks the issued Node, commands require exact Aggregate/Origin/session/Node and contract name/version, and private Failure delivery matches full Origin/session/Node.
5. Ordinary Agent `onClose` delegates to `disposeConnection`, which deletes the row by connection ID in `finally`. No update, independent revocation, TTL, lease, subscriber cursor or capability mutation writer was found. Socket closure is the deletion condition; command publication acknowledgement and history retention do not delete connection capabilities.
6. Hibernation preserves the socket and serialized trusted attachment; it is not disposal. Locally installed Partyserver restores user attachment state, so SQL is not needed to retain producer/phase/admission across hibernation. The Agent Chain has no orphan-row activation reconciliation hook.

## Original conditional installation and teardown gaps

Agent installation has no failure compensation: the `installConnection` exit finalizer disposes only Actor connections. If Agent SQL insertion succeeds and attachment installation throws, the row remains unless a later close callback runs. Encoding/SQL/attachment failures also need reliable teardown of the original accepted socket. Partyserver accepts that socket before `onConnect`; its fetch exception handler creates/closes a different pair and does not explicitly close the original accepted socket.

Agent send/error closure branches similarly depend on later `onClose` for SQL reclamation. The Agent class does not forward shared `onError` or run Actor activation reconciliation. A row without a valid attachment cannot authorize commands or receive live output; these are conditional orphan/socket-teardown gaps, not demonstrated ordinary-path unauthorized delivery, a reproduced production leak or a verified runtime failure.

Removing the redundant Agent table eliminates its SQL/attachment split and orphan-row responsibility. Preserve reliable socket teardown when attachment installation or later delivery fails. Do not add Agent SQL reconciliation to maintain a copied declaration that should disappear. Actor SQL disposal and its existing reconciliation remain separate.

## Historical approved connection replacement

Remove Agent `connectionLocks`, its full-lock copy, unique index, insertion/deletion and SQL lookup. Add no replacement marker, compact capability table, revocation registry, timestamp or copied lock in another store. Keep the existing trusted WebSocket attachment as the actual per-connection admission and phase state.

Derive capabilities from the exact authored Agent using the existing `makeAggregateSessionLock` / `makeConnectionCapabilities` semantics. This selects `agent.db.models`, unwraps the Agent's public contract versions and excludes external contracts. Do not expose the Aggregate release's full model graph, map every registry entry blindly, select latest versions or broaden the admitted capability set.

Before returning Agent capabilities, validate the exact Agent/release and trusted attachment: Aggregate ID/name/version against the physical owner, Agent Origin kind/name/version against the owner, session against the declared Agent session, and nonempty issued Node. Once resumed, preserve equality of resumed and issued Node. Apply these guards to message **and broadcast** paths; current message Aggregate checks do not cover broadcast's direct capability read. Keep full lock decoding/equality during initial admission, exact command own-key/version checks, private recipient checks, replay/live phases and the one-pending-command claim.

Preserve synchronous broadcast and final replay/live handoff. If derived capabilities require the `System` Effect service, explicitly supply the exact configured context to broadcast's `Effect.runSync`; Plan 211's final replay already supplies captured `System`. A missing service at that synchronous boundary would close sockets and is an implementation hazard, not a defect observed in the current table-backed reader. Chain activation already requires the exact Agent/release, so this proposal adds no latest-version fallback or remote lookup.

Actor's per-connection selected model subset and admitted historical command versions can vary; its three-column capability representation does not justify copying those columns into Agent. Keep Actor and Service storage unchanged in any bounded Agent implementation. Agent retained history/private resolutions and pending publication also keep their existing responsibilities.

The full lock remains an admission-boundary value, while actual per-socket admission/phase stays in the trusted attachment. Configured `System` is captured for synchronous broadcast capability reads. Agent `onError` delegates to disposal; replay/live and pending-command handoffs revalidate actual attachment state so late callbacks cannot restore disposed admission. Actor SQL disposal/reconciliation and Service storage retain their existing responsibilities. Existing checks are updated for the later batch verification; none is executed now.
