## Physical owner, row fact and lifetime

The browser Aggregate session owns an in-memory SQLite replica combining selected model resources with the declared session tables. Its Effect Scope opens and closes that database. Connected and standalone browser sessions both use this replica flow. The same declaration also backs the Native persistent `session_<owner.key>` database; closing Native SQLite does not delete its history. Browser transience therefore does not justify deleting fields needed for retained Native replay.

One row records one of two distinct facts:

- **Successful local staging:** immutable original command input and original local result at its allocated `sessionIndex`, initially without Node coordinates. First AggregateNode retention acknowledgement can enrich its coordinates without rewriting the original input/result or reallocating its position.
- **Received final command:** canonical admitted command ID/name, selected authoritative resource changes, nullable private failure and exact Aggregate position/hash, at a separate allocated `sessionIndex`. It carries no original payload or local staging result.

This is **local immutable phase history with limited coordinate enrichment**, not a dedicated pending delivery table. A final counterpart with the same command ID removes staging from optimism and handoff eligibility; it does not replace or delete staging. Final-only history cannot be resubmitted. The local result, Node retention acknowledgement, canonical execution commit and observation of selected final output remain separate facts. The browser row does not retain the complete canonical `outcome` or `IEvaluatedCommand`; those remain in their owning Chain histories.

[ADR 003](../../adrs/003-immutable-node-command-history-and-submission-order.md) requires separate staged/final observations, stable local positions, one row of each phase per command ID, exact retry and recovery without reapplying covered resources. The Durable Object resource/history ownership rule does not make this client replica an AggregateVersionRepo or authorize deleting its local observation history.

## Every structured member

- **`origin`:** the Actor branch retains `kind: 'actor'`, `actorName`, `actorVersion` and complete `claims`, an open string-keyed record. The Agent branch retains `kind: 'agent'`, `agentName`, `agentVersion`. The current SQL codec additionally allows `{ kind: 'system' }`; `SessionCommandSchema` already excludes that branch. Preserve the whole canonical original session Origin rather than splitting off claims or replacing them with Actor partition identity. Actor/Agent constants can be repeated alongside invocation claims without inventing another Origin representation for one table.
- **`staging.result`:** original encoded JSON success result, including valid JSON null. Local staging returns its decoded result to the caller and retains the encoded original observation under ADR 003. Rebase can produce different resources/results but does not rewrite this observation. Removing it loses original local result inspection/history; this is an explicit retained-history responsibility, distinct from the canonical `outcome`.
- **`staging.startedAt`:** original Date encoded as a string. Local model writes use this sample, and replay reuses it as `appliedAt` so speculative resource timestamps remain stable. Keep that one logical application time. This review does not rename it to canonical `outcome.finalizedAt`, which would conflate local staging with authoritative finalization.
- **`staging.completedAt`:** second Date sample after local synchronous evaluation. No reconciliation, replay, pending-selection or recovery decision reads this member. Remove it; generic inspection of elapsed staging time is diagnostic, not an independent durable requirement.
- **`staging.stagedDelta.inserted` and `.updated`:** arrays of complete initial speculative resources, each containing `id`, `modelName`, `version`, `createdAt`, `updatedAt` and the model's authored property keys. These are initial snapshots, not the latest rebased optimism. No later semantic reader consumes the retained arrays. Remove them from retained staging.
- **`staging.stagedDelta.deleted`:** initial speculative deletion references, each `{ id, modelName }`. No later semantic reader consumes this retained array. Remove it with the other historical speculative output.
- **`staging.stagedDelta.operations`:** ordered initial applied-operation array. Each member retains `commandId`, zero-based `operationIndex`, `modelName`, `modelVersion`, `resourceId`, `operationName`, encoded `body`, `appliedAt`, nullable `previousUpdatedAt` and encoded `inverseOperation`. Create bodies contain complete `attributes`, update bodies contain an attribute patch, delete bodies are empty, and move bodies contain `property`, nullable `prevId` and nullable `nextId`. Inverses are null for create, null-or-attribute-patch for update, null-or-complete-`resource` for delete, and null-or-`{ property, prevId }` for move. The initial array seeds current inverse bookkeeping; the historical copy inside `commands.staging` has no subsequent replay/rewind consumer. Remove the retained copy while preserving current inverse capture/application and sparse operation identity wherever required by its actual owner.
- **`failure`:** `_tag: 'ZerospinError'`, `code`, optional `scope` (`contract`, `actor` or `aggregate`), `message`, nullable numeric `status`, and arbitrary JSON `extra`. Retain the complete exposed refusal so later recognition/inspection does not depend on reconstructing it from current authored code. Absence of `scope` differs from a fabricated scope.
- **`actorDelta.upserted`:** selected complete encoded resources with the resource members above and open model property keys. **`actorDelta.deleted`:** `{ id, modelName }` references. Retain empty arrays: a final command can advance continuity and settle staging without changing any selected resource. No operation/result data or full private claims may be inferred from an empty delta.

## Bound context, invocation authority and shared-schema consequences

The four proposed context removals follow exact physical scope, not a claim that ownership fields are always redundant. Browser acquisition binds one immutable session declaration and initializes the concrete Aggregate ID. Connected Node identity includes Aggregate name/version/ID, session name, full Actor claims and declaration-lock hash; reconnect refuses a different identity. Native derives its replica filename from that exact owner identity and checks retained Actor/full claims before mutation. Standalone storage fixes Aggregate/Actor versions, session name and generated path; attachment separately validates the retained Aggregate ID and full declaration hash.

An implementation must pass frozen bound Aggregate ID/name/version/session context into input reconstruction and replay. Validate the complete received context **before** dropping its repeated fields; today's replica importer itself checks Aggregate name/session and Actor identity but does not independently compare Aggregate ID/version on first insertion. Reconstructed Node input must still be complete. Keep exact retry comparisons for all non-derived original input and selected output. Do not reconstruct from a later credentials-provider result or remove context from the admitted command/server history.

**Full Origin is different.** Standalone excludes incidental claims from its shared storage identity. Snapshot identity substitutes the observing attachment's claims, whereas each retained submitted command preserves its original invocation claims. Replaying another tab's staged command with local metadata Origin would evaluate its contract under the wrong authority. Preserve per-row full Origin even though connected exact-claims Nodes often repeat it. This requirement corrects the initial column review's overly broad five-field derivation candidate.

**Source contract version is also different.** The selected session lock fixes the ordinary locally constructed version, but Node ingress currently validates owner/Actor/session identity without enforcing selected contract-name/version membership. The replica preserves received source versions, and replay intentionally decodes/adapts those payloads. Removing `contractVersion` needs a separate admission/interpretation decision; this finding recommends keeping it.

**Agent submission state is independently owned.** Agent replicas spread this shared declaration, but `nextAgentSubmissionTx` genuinely allocates and retains their `pushIndex` as a direct producer sequence. Removing the Actor replica's redundant copy must isolate the Agent-owned column/schema instead of deleting the Agent fact. This is a coordinated consumer consequence, not a completed Agent table review. Service storage and Node storage keep their own findings/statuses. Shared staging schema cleanup must similarly update its actual consumers without changing the canonical `outcome` contract or silently dropping current inverse operations.

## Transactions, retries, recovery and exact deletion

1. `stageSessionCommandTx` evaluates the contract and applies model operations through the synchronous savepoint, encodes the local result, allocates the local position, advances its allocator and inserts the staged row plus current inverse operations in one `makeTx` transaction. Local rejection, resource failure, stale session or asynchronous suspension prevents the successful retained row; rollback preserves prior state. No remote Node admission runs inside this transaction.
2. Handoff selects locally owned staged rows without a final counterpart and, for submission, without Node coordinates. AggregateNode acknowledgement imports its retained staged record into the same local row by ID/phase. Exact input and coordinates must agree. The receipt adds Node coordinates without changing original result or position. Lost replies can retry the same input; admission/retention does not establish canonical execution or selected final observation.
3. Ordered import validates contiguous Node delivery against `afterNodeIndex`, queries current transaction state, and lazily rewinds optimism once before its first mutation. A new final retains a separate row, applies its selected delta only when beyond the confirmed resource checkpoint, and advances position/hash together. Rebase then re-evaluates surviving original inputs in Node order followed by uncertain local order and replaces current inverse bookkeeping. Row allocation, resources, final history, replay, allocator, checkpoint and stream cursor commit together before receiver publication/acknowledgement. Typed expected replay refusals can yield no current optimism while keeping original staging; they do not manufacture a canonical Failure or delete input.
4. Exact final redelivery compares position, name, hash, selected delta, private failure and available Node coordinates; conflicts abort. Missing final coordinates may be enriched later. A point recovery ahead of the resource checkpoint is deferred because it cannot establish intervening continuity. A covered final settles matching staging without applying its resource delta again. `failure: null` and empty delta still settle it.
5. Normal Node snapshots replace resource/inverse state while preserving command history and its allocator. Requested pending receipts/missing IDs must form an exact partition; acknowledged staging cannot be reported missing. Captured receipts and unresolved staging are retained and replayed inside the snapshot transaction. Direct Aggregate snapshot recovery also retains command rows and uses the confirmed bound to avoid reapplying covered final changes.
6. Ordinary acknowledgement, final ingestion, outbox drain and snapshot replacement **never delete `commands` rows**. The explicit acknowledged reset path validates its snapshot, then deletes all commands and metadata before reseeding resources/history in the same transaction. Browser Scope disposal closes the whole memory database. Native Scope disposal only closes persistent SQLite. No TTL, automatic history pruning, per-command acknowledgement deletion or deployment-time cleanup is justified by this review.

## Reviewer reconciliation and verification limits

The lifecycle reviewer retains separate phase history, stable local allocation, exact Node coordinates, final correlation and non-pruning retention, while identifying `pushIndex` as a redundant Actor replica copy. The column reviewer identifies unused retained speculative output/completion time and four repeated bound context fields. The independent context reviewer proves the standalone invocation-claims exception and the source-version decoding requirement. Reconciliation keeps full per-command `origin` and `contractVersion`, preserves Agent-owned producer state, and retains `actorDelta` under the local naming convention.

Whole-object retry equality and generic Devtools JSON display are real current readers, but they do not create a domain need to retain stale initial speculative snapshots or a second staging timestamp. Removing those fields deliberately narrows what exact staging retry equality compares after a coordinated shared-protocol cutover. It does not justify removing original result, stable replay time, current inverse bookkeeping or selected final output. No ordinary-path corruption or runtime failure was reproduced; the supported finding is storage/consumer simplification with identified correctness boundaries.

No production/schema edits, implementation subplan, tests, fixtures, runners, configuration, reset, deployment or commit occur. No typecheck, lint, tests, builds, acceptance, formatting, documentation/link/citation/whitespace checks, independent implementation review or unchanged-storage comparisons ran. Source reading and three independent source reviewers supply this finding, not verification of any active implementation plan. Inherited migration-ledger and Agent/Service/Node occurrences retain their separate review statuses; aggregate inventory totals are not revalidated.
