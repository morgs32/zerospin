## Historical physical owner and represented fact

AggregateAgentVersionRepo is bound to `systemId / aggregateId / aggregateName / aggregateVersion / agentName / agentVersion`. There is no actorPath or individual Node partition. One pending row freezes one selected command for durable publication to that exact AggregateAgentVersionChain. Its resource transaction has committed; local publication acknowledgement/deletion has not.

This is **complete pending delivery**, not retained projected history or an index-only marker. The row must survive loss of the delivery reply and interruption after local commit. Retaining it after durable publication acknowledgement would turn a resource-owning Repo into a projected-history owner; deleting it before that acknowledgement would remove independent publication recovery.

The Agent config now copies the five public fields from `aggregateExposedCommandsTable.shape` and adds nullable compact `commandResolution`. It inherits the integer `aggregateIndex` primary-key descriptor, but does not copy retained-history indexes. The former pending config reused the ten-column flat Agent history shape; Plans 210 and 211 replace the pending and retained layouts separately. Queue lookup, ordering, bounded drain and deletion use the Aggregate position. No pending-table query needs a private-field index.

## Every structured value

### Frozen selected delta

`delta` requires `upserted` and `deleted` arrays. The producer compares selected graphs before/after the command, retaining changed/newly selected complete resources and identity-only removals. Removal can mean leaving a selection rather than source SQL deletion. An empty delta still publishes its command position, including no-op, Failure and unselected commands.

| Nested field             | Meaning, null/absence rule and necessity                                                                                                                                                                                                                                                                                                       |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `upserted[].id`          | Required resource identity, not the command ID. Retain so receiving replicas replace the correct resource.                                                                                                                                                                                                                                     |
| `upserted[].modelName`   | Required model/table identity. Multiple models can be selected; retain the resource's model association.                                                                                                                                                                                                                                       |
| `upserted[].version`     | Required portable resource-model version. It can be resolved from the bound release, but remains part of the common complete-resource envelope and exact resource codec. Keep that shared format rather than introduce a partial, outbox-specific resource format.                                                                             |
| `upserted[].createdAt`   | Required encoded resource creation time, decoded as Date by the resource envelope. Preserve the original value; it is not a new publication timestamp.                                                                                                                                                                                         |
| `upserted[].updatedAt`   | Required encoded resource last-update time. A resource newly entering selection can carry an earlier update time. Preserve its actual value rather than resampling publication time or substituting the current command's finalization time.                                                                                                   |
| Authored resource fields | Application-defined encoded properties, validated/encoded using the exact selected model's property/resource codecs before insertion. Nullable attributes/references retain their declared null meaning. These are resource data, including fields that resemble owner identity; the generic envelope does not invent further fixed subfields. |
| `deleted[].modelName`    | Required model/table of the removed selected resource. Needed to remove it from the correct model.                                                                                                                                                                                                                                             |
| `deleted[].id`           | Required resource ID within that model. No resource body, version or timestamp is required for this identity-only removal.                                                                                                                                                                                                                     |

Both arrays and their ordering/content are frozen in the pending row; retry does not rerun the selection against newer state. No additional framework operation list, `operationIndex` or repeated command context is needed inside these resource values; authored property values remain intact.

## Historical six-column pending implementation

```ts
{
  aggregateIndex: number; // primary key
  dispositionChainHash: string;
  id: string;
  commandName: string;
  delta: typeof ActorDeltaSchema.Type;
  commandResolution: null | {
    nodeId: string;
    pushIndex: number;
    failure: typeof PublicFailureSchema.Type | null;
  };
}
```

`commandResolution === null` means no owned private resolution. A present object with `failure: null` means owned Success; a present refusal means owned Failure. Presence remains necessary even for Success/no-op, because it advances the originating Node's private resolved prefix. Require nonempty Node ID, positive safe push index and the existing exact refusal codec. Do not add another discriminator or status flag.

Derive Origin from bound `agentName`/`agentVersion` and `sessionName` from `system.agents[key.agentName][key.agentVersion]`, after validating that exact declaration's Aggregate release. Never choose a latest/other agent version or manufacture session identity. Source `validateAgentCommand` already requires this exact session; the Agent declaration captures/freezes that identity. Agent opening, snapshots and bootstrap use it. The exact declaration is already required to activate this resource owner, so derivation introduces no new registry or cross-owner lookup.

The shared outbound publication still carries the complete existing recipient context, including session name and its protocol-specific `claims: null`. Private Node/session/full Origin comparisons stay exact. Those restored wire fields do not need to be stored in each Agent pending row.

Plan 210 implements physical `exposedCommandOutbox` with an Agent pending declaration independent of retained history's schema. `decodeAgentOutboxPublication` strictly decodes this compact row, rejects excess fields or malformed resolutions, resolves the exact authored Agent identity/release and validates the full shared publication before delivery. `RepoServicesLive` supplies the authored System. AggregateAgentVersionChain receives the same publication. Plan 211 replaces its flat history/decoder with `exposedCommands`, an optional four-column `commandResolutions` child and joined publication reconstruction. Separate pending/history representations express distinct query and retention responsibilities. Plan 211 verification is deferred; Plan 210's prior passing checks remain evidence only for that earlier pending change. Service physical storage is unchanged.

## Commit, retry, acknowledgement and deletion

1. AggregateAgentVersionRepo receives complete evaluated commands through its source-bound subscriber. `exposedCommandOutbox.producerLease` holds durable publication recovery before projection production; the Repo explicitly runs `exposedCommandOutbox.wake()` on exit. One synchronous page transaction applies model mutations, computes selected transitions, inserts every new complete pending row and advances the head. A later page failure rolls back earlier changes from that page. Already committed source positions do not recreate rows or reapply resources.
2. AggregateVersionChain advances source subscriber acknowledgement after the successful AggregateAgentVersionRepo receipt. That proves local resources/head/pending publication committed; it does not prove AggregateAgentVersionChain publication. Publication proceeds independently and never requires rerunning a contract program.
3. The shared queue uses logical/alarm name `exposedCommandOutbox` and now binds the Agent SQL table of the same name. It reads oldest Aggregate positions first, optionally bounded through captured N, in pages of at most 64 by default.
4. Preparation strictly decodes each compact pending row and its null-or-complete resolution, resolves the exact authored Agent version/release and restores the declared session name with `claims: null` before validating the shared publication. AggregateAgentVersionChain validates the exact source key, publication schema, contiguous new positions and exact normalized duplicate equality in its synchronous append transaction. Its public row and optional private child commit together; exact bound session/Origin context is reconstructed locally rather than stored per resolution. Broadcast follows commit; individual socket failures do not undo publication retention or acknowledgement.
5. Only after a valid successful receiving RPC envelope does the outbox transaction delete exactly that delivered page's Aggregate indices. A lost reply, invalid/rejected envelope, preparation error, interruption or failed deletion leaves complete pending messages for retry. A previously committed append accepts an identical retry without duplicating history.
6. Producer completion wakes delivery while preserving its original result. Constructor registration arms cold alarm recovery; active producer/revision checks prevent an older empty drain from releasing a newer wake. Rows remain until their own Chain acknowledgement, with no TTL, retry-count deletion or diagnostic-history retention.

## Historical null-coupling limitation and implementation evidence

The original review observed that the flat pending decoder rejected partial four-field recipient tuples, wrong/mismatching Agent Origin and invalid outbound positions/hash/IDs. If unsupported SQL corruption supplied a non-null `failure` with all four recipient fields null, `decodeAgentExposedPublication` converted it to `commandResolution: null`, discarding the refusal before append/acknowledgement. This was a source-observed limitation for an unsupported row, not demonstrated ordinary-path data loss or a production corruption incident.

That observation remains historical. Plan 210 removes the flat pending representation and its decoder dependency. Compact resolution presence now owns the refusal: malformed or excess compact fields and unavailable/mismatching exact Agent declarations fail preparation without append/acknowledgement.
