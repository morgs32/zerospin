## Historical physical owner and durable fact

One SystemLogRepo was addressed by exact configured systemId. Its only domain table was admissionAttempts; the common migration ledger is separate. A row records a begun authentication/partition-selection attempt and, if acknowledged later, one terminal audit result. This is permanently retained audit history, not resource state, command admission, a session capability, a revocation list, pending work or a recovery checkpoint.

The reviewed owner had no domain read method that makes an authorization or recovery decision. beginAdmissionAttempt inserts; completeAdmissionAttempt conditionally updates one unfinished row. Generic authenticated SystemApi inspection is the retained-data reader. Keeping rows is therefore an investigation/history feature, not a prerequisite used to validate a later request. The reviewed implementation made writing that history a prerequisite by policy, rather than because a business decision needs to read it.

## Historical sequencing, failure priority and retention

1. AggregateApi.admit and ServiceApi.admit validate outer request arguments before their admission procedures run. Each procedure resolves its requested release and Actor before acquiring SystemLogRepo. These early rejections create no audit row. The audit does not cover every rejected access attempt.
2. auditAdmission enters an uninterruptible mask and waits for beginAdmissionAttempt's RPC. Begin inserts an unfinished row in one synchronous SQL statement, before credential decoding/authentication and canonical partition selection. A begin failure prevents authentication from running. A lost begin reply can leave a permanent unfinished row even though authentication never started.
3. The authentication/claims/partition/hash program runs with interruptibility restored. The SQL insertion, asynchronous authored callback, claims hashing, terminal update and capability construction have no shared transaction. Authored authentication effects cannot be rolled back by an audit completion failure.
4. A failure Cause containing interruption bypasses completion and leaves unfinished; the original Cause propagates. For other failures, the orchestrator requires a generic failed completion before rethrowing the original Cause. If the audit completion itself fails, that audit failure takes priority and the original admission failure is not the returned failure.
5. Success also waits for completed audit RPC before returning admission data and constructing AggregateAccessApi or ServiceAccessApi. This is the acknowledged-local-audit guarantee. A successful authentication can therefore fail to produce access solely because audit storage or its reply failed. A lost completion reply may leave a succeeded row while no capability reached the caller.
6. completeAdmissionAttempt performs one atomic UPDATE WHERE attemptId and status unfinished RETURNING. Exactly one row must change. Repeating an identical completed update fails with admission-attempt-not-unfinished; it does not recover an earlier receipt. A new admission creates another ID. No unfinished-attempt recovery, reaper, alarm, acknowledgement cleanup, expiry or deletion path consumes these rows. Both terminal and unfinished history accumulate indefinitely.

Audit succeeded means only that this authentication/partition/hash program returned and its terminal row update was acknowledged. Later session-lock/resource authorization, ticket issuance, socket installation, command admission, execution commit and outcome retention are separate. Rows omit explicit Actor name/version, session/lock identity and trace IDs; failed rows also omit actual failure detail. This is not a complete authorization/security journal to preserve merely because its comments call it mandatory.

## What actually protects access, and what telemetry provides

Authentication policy/credential validation, authored authentication, complete typed/encoded claims validation, Aggregate-ID agreement, exact Actor identity and makeActorSelection's reversible canonical path checks enforce admission independently of this table. Subsequent session authorization validates the selected declaration lock and resource access. None of those decisions consults a retained admissionAttempts row. Removing audit storage does not require removing any of those checks or changing command/projection/history ownership.

Existing rpcMethod capture surrounds request decoding and the complete domain Exit, then performs optional source-owned export before constructing the success/failure capability. admitAggregate/admitService already have named spans; normal tracing retains timing, identity arguments, bounded argument/result snapshots and failure Cause information. Preserve those spans and normal capture ownership. No new audit-event protocol or wholesale full-claims export is required to retire SQL auditing.

WorkerTelemetryLive may be disabled or sampled. Its export path bounds delivery and contains delivery failures; abrupt process loss can also prevent export. Hosted provider arrival remains separate unfinished work in Plan 143. These are appropriate diagnostic semantics, but they do not replace an acknowledged unsampled local audit. The removal recommendation explicitly chooses to stop making audit persistence a prerequisite to access, instead of pretending external telemetry supplies that guarantee.

## Governing context and bounded removal recommendation

[Plan 143](../../plans/143-plan-optional-effect-telemetry.md#scope-and-constraints) deliberately retained mandatory admission auditing while saying its optionality was a separate unresolved design question. The [reconciled telemetry handoff](../../archive/handoffs/2026-10-12-handoff-optional-cloudflare-telemetry.md#reconciled-direction) records the same scope boundary. Existing architecture/glossary language describes the current implementation; it supplies no additional product consumer for this history. No independent admission-audit requirement was found in governing ADRs.

Recommend a complete owner removal after explicit implementation approval: delete the table, class, begin/complete procedures, auditAdmission wrapper, SystemLogRepos service and all binding/export/Repo-kind/inspection/deployment declarations that exist only for it. Remove audit-only hash/result baggage and systemId acquisition plumbing where no longer consumed, while preserving complete claims, actorPath and canonical selection validation. Keep unrelated Browser claims hashing. Update the old mandatory-audit policy, existing assertion consumers and directly affected docs together. A removal plan should assess whether the retirement decision warrants an ADR; do not record an implemented decision before the implementation exists.

Do not keep the class as an optional empty shell, move audit SQL to SystemRepo, add a fallback table or an audit outbox. There is no business delivery obligation to recover here. The intentional behavior change is removal of local permanent attempt history, unfinished-on-interruption evidence and audit-write failure priority/availability gating. That is the concrete decision for the maintainer, not a claim that optional telemetry is lossless.
