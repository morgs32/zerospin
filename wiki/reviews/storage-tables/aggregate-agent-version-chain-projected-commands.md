# AggregateAgentVersionChain exposed-command history

**Original review:** 2026-10-16 against uncommitted source. The review replaced a flat ten-column projectedCommands table with an intermediate five-public/four-private representation. That private Agent child and its producer/version assumptions are subsequently superseded by Plan 151 and completed Plan 249. The historical inventory below preserves the original review rather than current requirements.

**Current decision:** retain exactly five public exposedCommands fields: aggregateIndex, dispositionChainHash, canonical admitted id, commandName and frozen selected delta. The view is bound to `(systemId, aggregateName, aggregateId, aggregateVersion, agentName)`; the Agent definition is unversioned and pins that exact owner release. Public rows preserve every position, including Failure, no-op and empty selected deltas. Exact duplicate equality, unique command ID, contiguous pages, synchronous commit-before-acknowledgement and commit-before-broadcast remain required.

There is no Agent commandResolution, commandResolutions, private history/cursor, bootstrap/outcome reader or ordinary browser command-submission capability. Observer nodeId binds ticket/resume and is not command producer identity. One fixed Node Repo acknowledgement advances delivery without deleting public history. Source Repo acknowledgement deletes only its complete pending publication; selection exit and socket disposal cannot prune retained Chain history.

## Historical physical owner and retained fact

AggregateAgentVersionChain is bound to `systemId / aggregateId / aggregateName / aggregateVersion / agentName / agentVersion`. There is no actor path or individual Node partition. Activation resolves the exact authored Agent and its Aggregate release. The Chain owns retained selected history and sockets; AggregateAgentVersionRepo owns the resource graph, selection, materialization head and complete pending publication.

One row freezes one source command's public selected transition and optional private producer resolution at its `aggregateIndex`. Every contiguous command occupies a row, including Failure, no-op and commands with empty selected deltas. This is **immutable history**, not resource state, a checkpoint, pending delivery or subscriber progress. Acknowledgement deletes the Agent Repo pending row; it does not delete this history.

## Original ten-column audit

Before Plan 211, the first five columns were non-null and the remaining five were nullable. None had a SQL default. `appendExposedCommands` inserted the complete flat row; supported paths never updated or pruned it. This plain table added no generated ID, timestamp, resource fields or foreign key. SQL did not enforce positive-safe positions, hash format or the coupling between nullable recipient fields; codecs and append supplied richer constraints. The following table preserves the original review and its agreed dispositions.

| Column                  | Meaning, readers and null rule                                                                                                                          | Disposition and removal consequence                                                                                                                                                                                               |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `aggregateIndex`        | Integer primary key identifying the source Aggregate command position. Orders append/replay, bounds private recovery and locates snapshot checkpoint N. | Retain publicly. A Node push count, row count, command ID or owner cannot replace this source position.                                                                                                                           |
| `dispositionChainHash`  | Required text for the ordered command/disposition prefix at this position. Exact historical checkpoint reads consume it.                                | Retain publicly. The materialization head can be newer; public history lacks the Success/Failure tags needed to reconstruct the hash. It represents ordered IDs and decisions, not resource, delta, result or timestamp equality. |
| `id`                    | Required canonical admitted command ID. Public replay, client reconciliation and immutable duplicate comparison retain it unchanged.                    | Retain publicly. Owner, position and command name cannot reconstruct the admitted ID locally.                                                                                                                                     |
| `commandName`           | Required public command name. All Aggregate commands advance this Agent history, including commands from other producers.                               | Retain publicly. The bound Agent, opaque ID and selected delta cannot derive the name. It remains part of the public command and exact retry contract.                                                                            |
| `delta`                 | Required JSON selected transition with `upserted` and `deleted` arrays. Empty arrays are valid; null is not.                                            | Retain publicly. Later resources cannot reproduce the historical transition. Canonical operations would require historical resource/selection replay to reconstruct it.                                                           |
| `failure`               | Nullable complete public refusal for an owned Failure. Null also covers owned Success and commands without an owned resolution.                         | Retain privately as nullable child `failure`. Presence of the private resolution, rather than null failure alone, identifies an owned push.                                                                                       |
| `completionNodeId`      | Nullable originating Node ID, present with the complete owned recipient tuple. Private recovery and recipient filtering use it.                         | Retain privately as required child `nodeId`. Multiple Nodes share this Agent Chain; the owner and session do not derive it.                                                                                                       |
| `completionPushIndex`   | Nullable producer-local submission position. Private recovery must prove a contiguous push prefix.                                                      | Retain privately as required child `pushIndex`. Interleaved Aggregate positions and canonical IDs cannot replace producer order.                                                                                                  |
| `completionSessionName` | Nullable admitted session name, checked during private replay/recovery.                                                                                 | Remove from each row. Agent admission requires the exact frozen Agent declaration's session name; Chain activation already depends on that declaration. Restore that exact value for recipient matching.                          |
| `completionOrigin`      | Nullable Origin JSON. Every supported present value is `{ kind: 'agent', agentName, agentVersion }` matching this physical owner.                       | Remove from each row. All three fields derive from the owner. Agents have no claims to preserve; add no stored claims placeholder.                                                                                                |

The `aggregateIndex` primary key and unique `projectedCommands_id(id)` enforce separate position and canonical-ID invariants. Unique `projectedCommands_completion_node(completionNodeId, completionPushIndex)` prevents two retained resolutions for one producer submission and supports Node/push traversal. Multiple unowned rows with null recipient fields are valid. That index does not enforce recipient null coupling. Preserve both uniqueness guarantees; adding session/Agent identity to Node/push uniqueness would weaken the existing submission invariant.

## Every structured value

### Selected delta

`delta.upserted` and `delta.deleted` are required ordered arrays; both may be empty. Before/after selection comparison freezes their contents. A removal can mean leaving the selection rather than deleting a source resource.

| Nested field                          | Meaning and necessity                                                                                                                                                                                                             |
| ------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `upserted[].id`                       | Required resource ID, distinct from the command ID; identifies the resource to replace.                                                                                                                                           |
| `upserted[].modelName`                | Required model/table identity; associates the resource with the correct selected model.                                                                                                                                           |
| `upserted[].version`                  | Required portable model version. Derivable from the bound release, but retained in the shared complete-resource envelope and codec. Do not introduce a partial Agent-only envelope.                                               |
| `upserted[].createdAt`                | Required encoded creation time, decoded as Date. Preserve the resource's original time.                                                                                                                                           |
| `upserted[].updatedAt`                | Required encoded update time, decoded as Date. A newly selected resource can have an earlier update time; publication time cannot replace it.                                                                                     |
| Authored resource properties          | Application-defined encoded fields, including nullable attributes/references with their declared meanings. Exact selected-model codecs validate them before publication; the generic envelope invents no further fixed subfields. |
| `deleted[].id`, `deleted[].modelName` | Required identity-only removal. No body, model version or timestamp is necessary to remove the selected resource.                                                                                                                 |

Retain these fields and their frozen values. No repeated command context, canonical operation list, `operationIndex`, separate clock or full `outcome` belongs inside this selected delta.

### Private refusal and Origin

A present `failure` requires `_tag: 'ZerospinError'`, `code`, `message`, numeric-or-null `status` and JSON `extra`; `scope` is optional and, when present, is `contract`, `actor` or `aggregate`. JSON null `extra`, null `status` and omitted `scope` are valid and do not indicate Success. Retain the complete refusal for the owned recipient; a code, hash or later declaration cannot recover its original details. “Public” names the error format, not permission to disclose it to another Node.

The former generic `completionOrigin` codec permitted Actor `{ kind, actorName, actorVersion, claims }`, Agent `{ kind, agentName, agentVersion }` and System `{ kind }`. Actor claims are a required record of application-defined values. The former Agent retained decoder rejected Actor/System and mismatching Agent Origins: only the three fixed Agent fields were supported. The replacement model stores none of them per row and derives the same Agent Origin from its owner.

## Commit, acknowledgement, replay and recovery

1. AggregateAgentVersionRepo commits resources, its head and complete pending `exposedCommandOutbox` in one synchronous transaction. Its publication preparation restores the exact Agent session and existing shared recipient context. AggregateVersionChain's subscriber acknowledgement proves that Repo commit; it does not prove Agent Chain publication.
2. AggregateAgentVersionChain checks the exact source key and complete publication, then appends the whole page in one synchronous transaction. Existing positions require exact normalized publication equality. New Aggregate positions must be contiguous; duplicate IDs and Node/push pairs cannot occupy another retained position. Append does not independently prove a contiguous private push prefix: source admission enforces producer continuity, while private recovery detects gaps. A page failure rolls back earlier inserts from that page.
3. Append commits before broadcast and acknowledgement. Socket-send failure cannot undo retained history or the publication receipt. Only a valid successful RPC envelope permits the Agent Repo queue to delete exactly the acknowledged pending indices. A lost reply leaves pending publication for an identical retry; history remains immutable.
4. Browser replay reads Aggregate order and separately covers the requesting Node's private push prefix. Replay/live delivery disclose a refusal only after exact Node, session and full Origin comparison. Public command frames carry the selected public shape and filtered failure, not producer identity, claims, canonical input or operations.
5. A snapshot captures resources/head N together in AggregateAgentVersionRepo, publishes through N and verifies the exact retained position/hash N. `getResolvedThrough` reads only positions at or before N, validates every selected resolution's recipient and requires push indexes `1..resolvedThrough`; it must reject mismatches/gaps rather than filter them away or take a maximum. Agent bootstrap recovers the same bounded immutable outcomes. A newer history tip cannot relabel the captured resource graph.
6. No retained-history update, deletion, pruning, TTL or retirement writer was found. Neither socket delivery, private resolved progress, pending deletion nor source subscriber acknowledgement is a history-deletion condition. Cold reconnect/bootstrap depends on retained rows after the Repo outbox drains.

## Historical intermediate 5+4 replacement

```ts
exposedCommands {
  aggregateIndex;          // primary key
  dispositionChainHash;
  id;                      // unique
  commandName;
  delta;
}

commandResolutions {
  aggregateIndex;          // primary key + foreign key to exposedCommands
  nodeId;                  // required
  pushIndex;               // required
  failure;                 // nullable complete PublicFailure
}
// unique (nodeId, pushIndex)
```

Child absence means no owned resolution. A present child with `failure: null` records owned Success; a present refusal records owned Failure. Successful no-op commands still need their child to advance the originating Node's private prefix. The public row seals that exact child or its absence. Both insert atomically before one acknowledgement, and retries compare both; no separate child insertion, queue, acknowledgement or delivery lifecycle is introduced.

Plan 210's compact pending JSON is appropriate for rows read/deleted only by Aggregate position. Retained history additionally needs indexed Node/push access and uniqueness. A small optional child supplies both through existing relational primitives, allows direct private-prefix reads, and makes Node/push required whenever a resolution exists. It removes the flat nullable tuple without introducing JSON-expression indexes or copying Actor-only session/claims columns. The public five-field shape can use the existing `exposedCommands` representation.

Derive Origin from the immutable Agent owner and session name from that exact frozen authored Agent version. **Validate the incoming publication's session against that declaration before omitting it from storage.** Silently canonicalizing an incompatible recipient would weaken exact publication/duplicate validation. Missing/mismatching declarations must fail; never choose another/latest version or use transient connection state. Retain the existing full publication and browser protocols with locally restored context.

Plan 211 replaces `projectedCommands` with `exposedCommands` and its optional `commandResolutions` child. The Agent Chain retains exposed command history while AggregateAgentVersionRepo performs projection/materialization. The implementation removes the old flat table/decoder, updates Agent consumers and ADR 013, and preserves Actor/Service storage. This child is part of the reviewed table's replacement model, not another completed table review. All Plan 211 verification remains deferred.

## Historical source findings and verification limits

The original retained decoder validated the four recipient fields as all-null or all-present, but independent `failure` was outside that coupling. An unsupported stored row with non-null failure and all four recipient fields null became `commandResolution: null`, silently discarding the refusal. The supported append writer could not emit that combination. This is a stored-row validation gap, not observed ordinary-path loss or a reproduced corruption incident. Plan 210 removed this representation only from pending storage. Plan 211 now removes the flat history representation and decoder; its optional required-producer child removes the orphan-refusal state. That described the intermediate implementation; Plan 151/249 subsequently removed Agent private resolution entirely.

The original Agent `getResolvedThrough` branch read/decoded complete historical public rows, including deltas, only to keep their private resolutions. Plan 211 replaces it with direct child reads while preserving recipient and contiguous-prefix checks. No latency improvement was measured or claimed.
