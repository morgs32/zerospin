## Physical owner and represented fact

One ServiceActorVersionRepo fixes `{ systemId, serviceName, serviceVersion, actorName, actorVersion, actorPath }`. Configuration resolves the exact Service release and actor view before composing resources and projection infrastructure. ServiceActorVersionChain has the matching identity but independently owns permanent selected history and sockets.

One row is one **complete pending selected publication** whose resource transaction has committed and whose receiving Chain retention has not yet been acknowledged locally. It is neither retained command history nor an index-only delivery marker. Supported production freezes the complete row until acknowledgement deletes it. A pending row can remain after ServiceActorVersionChain has committed when its reply or local deletion was lost; exact immutable retry handles that state.

The immutable owner supplies release identity and fixed Actor kind/name/version. These values need no row columns or repeated Origin object. Node/session/full historical claims remain variable private-recipient facts and cannot derive from the owner.

## Every structured value

### Selected delta

`delta` has required `upserted` and `deleted` arrays; neither array is nullable. Both can be empty for a valid publication.

1. `upserted` contains complete selected encoded resources that entered the selected graph or changed. Every resource has required `id`, `modelName`, portable model `version`, original `createdAt`, actual `updatedAt` and application-defined encoded properties permitted by the exact model/exposure codec. Authored property shapes/nullability remain model-defined; there are no further universal framework fields.
2. Resource `id` and `modelName` identify the resource/model, not the publication command or projection owner. Explicit `version` is derivable from the bound release but belongs to the shared complete-resource envelope; removing it would introduce another partial representation.
3. Resource timestamps preserve actual resource history. A resource entering selection may have been created/updated by an older command, so replacing its timestamps with the current command's `outcome.finalizedAt` would be wrong. There is no separate publication/execution timestamp column to add.
4. `deleted` contains only `{ modelName, id }` references for resources that left the selected graph. This can mean leaving a selection rather than deletion from canonical SQL. No resource body, version or timestamp is needed for that removal identity.

The delta is computed while the before/after selected graphs are available in the transaction. Pending delivery must not recompute it from a newer graph. An empty delta still preserves Service ordering and can carry an owned private resolution.

### Private command resolution and refusal

`commandResolution === null` means this publication owns no private producer resolution; it does **not** mean the source command succeeded. A present resolution has exactly:

1. Required nonempty `nodeId`: producing Node identity, independently variable within the actor partition.
2. Required positive safe-integer `pushIndex`: that Node's admitted command-stream position, used for contiguous private recovery. It is not the global `serviceIndex`.
3. Required nonempty `sessionName`: exact admitted session definition; actor identity or Node alone cannot determine it.
4. Required `claims`: complete original encoded application-defined claims record. Actor path contains the partition identity fields, not every original claim. Preserve all claims for exact historical recipient equality; do not replace them with path-only or empty claims.
5. Required nullable `failure`: public refusal, or null for an owned Success, including no-op Success. This null belongs inside a present owned resolution; it is distinct from absence of the entire resolution.

A non-null public failure contains required `_tag: 'ZerospinError'`, `code`, `message`, nullable numeric `status`, required JSON `extra`, and optional `scope` (`contract`, `actor`, `aggregate`). JSON null is valid `extra`; absent scope is valid. Preserve the complete public refusal, not just its code/tag. No runtime exception, Success result, full `outcome`, original payload or outcome timestamp is stored in this selected publication.

The producer recognizes ownership using Actor kind/name/version, a complete producer tuple and equality of canonical encoded partition fields in Origin claims. It then preserves the **full** original claims. Later private disclosure/recovery proves exact actor/version, Node, session and complete claims equality. Fixed Actor Origin fields derive from the bound receiving owner and are reconstructed only where needed; they do not need to be repeated inside pending resolution.

## Commit, delivery, deletion and retry

1. ServiceActorVersionRepo acquires `exposedCommandOutbox.producerLease` before incoming projection application and explicitly runs `exposedCommandOutbox.wake()` on exit. The lease holds durable recovery before producer work and performs only producer bookkeeping on release. One synchronous page transaction validates complete source output, contiguous positions/hash, applies model mutations, computes selected deltas and inserts each complete pending publication with the resource head. A later page failure rolls back every new resource/head/outbox write in that page.
2. Every new source position produces a publication, including Failure, no-op Success and unchanged selected graphs. Already materialized positions skip all resource/outbox/head writes. The source fanout receipt therefore proves local resource/head/pending-publication commit; it does not prove ServiceActorVersionChain retention.
3. After producer completion, queue wake starts delivery without awaiting selected-history acknowledgement. Producer count/revision and durable alarms prevent a concurrent drain from releasing a newer producer's recovery. Failures retain recovery without a persisted retry counter, suspension mode or replacement message body.
4. Delivery reads at most 64 complete rows in ascending `serviceIndex`, optionally through a requested snapshot boundary. Preparation decodes stored publication values, then acquires ServiceActorVersionChain using this exact projection key and sends the full source key plus complete publications. It performs no contract evaluation or past-graph reconstruction.
5. `appendExposedCommands` checks exact source-owner equality, publication schema, contiguous new positions and immutable duplicates. Its synchronous transaction retains the public command and optional private resolution together. A duplicate compares the public row plus exact resolution-or-null; absence is sealed and cannot be filled later. Changed private metadata or public output conflicts.
6. One successful decoded receiver envelope acknowledges that complete publication. Only then does the outbox transaction delete the exact delivered indices. Newer concurrently produced rows are not included. Lost replies, interruption, receiver conflict, decode failure or local deletion failure leave complete pending rows for exact retry.
7. Broadcast follows durable Chain retention. Browser/socket delivery is a separate fact and cannot undo projection resources or retained selected history. Public client commands contain selected output and recipient-filtered failure; raw claims/producer metadata do not become an unfiltered browser publication.

**Deletion condition:** durable acknowledgement from the exact ServiceActorVersionChain for the complete publication, followed by local exact-index deletion. There is no TTL, diagnostic-retention or idle deletion policy. Pending rows are not kept as permanent history; the head and receiving Chain history survive their deletion.

## Snapshot publication and complete-message requirement

Snapshot capture reads selected resources and actual head N in one local transaction. Outside SQL it drains this outbox through N, compares the exact receiving Chain checkpoint/hash at N and obtains private resolution progress bounded through N. A newer resource graph, source acknowledgement or Chain tip cannot replace the frozen pending transitions needed to publish that captured prefix.

A marker/pointer would discard the selected before/after transition and private recipient facts. ServiceVersionChain retains complete source output, not this actor's already computed selected publication; reconstruction would require historical state/replay and another coordination path. The local head may be newer, and pending rows may contain earlier distinct hashes/deltas. Keep complete pending messages until their own receiving acknowledgement, while retaining no permanent selected history in this resource-owning Repo.
