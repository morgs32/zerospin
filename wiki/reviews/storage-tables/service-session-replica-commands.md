## Physical scope and row fact

[openServiceReplica](../../../packages/browser/src/sessionReplica/openServiceReplica.ts) creates one in-memory SQLite client per acquired Service session lifetime and closes it with that Effect Scope. It composes selected Service models with the fixed session tables. The persistent ServiceNode journal is a separate owner and is not this database. The current mock Service replica supports validation but its command binding rejects staging before persistence; no supported Native or standalone Service staging path was found among these production consumers.

One row retains a **local staged-input record or received selected final record**, each with its own local sessionIndex. Successful local staging retains original encoded input/result and later acquires the original Node record's coordinates. A selected final retains canonical command ID/name, selected authoritative changes, nullable private failure and exact Service position/hash at a separate local position. A final counterpart settles matching optimism by ID without deleting the original row. Canonical `outcome: { result, finalizedAt }` remains in its owning Chain history, not inferred from the browser's nullable failure.

This is local phase-record state/history, not a dedicated pending-delivery row. Eligibility for handoff and replay is a query over original rows without a final counterpart. Node retention acknowledgement, ServiceChain admission, ServiceVersionRepo finalization and observation of selected final output remain different facts. No delivery acknowledgement owns deletion of these rows.

## Every column and constraint

There are no declared defaults, added owner/ID/timestamp columns, foreign keys, TTL or delivery-status fields. A nullable input is not permission to submit an incomplete original: the staging/import/handoff codecs require complete original input. Final rows deliberately omit it.

## Structured members and actual undo needs

1. **claims:** an open string-keyed record of encoded values. The release claims codec owns the full representation; the selected contract's claims codec owns its invocation input. Those transforms and validation remain needed after storage normalization. Bind the canonical encoded authenticated record, then decode through the same release/contract preparation when replaying. Object equality against raw decoded claims is not a substitute for encoded-wire equality.
2. **staging.result:** original encoded JSON contract return value, including valid JSON null. The public staging return substitutes its decoded result. Retention preserves the original local observation/inspection and retry value; it is not a replay or canonical-completion verdict. Rebase must not rewrite it merely because a later speculative evaluation differs.
3. **staging.startedAt and completedAt:** two Date/string samples. Initial local writes and replay currently use startedAt; completedAt has no independent reconciliation reader. Retain one logical completedAt and use it consistently for initial local writes and replay. This is a successful staging timestamp, not canonical outcome.finalizedAt.
4. **staging.stagedDelta:** inserted and updated arrays use full encoded resources; deleted uses `{ id, modelName }`; operations uses complete encoded applied operations. The actual Service evaluator produces **all four arrays empty**. None drives local replay/undo, which uses the separate current inverse bookkeeping. Their appearance in whole-object retry equality, transport and generic Devtools display does not create a domain requirement to keep them.
5. **Applied-operation members allowed by that schema:** commandId, operationIndex, modelName, modelVersion, resourceId, operationName, encoded body, appliedAt, nullable previousUpdatedAt and encoded inverseOperation. Create bodies contain complete attributes, update contains an attribute patch, delete has an empty body, and move contains property/prevId/nextId. Inverses are null for create, null-or-attribute-patch for update, null-or-deleted-resource for delete and null-or-property/prior-value for move. These declared members can arrive through the Node codec even though the ordinary Service staging producer emits no stagedDelta operations. A compact staging protocol would deliberately remove those unused evidence fields from exact input comparison, not preserve an old-format decoder.
6. **Current inverseOperations proposal:** retain only exact model/resource identity, operation kind, prior attribute/property values or full deleted resource, and prior updatedAt where needed. Undo must restore created/deleted resources and timestamps under reference constraints in reverse command/operation order. Complete forward bodies, command ID, authored operationIndex and appliedAt need not be copied into current undo data. The model codecs own the inverse body; the Aggregate compact inverse implementation illustrates those same operation semantics without proving Service integration. A shared implementation need not introduce a second Service-only inverse concept.
7. **failure:** `_tag: 'ZerospinError'`, code, optional scope (`contract`, `actor`, `aggregate`), message, nullable numeric status and arbitrary JSON extra. Keep the complete selected refusal. Its absence can hide another recipient's Failure, so no new public outcome union can be inferred from it.
8. **exposedDelta proposal/current actorDelta:** upserted full encoded resources contain id, modelName, version, createdAt, updatedAt and the model's authored properties; deleted entries contain id and modelName. Open resource properties remain owned by exact model codecs. Keep empty arrays and nullable failure independently: a final can settle the original and advance Service continuity with neither exposed resource change nor visible refusal.

## Bound claims are a Service invariant; payload version is not

The current initialized Service command binding captures the exact replica capability and refuses a foreign contract object before evaluation. It supplies only that capability's admitted claims. ServiceNode's complete identity contains API/System/Service/release/Actor/session context, full claims and declaration hash. Original admission rejects any of the four repeated names or canonical full claims that differs from that identity. Browser reconnect refuses a changed identity key, and ServiceNode reauthentication requires the same complete key.

The claims column therefore repeats an established invariant for this replica, rather than preserving another tab's distinct invocation authority. The Service mock cannot stage, and no Service counterpart of Aggregate standalone's cross-claims Node exists in the reviewed production paths. Derivation must use frozen exact **authenticated encoded claims**, not a new credentials-provider result or mutable decoded UI values. Pass the bound context into import/replay/handoff, validate each complete incoming original against it before dropping columns or rewinding resources, and reconstruct complete ServiceNode input with all names/full claims. Server original/admitted history and private refusal ownership retain their existing full authority data.

By contrast, SDK staging's use of current contract.version does not establish an ingress invariant. ServiceNodeCommandInputSchema accepts contractVersion as a string, the supported subscriber decodes that schema, and Node admission validates identity without requiring the lock-selected contract version. Replay actually interprets the retained source version through previous/next payload adaptation. Dropping that field would need a separate decision to restrict accepted versions or normalize payloads, not just column derivation. This review recommends retaining it.

## Why retain two phase rows

No production local reader needs a chronological two-row display as an ordering authority. An old ADR or a generic claim to preserve history is not enough to justify this representation. The concrete responsibility is **two independently retained Node record coordinates** for the same canonical command: original acceptance and selected final delivery.

For example, local staging may receive its final at nodeIndex 9, then receive a delayed original acceptance at nodeIndex 4. A single merged nodeIndex either rejects valid evidence or overwrites the final coordinate and loses exact final retry/collision checks. Snapshot reconciliation also distinguishes durably acknowledged original input from its optional final, including captured coordinate bounds and refusal to report acknowledged originals missing.

A merged canonical-ID row is possible, but would need separate original/final Node coordinates, cross-phase collision checks, input enrichment after final-first delivery without reopening handoff, and snapshot reconciliation based on original evidence instead of serviceIndex-null phase. Retaining the two current phase rows directly represents those independent facts without introducing that alternative structure. This finding recommends keeping them and their indexes, not treating them as unchangeable architecture.

## Transactions, retry, recovery and exact retention

1. Local staging requires current initialized metadata/capability, evaluates guards/program/result once under the synchronous savepoint, applies model operations and captures undo. Command retention, inverse bookkeeping, resource writes, allocator advancement and final capability fence share one transaction. Local refusal/suspension/defect/resource failure retains no successful command or partial write. Validation uses the same evaluation with rollback always and retains none of those facts.
2. Handoff selects original rows with no final counterpart and, for submission, no Node coordinates. The runtime registers the locally originating command for failure observation; imported Node staging does not become another uncertain handoff. A first receipt enriches original coordinates in place without changing immutable input/result/position. Lost replies retry the same full command ID/input and recover already retained Node original/final records.
3. Ordered import validates Node page bounds and exact current-transaction identity/coordinates. It rewinds current optimism lazily once before the first change, retains original/final facts, applies newly contiguous selected final changes, advances the Service checkpoint, and replays surviving originals in Node order followed by uncertain local order. Records, resources, current undo state, allocator/checkpoints and afterNodeIndex commit together before publication/acknowledgement. Exact duplicate pages allocate/apply nothing; conflicts abort.
4. Rebase re-evaluates original payload/source version under the submitting bound claims. Current inverses must be regenerated from that new baseline. Expected business/dependency replay refusals leave no applied changes for that original while keeping its original local result/input; defects and compound Causes retain their failure semantics. This is not a canonical Failure or an excuse to delete original input.
5. Selected final receipt settles staging by canonical ID, including empty delta and null failure. Privacy filtering owns refusal disclosure separately from completion. Covered final recovery retains evidence/settles staging without applying an old delta over newer resources; ahead point recovery defers until ordered history provides continuity. Direct receipts do not advance the stream cursor.
6. Ordinary snapshots preserve command rows and their positions, replace resource/current-undo state, retain captured original/optional-final receipts and unresolved originals, then replay surviving pending input. Requested receipt/missing partitions and Node capture coordinates must agree; acknowledged original input cannot simply disappear. Explicit announced DEV reset clears commands and metadata together while installing the replacement projection.
7. Ordinary Node acknowledgement, final receipt, pending handoff drain, snapshot replacement and canonical completion do not delete command rows. Browser Scope disposal releases the entire in-memory database. There is no per-command TTL, acknowledgement pruning or deployment-time command cleanup here. Persistent ServiceNode retention is separate and unchanged by this finding.

## Original reviewer reconciliation and verification limits

All three source reviewers support the thirteen-column model. The column/lifecycle reviewers initially treated claims as original replay input; the context review proves that, unlike Aggregate standalone, Service already fixes identical full claims across one Node/replica lifetime. Reconciliation removes the redundant row copy only with explicit bound encoded/decoded context and pre-mutation mismatch checks. contractVersion stays because the accepted protocol still permits a source version distinct from the selected declaration.

The lifecycle deletion test also challenges phase history directly. Its concrete coordinate/recovery responsibilities justify keeping both phase records for this cleanup; ADR wording does not settle that choice. The current empty stagedDelta and unused completion sample provide direct evidence for compact stagingOutcome. Rebase's changing baseline proves why mutable current inverses belong separately from the original local result. The sibling optimism table can be eliminated by an approved coordinated command-row implementation, but its own review status is not advanced here. Metadata allocator/identity cleanup remains a separate table review.

No ordinary-path runtime failure was reproduced. These are storage/consumer simplifications with identified binding, privacy, ordering and undo requirements. Current Aggregate implementation is context, not automatic Service approval or passing verification.

## Approved implementation — written, unverified

Both phase rows and all four unique indexes remain. The replica no longer copies bound Service/Actor/session names, full encoded claims or Node-owned pushIndex. The eight-field serviceSessionMetadata declaration and allocator remain for their own review.

The browser retains a private complete authenticated identity across reset and capability withdrawal. Public initialized claims cannot replace that authority: handoff receives a deep clone of the private encoded claims, and staging/validation decode claims from that binding. Import, replay and snapshot initialization receive explicit encodedClaims. Full incoming original names/claims must match before rewind or resource replacement. Complete ServiceNode input is reconstructed from bound names/claims and retained canonical id, commandName, payload, source contractVersion and stagingOutcome. ServiceNode/admitted history keeps full original authority and the real producer submission position.

Exposed selected changes use exposedDelta locally and delta on transport. The physical Service optimisticAppliedOperations table, stagedDelta and old two-time staging envelope are removed.
