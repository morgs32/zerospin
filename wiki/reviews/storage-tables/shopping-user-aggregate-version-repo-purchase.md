Derive modelName='purchase' and version=1 from the exact bound model instead of repeating them in every SQL row. Preserve both fields in complete resource values and portable output. This requires coordinated generic storage/read/write/query reconstruction; it is not safe to delete fields from PurchaseV1's public model shape alone. No implementation is approved or performed in this review, and other model owners are not implicitly changed.

## Why the table exists

[Shopping's System](../../../examples/shopping/src/zerospin/system.ts#L8-L15) registers the user Aggregate release at 1.0.0. [userAggregateReleaseV1](../../../examples/shopping/src/zerospin/aggregates/user/userAggregateReleaseV1.ts#L18-L28) includes purchaseV1 among its authored models. [PurchaseV1](../../../examples/shopping/src/zerospin/aggregates/user/models/purchase/PurchaseV1.ts#L2-L35) declares model purchase, ID abbreviation pur and model version 1.0.0.

The physical database belongs to the AggregateVersionRepo key `(systemId, aggregateName='user', aggregateId, aggregateVersion=1)`. AggregateVersionRepo resolves that exact configured release, then calls makeResourceDbConfig with its models and Repo metadata tables. Model table composition uses each model.table; it has no branch that knows Shopping or purchase. [Bound release composition](../../../packages/system-worker/src/AggregateVersionRepo/AggregateVersionRepo.ts#L61-L87), [fixed Repo tables](../../../packages/system-worker/src/AggregateVersionRepo/aggregateVersionRepoDbConfig.ts#L6-L23), [generic resource-table composition](../../../packages/core/src/drizzle/make/makeDbConfig/makeDbConfig.ts#L29-L44).

One row represents the current Purchase business entity: its quoted amount, payment decision/evidence, label state and latest tracking state. It is resource state, not an admitted command, retained execution, event/audit log, subscriber cursor or complete pending delivery. Payment/fulfillment continuations must read and mutate this state after pending request/publication rows have fulfilled their delivery responsibilities. Eliminating purchase would require moving this business authority to another resource owner or reconstructing it from retained history on each read; the ownership cutovers did not remove materialized resources from AggregateVersionRepo.

## Every current column and constraint

makeModelVersion synthesizes id/modelName/createdAt/updatedAt/version alongside ten authored attributes: fifteen physical columns. Six authored columns are nullable; the other nine columns are required. id is the generated pur-prefixed resource primary key. Purchase declares no additional indexes, unique attributes, outgoing references, TTL or defaults. Other models' references to Purchase do not add a new identity field to this row. Enum membership and business-transition invariants belong to the declared codecs/programs; primary-key uniqueness alone does not prove a valid payment/label/refresh state. [Authored attributes](../../../examples/shopping/src/zerospin/aggregates/user/models/purchase/PurchaseV1.ts#L6-L35), [framework fields](../../../packages/core/src/models/make/makeModelVersion.ts#L325-L338).

## Writers, readers, transactions and retention

1. Checkout reads the current cart and rejects locked/invalid quantities or a reused purchase ID. It creates Purchase with null total/evidence, preparing payment, no label, refresh sequence zero and no pending refresh; it also creates frozen line quantities and the cart linkage. [Checkout](../../../examples/shopping/src/zerospin/aggregates/user/contracts/checkoutV1.ts#L42-L118).
2. Quote continuation checks the current preparing purchase, cart linkage and exact frozen line identities. Invalid/unavailable quote marks refused. Valid quote proves item/price/quantity/total consistency, freezes prices and total, marks pending and emits the payment request with stable purchase-bound key. [Quote application](../../../examples/shopping/src/zerospin/aggregates/user/contracts/getExternalPurchaseQuoteV1.ts#L76-L164).
3. Payment continuation checks current pending state, quoted amount, stable key and frozen cart/line correspondence. Unknown external result marks needs_reconciliation; valid evidence installs paid/declined plus reference/evidence. Paid deletes cart items, not Purchase. [Payment application](../../../examples/shopping/src/zerospin/aggregates/user/contracts/processExternalPaymentV1.ts#L41-L105).
4. Label creation requires paid state, payment reference and proof, then reserves requested. Continuation validates the still-requested purchase and provider key, storing label reference/tracking data or needs_reconciliation. [Label reservation](../../../examples/shopping/src/zerospin/aggregates/user/contracts/createTrackingLabelV1.ts#L26-L52), [label observation](../../../examples/shopping/src/zerospin/aggregates/user/contracts/createExternalTrackingLabelV1.ts#L30-L69).
5. Tracking request requires paid/ready/current label, coalesces an outstanding reservation, or increments sequence and marks pending. Continuation requires the same label/sequence and matching response identity before changing status or clearing pending. [Refresh reservation](../../../examples/shopping/src/zerospin/aggregates/user/contracts/updateTrackingInfoV1.ts#L40-L79), [matching observation](../../../examples/shopping/src/zerospin/aggregates/user/contracts/refreshExternalTrackingInfoV1.ts#L35-L76).
6. AggregateVersionRepo evaluates/applies operations under the command savepoint and enclosing materialization transaction. Resource mutations, materializationHead and complete pending evaluated-command publication commit together; refused business execution rolls resource changes back before retaining its outcome. Keep network/provider work outside the synchronous resource transaction. [Materialization orchestration](../../../packages/system-worker/src/AggregateVersionRepo/materializeCommandTx.ts#L33-L43), [execution savepoint](../../../packages/system-worker/src/AggregateVersionRepo/utils/executeAggregateCommandTx.ts#L43-L79), [resource operation application](../../../packages/system-worker/src/AggregateVersionRepo/utils/applyAggregateOperationsTx.ts#L35-L48), [checkpoint/publication retention](../../../packages/system-worker/src/AggregateVersionRepo/utils/retainEvaluatedCommandTx.ts#L16-L40).
7. Source business programs query Purchase directly; actor selections expose current resource values; the paid-Purchase Agent selection and checkout query rendering consume its state. These are dependencies, not completed reviews of those owners' storage. [Actor selection](../../../examples/shopping/src/zerospin/aggregates/user/actors/userActorV1.ts#L27-L34), [purchase selection](../../../examples/shopping/src/zerospin/aggregates/user/actors/userActorV1.ts#L66-L71), [Agent selection](../../../examples/shopping/src/zerospin/agents/purchasesAgentRelease.ts#L24-L28), [current committed source query](../../../packages/system-worker/src/AggregateVersionRepo/executeAggregateQuery/executeAggregateQuery.ts#L31-L58).
8. No authored Purchase delete operation, expiry or acknowledgement-based pruning path was found. Paid, declined and refused purchases remain business entities; completion does not convert their rows into framework command history. A publication acknowledgement deletes only complete pending publication; AggregateVersionChain retains evaluated-command history separately. Replay suppresses external re-emission while applying declared model operations. [Replay preparation](../../../packages/system-worker/src/AggregateVersionRepo/utils/prepareAggregateOutput.ts#L25-L44). This finding proposes no new retention policy.

## Bound model identity and coordinated simplification

Both modelName and version are constants derivable from the exact accepted model in this owner. Their appearance in the complete portable resource envelope does not by itself require storing them in each SQL row. Retaining Purchase is necessary; retaining all fifteen independent physical values is not established.

Current generic code couples physical rows to complete resources: makeModelVersion builds one properties/table shape, create operations write modelName/version, resource readers select that physical shape, encodeResource requires and checks both, and query compilation uses the bound model declarations. A proper follow-up must distinguish stored properties from reconstructed complete resources, adapt writes/reads/query layouts and preserve exact incoming operation/model identity/version validation. [Resource create](../../../packages/core/src/contracts/applyOperationTx.ts#L149-L165), [complete resource encoding](../../../packages/core/src/models/encodeResource.ts#L10-L54), [source query compilation](../../../packages/system-worker/src/AggregateVersionRepo/executeAggregateQuery/executeAggregateQuery.ts#L40-L58).

Do not remove public model identity fields, silently change selection/protocol shapes or apply a Purchase-only decoder workaround. The raw per-row identity-consistency comparison would disappear deliberately; the bound model/owner supplies the reconstructed identity, with strict identity checks retained at operation/resource boundaries. Any implementation must explicitly scope the generic changes and other owner schemas instead of treating this one occurrence as automatic approval for all model tables. Fixed-schema changes require empty affected storage, with no compatibility migration or reset authorized by this review.

## Reviewer reconciliation and limits

Both independent reviewers retain the table and its ten authored attributes. Both distinguish quoted total's deliberate business denormalization from constant model metadata, and tracking reservation state from delivery bookkeeping. Both identify modelName/version as derivable within this exact owner; the proposed thirteen-column representation requires coordinated generic resource/storage work. No ordinary supported-path lifecycle defect was established. Old ADRs and the existing complete-row codec explain current code without making redundant SQL identity necessary.
