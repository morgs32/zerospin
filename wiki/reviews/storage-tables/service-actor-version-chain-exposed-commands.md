## Physical owner and represented fact

One ServiceActorVersionChain fixes `{ systemId, serviceName, serviceVersion, actorName, actorVersion, actorPath }`. Configuration resolves the exact Service release and validates the authored actor/version/canonical path before returning its fixed history schema. ServiceActorVersionRepo separately owns resources, its materialization checkpoint and complete pending selected publication.

One row is the **permanent immutable public selected command** at one admitted Service position for this exact actor view. It records a historical selected transition, including an empty transition, rather than a current resource view. Embedded resource values are immutable transition contents; this Chain does not compose application resource models or perform projection evaluation.

Public selected history remains scoped to the actor partition. Session reads/broadcasts still filter admitted models and private refusal ownership. Private Node/session/claims/refusal facts live in the optional `commandResolutions` relation, whose separate column-purpose review is next. Owner identity supplies fixed actor/release context and needs no repeated public columns.

## Every column, constraint and consumer

All five columns are required/non-null, with no explicit SQL defaults. `serviceIndex` is the integer primary key; `id` is unique `cmd`-branded text. The `foreignKey` primitive provides typed identity without declaring a SQL foreign key or cross-Durable-Object relationship. No additional declared indexes, synthetic IDs, timestamps, status, current-resource or private-recipient columns are introduced.

`appendExposedCommands` is the sole insertion writer. There is no supported UPDATE, DELETE, pruning or expiry path. Readers include immutable duplicate comparison, exact checkpoint lookup, ordered browser replay and private recovery's public-history join. Socket replay and captured-N snapshot comparison consume those readers.

| Column                 | Meaning and actual consumers                                                                                                                                                                | Necessity and removal consequence                                                                                                                                                                                                  |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `serviceIndex`         | Exact admitted Service position, preserved by selected materialization. Append enforces contiguous new positions; pages, private joins, resume/checkpoint reads and snapshots use it.       | Retain. Failure/no-op/empty selected transitions still occupy positions. Removing it loses ordered contiguous history and exact historical bounds. It cannot be replaced by a Node push sequence or opaque command ID.             |
| `dispositionChainHash` | Frozen Service disposition prefix at this published position. Exact checkpoint, resume and snapshot readers compare it; replay advances the retained prefix.                                | Retain. The source/hash at an older published position cannot be replaced by the latest local materialization head or Chain tip. It anchors the particular ordered command/disposition prefix, not the selected resource contents. |
| `id`                   | Canonical admitted command ID copied from parent Service output `commandId`. Unique across this history; retained in public commands and full retry equality.                               | Retain. Position, name and owner do not encode canonical identity. Removing it loses command reconciliation/identity and permits a weaker publication contract. It is not a newly allocated projection ID.                         |
| `commandName`          | Public admitted command name, retained with each selected transition and compared on retry.                                                                                                 | Retain. Neither opaque ID nor delta/owner can derive it locally. Resource application uses the delta, but command naming remains a distinct part of the public history/reconciliation contract.                                    |
| `delta`                | Required typed JSON frozen selected transition with `upserted` and `deleted` arrays. Browser replay, reconnect and private recovery's joined public command use it. Empty arrays are valid. | Retain. Current resources and raw source operations cannot directly recover an earlier actor selection transition. Removing it requires historical graph/selection replay and loses the exact published value.                     |

The PK and canonical-ID unique constraint enforce different associations; command name is not unique. Positive safe positions, hash format and structured output meaning are validated by publication/wire codecs and append logic rather than SQL CHECK constraints. No constraint/index change is justified by this review.

## Every structured delta value

`delta.upserted` and `delta.deleted` are required arrays, never nullable containers. The producer compares the actor's selected graph before and after each source command, including selection changes caused by related resources.

| Structured field                      | Meaning, null semantics and storage challenge                                                                                                                                                                                                                                              |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `upserted[].id`                       | Required identity of the resource entering/changing in this selected graph. It is distinct from the parent admitted command's `id`; replay needs the exact resource to replace.                                                                                                            |
| `upserted[].modelName`                | Required model association for a mixed-model delta, codec selection and session model filtering. Retain it rather than inventing ID-prefix routing.                                                                                                                                        |
| `upserted[].version`                  | Required portable model version in the shared complete-resource envelope. It is derivable from the bound release's model definition, but retaining the common envelope avoids a second partial history/resource codec and reconstruction path. This is a deliberate representation choice. |
| `upserted[].createdAt`                | Required original resource creation time. Selection entry can expose a resource created before this command; command finalization time cannot generally replace it.                                                                                                                        |
| `upserted[].updatedAt`                | Required actual historical resource update time. An unchanged older resource can newly enter the selected graph, so this also need not equal the current command's `outcome.finalizedAt`.                                                                                                  |
| Remaining selected properties         | Frozen application-defined encoded resource values permitted by the exact exposed model. Attribute keys/nullability are authored, not extra universal table fields. Preserve legitimate attribute nulls and the historical values.                                                         |
| `deleted[].modelName`, `deleted[].id` | Required identity-only reference for leaving the selected graph. A selection exit need not be canonical SQL deletion. No previous body, version or timestamps are needed for this removal.                                                                                                 |

There is no top-level model version, repeated owner, `executionStartedAt` or `finalizedAt` to remove. Source/projection resource writes share retained `outcome.finalizedAt`; this selected history already carries the resulting resource times inside delta. It retains no Success result, full source `outcome`, admitted payload, Origin, source operation array or external description.

### Hash meaning and validation ownership

`dispositionChainHash` extends SHA-256 over `[previousHash, serviceIndex, commandId, outcome.result._tag]`. It excludes result/refusal details, timestamps, model operations, selected delta and claims. Equal hashes do not prove equal exposed commands/resources, so full publication equality is independently required on retry.

ServiceVersionChain validates its complete output/prefix, and ServiceActorVersionRepo recomputes the rolling prefix while applying new source output. ServiceActorVersionChain validates publication/wire shape, contiguous new positions and exact public/private retry equality; it does not independently recompute the rolling hash from these five public fields, which omit source disposition for every position. No additional hash-validation change is proposed. AggregateVersionChain's separately deferred question remains outside this finding.

## Commit, acknowledgement, retries and permanent retention

1. ServiceActorVersionRepo atomically commits resources, materialization head and each complete pending selected publication. Every new source position is represented, including Failure, no-op Success and empty selected deltas. A later failure rolls back new writes for the whole projection page.
2. The same-key outbox sends the frozen complete publication and source key to this Chain. `appendExposedCommands` compares the full six-part bound key with `sourceKey` before processing. This is internal source/owner consistency, not a substitute for external session authorization.
3. One synchronous append transaction strict-decodes each complete publication, validates its public wire command, requires the next position and inserts the public row plus optional private child. Public insertion seals the exact resolution **or its absence**. A later row failure rolls back the page's new history writes.
4. A previously retained position compares the entire public row and reconstructed private resolution-or-null. Changed public values, changed private metadata, later attachment/removal of a resolution or conflicting canonical ID fail. Exact retries insert nothing and do not rebroadcast prior commands.
5. The class broadcasts after transaction commit. Individual lock-validation/privacy/send failures are isolated per socket and close the failing connection; they cannot roll back history. A successful publication envelope proves retained Chain commitment, not browser consumption.
6. Only that decoded successful envelope permits the producer queue to delete exact pending outbox indices. A lost reply or failed local deletion retains complete pending work for exact retry. Neither acknowledgement nor pending-row deletion deletes this history.

**Deletion condition:** none in the supported lifecycle. Retain exposed commands for the lifetime of this exact physical Chain. Publication acknowledgement, source subscriber progress, socket closure, inactivity and a resource leaving selection do not prune history. There is no TTL, acknowledgement-floor or release-retirement cleanup policy here.

## Historical reads, snapshots and privacy

`getCheckpoint` reads the exact requested historical position/hash, or the current tip when omitted. Zero has a separate Service genesis result; an unavailable explicit nonzero position fails. Snapshot capture in ServiceActorVersionRepo reads resources/head N together, publishes through N and compares exactly N's retained index/hash before private recovery bounded through N. A newer tip cannot relabel those captured resources; retaining only the latest public row would break this contract.

Browser replay reads at most 64 ascending rows after its exclusive cursor and through an inclusive bound, checking contiguous Service positions. It joins private resolution internally to reconstruct a client command. The public wire command has nullable `failure`; this physical public table has no failure/claims/Node/session fields. Disclosure requires exact Actor/version, Node, session and full claims ownership; otherwise refusal is redacted. Null wire failure alone does not establish source Success. Admitted model filtering still applies to both resource upserts and exits.

Private recovery independently proves the caller's complete contiguous push prefix through its captured Service bound before joining the public selected command. That dependency explains the public history join; it does not complete the next table's private-column review.

Socket resume verifies its retained index/hash, replays bounded segments and performs the final durable tip read, remaining sends, checkpoint comparison and transition to `phase: 'live'` in one synchronous turn. Permanent local history supports reconnect after socket failure or cold activation. Reconstructing from ServiceVersionChain would require historical actor selection replay at another owner rather than reading this already published transition.
