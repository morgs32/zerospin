# AggregateVersionChain.agentVersionChainFanout

**Reviewed:** 2026-10-15, against current working-tree source after completed [Plan 202](../../archive/plans/202-plan-aggregate-version-chain-commands-and-actor-fanout.md). Exactly this physical payload table was reviewed. Agent-specific receiving, bootstrap and subscriber paths were read as dependencies.

**Verdict: simplify — remove the redundant physical payload table.** The logical `agentVersionChainFanout` queue can deliver the same complete evaluated commands directly from permanent `AggregateVersionChain.commands`. Keep agent subscriber cursors, source-bound capabilities, fixed-tip paging, producer leases and alarms. No pointer or replacement payload table is needed.

**Decision status:** Approved in [Plan 203](../../archive/plans/203-plan-aggregate-version-chain-agent-fanout.md); implementation and required verification passed on 2026-10-15 (nine scoped tasks, 27 Workerd tests and thirteen contract acceptance groups). Plan 202 deliberately changed only actor payload storage; this separate agent review found no agent-specific need for a second copy. No delivery-loss defect was found in the former acknowledgement/pruning lifecycle.

**Review queue:** [Plan 151](../../plans/151-plan-storage-table-review.md). Full evaluated-command fields remain governed by [Plan 200](../../archive/plans/200-plan-aggregate-operation-context.md).

## Historical pre-cutover scope, row meaning and ownership

The physical-table evidence through the structured-values section records the reviewed snapshot before Plan 203. It is retained as historical reasoning, not a description of the current schema. Source links identify the owning files; removed insert/prune/backfill implementations no longer exist there. The current implementation is recorded separately below.

One AggregateVersionChain database is bound to `systemId / aggregateId / aggregateName / aggregateVersion`. One row is one complete `IEvaluatedCommand` still pending coverage by the enrolled agent projection subscribers. It is **complete pending delivery**, rather than agent state, permanent history, an execution attempt or subscriber progress. The primary key is `aggregateIndex`; canonical `id` is also unique.

The immediate recipient is `AggregateAgentVersionRepo`, which materializes the agent view and independently publishes selected output to AggregateAgentVersionChain. Agent subscriber identity includes `agentName / agentVersion`; there is no actor path. Neither identity field is added to this table. All agents receive the same source command value and apply their own bound selections. The table name refers to the eventual agent Chain path, while the queue's immediate recipient is the projection Repo.

All 16 columns are the exact values already retained in permanent `commands` in this same database. New append encodes once and inserts both copies atomically. Enrollment backfill copies retained command rows unchanged. No row is updated; pruning deletes it, and later backfill may reinsert it. There are no framework-synthesized resource columns, per-agent envelope fields, delivery timestamps or attempt diagnostics.

## Historical lifecycle and exact deletion condition

1. `appendEvaluatedCommands` arms both queue producer leases before the synchronous append. The append transaction validates ordered positions, immutable full-command equality, result/operation constraints and exact model codecs, then inserts permanent `commands` plus the identical agent pending row. Identical repeated publication returns without recreating a deleted pending copy. A failed transaction leaves neither partial retained commands nor partial pending output.
2. The agent queue fixes one retained command tip per drain. Catch-up reads permanent `commands`; pushed delivery reads this pending table. Both page readers order by `aggregateIndex`, return at most 64 complete commands and honor the captured upper bound. Pending-row deletion does not change the advertised source tip.
3. AggregateAgentVersionRepo applies model members and commits resources, materialization progress and complete pending selected publication together. Only after its successful receipt does the source queue acknowledge the last delivered row. The receipt does not establish AggregateAgentVersionChain publication; that later transfer has its own pending message and acknowledgement.
4. Source acknowledgement advances the agent subscriber cursor monotonically and prunes in the same transaction. Pruning deletes pending rows through the **minimum `currentIndex` of all enrolled agent subscribers**. A slow or failed agent therefore retains every row it still needs. With no enrolled agent subscribers, pruning deletes every pending row. Permanent `commands` is never deleted by this process.
5. AggregateAgentVersionRepo activation catches up from retained commands, rereads its committed cursor and enrolls it. Enrollment atomically backfills pending copies above the new minimum subscriber cursor. Its producer lease spans source-tip validation and the local enrollment transaction, outside the drain semaphore. This covers the catch-up/enrollment interval without deadlocking activation against delivery.
6. A lost receipt leaves source acknowledgement behind the projection commit. Repeated delivery skips committed positions. Failed recipients retain their cursor and alarm recovery while healthy recipients progress. Fixed-tip drains, pre-commit producer leases and revision-guarded alarm release prevent production or enrollment from losing its wake-up. Removing this derivative payload copy would not change those mechanisms.

## Historical columns and their removal consequence

For every column, the writers are new append and unchanged-row backfill; the common reader decodes the complete row for pushed agent delivery. Pruning reads only `aggregateIndex`. Every value is immutable while present. The full command remains required in retained `commands` and transport; its second physical copy is the redundancy being challenged.

| Column                 | Meaning, nullability and necessity challenge                                                                                                                                                                                                                |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `aggregateIndex`       | Non-null primary key in admitted Aggregate order. Required for contiguous projection application, page bounds and cursor advancement. Permanent `commands` already supplies the same indexed position; there is no independent agent sequence here.         |
| `id`                   | Non-null unique canonical admitted command identity. Supplies model lineage, private completion identity and hash input. The duplicate constraint adds no immutable-publication protection because duplicate comparison already reads permanent `commands`. |
| `commandName`          | Non-null admitted contract name, included in selected command output. It is identical for every agent recipient.                                                                                                                                            |
| `payload`              | Non-null encoded admitted input. Agent projection does not reevaluate it. Keep it in the agreed full command rather than create a reduced message, but another stored copy adds no delivery fact.                                                           |
| `externalOutcome`      | Nullable admitted external observation. Null means no observation; recorded success/failure and its `recordedAt` remain input provenance. Permanent commands preserve the same value.                                                                       |
| `contractVersion`      | Non-null admitted contract version. Current executing declarations cannot replace historical input provenance. It remains in the full delivered command.                                                                                                    |
| `aggregateId`          | Non-null Aggregate instance identity, checked at source and projection boundaries. Derivable from the containing database, but retained by the approved full command. Removing the duplicate row avoids an abbreviated sibling representation.              |
| `aggregateName`        | Non-null Aggregate declaration identity. Same owner/envelope reasoning as `aggregateId`; it does not identify an agent recipient.                                                                                                                           |
| `aggregateVersion`     | Non-null original admission release. It may differ from the evaluating release bound to this AggregateVersionChain, so deriving it from the database binding would corrupt replay provenance.                                                               |
| `origin`               | Non-null Actor/Agent/System authority. Agent private completion checks exact admitted `agentName / agentVersion` when Origin is Agent. Origin identifies the command's authority, not every receiving agent.                                                |
| `nodeId`               | Nullable submitting Node correlation, coupled to `sessionName / pushIndex`. Used for private completion; null does not imply System authority.                                                                                                              |
| `sessionName`          | Nullable submitting session declaration, coupled to the producer tuple. Agent bootstrap and private completion preserve this association.                                                                                                                   |
| `pushIndex`            | Nullable producer submission position, distinct from aggregate order. The three producer fields are all null or all present.                                                                                                                                |
| `outcome`              | Non-null `{ result, finalizedAt }`. Supplies exact private failure and model-application time. A retained Failure has no operations; JSON-null Success remains valid. There is no second timestamp column.                                                  |
| `dispositionChainHash` | Non-null release-local identity/disposition prefix. Projection checks and retains it in progress/selected output. It does not fingerprint command payload, result details or operations and does not justify duplicating them.                              |
| `operations`           | Non-null authored-order model/external union. Agent projection applies model members and skips external descriptions. Preserve sparse `operationIndex`, exact model versions and frozen external IDs in the complete command.                               |

There are no indexes beyond the primary key and `unique(id)` declared by the shared shape. No column is unique pending-agent state. Removing any field only from delivery would weaken the approved full-command model; removing this entire duplicate table preserves every command field and consumer behavior.

## Reviewed structured values and agent-specific requirements

1. `origin` is Actor `{ kind, actorName, actorVersion, claims }`, Agent `{ kind, agentName, agentVersion }`, or System `{ kind }`. The literal `kind` selects authority; Actor claims retain the complete authored record, including any null values. Producer absence does not erase that authority.
2. `externalOutcome` is SQL null or Success `{ _tag, success, recordedAt }` or Failure `{ _tag, failure, recordedAt }`. External failure contains `_tag: 'ExternalRequestFailure'`, `code: 'external-request-failed'`, and `message`. Successful JSON null is distinct from no observation.
3. `outcome` is `{ result, finalizedAt }`, with Success `{ _tag, success }` or Failure `{ _tag, failure }` under `result`. Public failure contains `_tag: 'ZerospinError'`, `code`, optional contract/actor/aggregate `scope`, `message`, nullable `status`, and JSON `extra`. The outer finalization sample is preserved through delivery and used for model application; external observation `recordedAt` describes another event.
4. Model members contain `operationIndex`, `modelName`, `modelVersion`, `resourceId`, `operationName` and encoded `body`. Create body retains complete `attributes`; update retains an attribute patch; delete is empty; move retains `property / prevId / nextId` under exact model codecs. Parent `id` and `outcome.finalizedAt` supply lineage and application time. No inverse operation or prior resource snapshot is stored here.
5. External members contain `operationName: 'external'`, `operationIndex`, `externalContractName`, `externalContractVersion`, JSON `payload`, and frozen `externalCommandId`. Parent `id / origin` and the bound original execution release supply omitted request context. AggregateChain owns pending external requests; agent fanout does not run them. All operation indexes are nonnegative safe integers in strictly increasing order; replay may leave gaps.
6. Agent identity and authored selections are resolved by the bound AggregateAgentVersionRepo. The shared payload carries all source model changes; its completion filtering distinguishes each agent's own private result. Neither requires a pending copy. `getAgentBootstrap` obtains a coherent projection snapshot, publishes selected output through its captured position and reads the covered private outcomes from AggregateAgentVersionChain. It never reads this payload table or recovers bootstrap state from it.

## Approved amendment and review reconciliation

Permanent `commands` contains the exact complete value before any agent delivery can occur. Agent eligibility is already determined by subscriber progress against that retained tip. The queue's existing `readDeliveryPage ?? readPage` fallback can read those same commands directly. That preserves full input/output, order, exact source timestamps, fixed-tip drains, independent agent progress, retries, late enrollment and bootstrap. It removes only deletion and reconstruction of an identical second copy.

- [Existing delivery-reader fallback](../../../packages/system-worker/src/makeFanoutQueue/makeFanoutQueue.ts#L261-L264), [cursor-based eligibility](../../../packages/system-worker/src/makeFanoutQueue/makeFanoutQueueStorage.ts#L106-L137).

Plan 203 removes this physical table and append insert, the agent `readDeliveryPage` override, `#pruneAgent`, `#backfillAgent`, and their hooks. The logical queue, agent subscriber table, source-bound receiving capability, producer lease and alarm recovery remain. Acknowledgement advances only the agent subscriber cursor and never deletes permanent commands. Both Aggregate fanout queues now use the complete-command reader for delivery and catch-up, including late activation and enrollment. Generic pending-reader/prune/enrollment hooks remain in the shared factory because ServiceVersionChain and other owners still use them. Resource-owning projection Repos retain complete pending selected publication because they do not retain selected history.

An AggregateAgentVersionRepo receipt proves that Repo committed resources, its materialization head and pending selected publication together. AggregateVersionChain then advances the agent subscriber cursor. AggregateAgentVersionChain retention is a separate publication with its own acknowledgement. A lost source receipt may redeliver commands without reapplying committed positions. Agent bootstrap still reads selected history through its exact captured snapshot prefix.

Both independent reviewers reached this conclusion after examining agent-specific identity, selections, bootstrap and receipt boundaries. They found no correctness defect in the former floor/prune/backfill design and no additional durable fact supplied by its payload copy. This extends the reasoning implemented for actor delivery in Plan 202 only after a separate agent review; it does not automatically review either subscriber table or change any approved full-command field.
