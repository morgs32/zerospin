## Physical scope and row responsibilities

[agentReplicaDbConfig](../../../packages/browser/src/agentSession/agentReplicaDbConfig.ts#L7-L20) spreads Aggregate session tables into the Agent's selected model database and adds separately owned producer metadata. [openAgentReplica](../../../packages/browser/src/agentSession/openAgentReplica.ts#L24-L50) creates one fresh local session ID and one in-memory SQLite client per owning Scope. Reconnect attempts reuse that client; disposal closes the entire database. This is direct Agent socket delivery, without an AggregateNode journal, persisted Agent replica file or cross-tab original-command input stream.

Current successful staging retains one original row with input, original local result/time and current inverses. Incoming selected exposure retains a second final row with the same command ID. Correlation suppresses further submission/replay and proves the contiguous producer outcome prefix. Foreign selected commands retain only a final row. Unlike Actor/Service Node delivery, neither Agent phase acquires an independent Node coordinate.

The required row responsibilities are **pending input/current optimism**, **retained producer correlation**, and **immutable selected final evidence**. They need not be separate rows. Producer correlation must survive final exposure because admission reconciliation and outcome-prefix recovery still need id/pushIndex. Selected final evidence must survive subsequent resource changes because exact redelivery cannot be checked against the latest resource view. Pending input/time/current inverses have no supported reader after final exposure and can then be cleared.

## Structured members and source-specific derivation

1. **Origin:** the shared codec permits Actor, Agent and System. Actor has kind/name/version plus a complete encoded claims record; Agent has kind/name/version without claims; System has only kind. The supported Agent writer produces only the exact bound Agent branch. Removing the SQL copy does not remove protocol authority or justify deleting per-command Actor Origin from a different replica owner.
2. **Staging result/time:** result accepts encoded JSON, including JSON null; completedAt uses the Date/string codec. Result encoding/validation remains necessary before successful staging, and the caller still receives the decoded domain result. Agent submission explicitly omits the whole envelope; pending replay consumes its time and validates the newly evaluated result without comparing the original. The shared retained-command decoder's schema requirement is not an independent Agent requirement. No concrete Agent history/inspection consumer requires stored encoded results. Retain only the existing sample as stagedAt while pending.
3. **Compact inverses:** every variant has exact modelName/modelVersion/resourceId and original operationName. Create needs only identity to undo the speculative resource. Update/move retain a model-encoded inverse string and previousUpdatedAt; delete retains the complete deleted resource through its inverse codec. Model codecs own authored values and reference semantics. Keep reverse command/operation application, prior timestamps and reference constraints; do not restore the old forward-operation envelope.
4. **Final failure:** retain `_tag: 'ZerospinError'`, code, optional scope, message, nullable numeric status and JSON extra exactly as disclosed. Canonical `outcome: { result, finalizedAt }` stays in owning Chain history. Nullable browser failure cannot replace `outcome.result._tag` or identify private failures belonging to another recipient.
5. **Selected delta:** upserted resources include id/modelName/version/createdAt/updatedAt plus model-owned authored properties. Deleted references contain id/modelName. Complete selected values support resource application and immutable final retry comparison, including empty arrays. There are no local original-input fields hidden inside this delta.

## One command row, with distinct admission and exposure

The Actor/Service Node justification for two phase rows is independent original/final Node record coordinates. Agent has neither coordinate: admission receipts update producer acknowledgement metadata, while only IAggregateExposedCommand pages arrive as command history. Keeping two rows solely to reuse generic Aggregate anti-joins preserves machinery without another independent record fact.

1. **Local stage:** evaluate once, validate the result, sample the existing logical time, apply optimism and retain canonical ID/name, encoded payload, stagedAt/current inverses and local position in one synchronous transaction. The public result remains unchanged. The row initially lacks final fields and may lack a pushIndex until handoff.
2. **Submission/admission:** assign pushIndex once atomically with producer allocation. Reconstruct complete admitted input from row input plus immutable bound context/contract, including protocol nodeId from the lifetime ID. Uncertain reconnect retries preserve ID, payload and assigned pushIndex. Admission validates ID/push/allocated prefix/current pending ownership and advances only admission acknowledgement. Retain pending input/time/inverses after admission.
3. **Final exposure:** rewind local optimism before applying selected authoritative changes. For a matching pending ID, require matching commandName, preserve sessionIndex/pushIndex and attach final failure/delta/index/hash. Clear payload/stagedAt/current inverses in that same commit, then replay remaining pending inputs. A foreign final inserts one final-only row. Empty selected changes and null failure still settle the local input. Exact final repeats must compare all selected final fields before any mutation; conflicts or occupied Aggregate positions abort.
4. **Late admission receipt:** exposure can arrive before its admission receipt and clear the connection's pending admission. Reconciliation must locate the retained originating producer row regardless of whether it now has aggregateIndex, and validate the same ID/push/allocated prefix. Its current original-phase predicate must not survive this merge. Clearing settled input/time loses no receipt evidence.
5. **Prefix/provenance:** committedOutcomeIndex must scan every row with a local pushIndex, including settled rows, and prove the contiguous finalized producer prefix directly. Pending submission/replay becomes aggregateIndex-null, without a final-counterpart anti-join. Final-only rows have no local producer position and must never create local-origin failure authority. Keep lifetime/current-attempt fences and the originating ID/name map; emit failure only after the final row commit, once for that actual originating command.
6. **Admission refusal:** refuse only the actual local unfinalized, unadmitted pending submission. Preserve contradiction checks against admitted prefixes and any later finalized producer positions. In one transaction rewind optimism, delete that refused row, compact only allowed later unadmitted push positions, decrement producer allocation and replay survivors. This refusal is not retained canonical execution Failure. A settled row must never be deleted or have its producer coordinate compacted by that path.
7. **Snapshot/reconnect:** validate the bound snapshot and complete requested recovery prefix first. Snapshot replacement clears current inverses, replaces resources/checkpoint, retains/merges covered final evidence and replays surviving pending input in one transaction. Covered finals settle local input without reapplying stale deltas; new streamed finals preserve contiguous Aggregate application and hash comparisons. Current final commit and later admission-prefix reconciliation are distinct transactions; retained final proof supports recovery if prefix publication lags. Do not infer canonical finalization from an admission index.
8. **Retention:** retain settled producer/final proof for exact retry and contiguous outcome recovery. No ordinary acknowledgement, exposure or reconnect prunes those rows. Only an explicit pre-admission refusal removes its pending row; Scope disposal releases the whole in-memory database. Payload/time/current undo are cleared on final exposure, not after admission. No new TTL, reset, pruning or persistence feature is proposed.

## Original reviewer reconciliation and limits

All three reviewers support an Agent-owned eleven-column model, bound context/contract derivation, removed Node coordinates and one row per canonical ID. The staging-result challenge was resolved from actual wire/replay consumers: retain result validation/public return, but only the existing time in pending SQL. A lifecycle follow-up also challenged the initial assumption that merged final rows should retain local payload/time. No supported reader needs them after exposure; late receipts/prefixes need ID/push/final proof, so those pending fields should be cleared with final application.

Implementing this recommendation requires updating Agent staging, submission reconstruction, replay/rewind, final import, snapshot, prefix/rejection and observer consumers together. Reuse meaningful contract evaluation/model undo procedures, without forcing the Agent back into an artificial Aggregate twenty-column/two-phase SQL representation. Keep Aggregate and Service physical storage unchanged; their independently versioned/Node-coordinate responsibilities are not removed by this finding. Existing ADRs document context, not a constraint on the clearer Agent model.

No ordinary supported-path runtime defect was reproduced or identified by this source review.
