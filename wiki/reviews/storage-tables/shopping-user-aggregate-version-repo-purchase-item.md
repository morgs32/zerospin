# Shopping user AggregateVersionRepo.purchaseItem

**Reviewed:** 2026-10-17 against current source, with independent lifecycle and column-design reviewers. Exactly the source AggregateVersionRepo.purchaseItem ownership context is reviewed. Projection Repos, Nodes and replicas are dependencies, not additional completed table reviews. All verification remains deferred, including Plan 236 implementation verification.

**Verdict: retain the table and all eight current stored columns.** PurchaseItem is a Purchase's frozen checkout line: product identity and quantity, followed by quoted name and unit price. Those business facts survive payment and cart clearing. They belong with the Purchase resource in AggregateVersionRepo. No further schema, naming or lifecycle cleanup is recommended.

**Plan 239 follow-up (2026-10-17):** Approved [Plan 239](../../archive/plans/239-plan-shopping-promotion-reservations.md) keeps all eight PurchaseItem SQL fields and full resource envelopes. Price is the authoritative undiscounted unit price in integer USD cents; quantity remains the frozen CartItem quantity. Promotion discount is retained on Purchase and does not rewrite individual prices. Paid clearing still deletes matching CartItems, not PurchaseItems. Implementation is written with all verification deferred; the source review below is historical evidence, not passing Plan 239 verification.

## Ownership and current representation

[Shopping's System](../../../examples/shopping/src/zerospin/system.ts#L8-L15) registers user@1.0.0. Its [release model map](../../../examples/shopping/src/zerospin/aggregates/user/userAggregateReleaseV1.ts#L18-L27) explicitly includes purchaseItem@1.0.0. [PurchaseItemV1](../../../examples/shopping/src/zerospin/aggregates/user/models/purchaseItem/PurchaseItemV1.ts#L4-L23) declares the pit-prefixed resource identity and five authored attributes.

The physical owner is AggregateVersionRepo with key `(systemId, aggregateName='user', aggregateId, aggregateVersion=1)`. [Release resolution](../../../packages/system-worker/src/AggregateVersionRepo/AggregateVersionRepo.ts#L60-L85) composes that exact release's model tables with the Repo's fixed materialization checkpoint and complete pending publication. [Generic composition](../../../packages/core/src/drizzle/make/makeDbConfig/makeDbConfig.ts#L29-L44) uses each canonical model.table; there is no PurchaseItem-specific framework table or release storage policy.

[Plan 236](../../archive/plans/236-plan-model-rows-and-resource-envelopes.md) is written but unverified. Current [model construction](../../../packages/core/src/models/make/makeModelVersion.ts#L331-L397) synthesizes the resource fields and omits modelName/version from the SQL table. PurchaseItem therefore has **eight stored fields**, not the previous ten. Complete resource envelopes still have ten: the same eight plus bound modelName='purchaseItem' and version=1. This finding does not reverify that cutover or repeat its implementation proposal.

One row is current business resource state, not retained command history, a materialization checkpoint or pending delivery. Deriving purchase lines by replaying Chain history would replace a direct owned resource with historical reconstruction. Clearing a publication outbox after acknowledgement must not delete the PurchaseItem.

Checkout requires a positive safe integer; quotation and payment require exact equality with the frozen line.                                              | Retain. The [declaration](../../../examples/shopping/src/zerospin/aggregates/user/models/purchaseItem/PurchaseItemV1.ts#L8-L22) has no authored indexes, defaults, extra uniqueness, TTL or JSON columns. name and price are the only nullable fields. The id primary key is the only unique identity; there is no product-per-Purchase uniqueness assumption. The concrete purchaseId reference has ordinary NO ACTION update/delete behavior, not automatic cascading deletion. [SQL primitive mapping](../../../packages/shapes/src/primitiveMaps.ts#L124-L255) distinguishes timestamps, integers, concrete refs and prefixed identifiers; [foreign-key compilation](../../../packages/core/src/drizzle/definition/compileSqliteTableDefinition.ts#L43-L53) retains the reference actions.

Positive quantity, nonnegative price, the name/price null pair and correspondence with Purchase.paymentState are command-level invariants, not SQL CHECK constraints. [PurchaseLine/PurchaseQuote codecs](../../../examples/shopping/src/zerospin/purchaseQuote.ts#L3-L27) and the authored writes establish their supported values. Do not claim that arbitrary direct SQL writes or arbitrary future model-operation permissions preserve them. There are no structured column members to audit. Additional parent-reference indexing would need workload evidence; this review establishes no performance requirement.

## Writers, readers and transaction lifecycle

1. **Checkout freezes the original lines.** [checkoutV1](../../../examples/shopping/src/zerospin/aggregates/user/contracts/checkoutV1.ts#L44-L118) rejects a locked cart, empty/invalid quantities and a reused Purchase ID. It creates Purchase and its lines with product/quantity and null name/price, then links the cart to that Purchase. [checkoutServerV1](../../../examples/shopping/src/zerospin/aggregates/user/contracts/checkoutServerV1.ts#L21-L44) records those model operations and the frozen quotation request together.
2. **Quotation captures mutable catalogue facts once.** Marketplace's [quotePurchase query](../../../examples/shopping/src/zerospin/services/marketplace/marketplaceServiceReleaseV1.ts#L26-L83) reads Product by productId, checks supported quantities/prices and returns name/price plus the total. It does not own or mutate PurchaseItem. [getExternalPurchaseQuoteV1](../../../examples/shopping/src/zerospin/aggregates/user/contracts/getExternalPurchaseQuoteV1.ts#L84-L164) requires the still-linked preparing Purchase and exact retained line set; it validates response IDs, products, quantities, uniqueness, safe prices and total arithmetic. A refused/unavailable quote marks Purchase refused and leaves the unquoted lines. A valid quote updates all names/prices, makes Purchase pending with its total and records the payment request in the same evaluated command.
3. **Payment uses the frozen line set.** [processExternalPaymentV1](../../../examples/shopping/src/zerospin/aggregates/user/contracts/processExternalPaymentV1.ts#L49-L105) checks pending Purchase identity, amount/key and exact locked-cart correspondence by line ID, product and quantity. Successful payment deletes cartItem rows only. PurchaseItem remains available independently of the cart. The line snapshot is intentional business denormalization; current catalogue/cart lookup cannot replace it.
4. **Reads expose complete resources without moving their authority.** The [user Actor](../../../examples/shopping/src/zerospin/aggregates/user/actors/userActorV1.ts#L16-L34) declares PurchaseItem and [selects its rows](../../../examples/shopping/src/zerospin/aggregates/user/actors/userActorV1.ts#L66-L70). The [purchases Agent selection](../../../examples/shopping/src/zerospin/agents/purchasesAgentRelease.ts#L12-L28) also includes PurchaseItem. Selection/exposure are actual readers, but retaining these columns is justified by the frozen Purchase facts above, not merely by their inclusion in a selection. This review does not certify Agent reference closure or another owner's storage shape.
5. **Resource writes, progress and pending publication commit together.** [materializeCommandTx](../../../packages/system-worker/src/AggregateVersionRepo/materializeCommandTx.ts#L14-L43) owns the synchronous transaction. [executeAggregateCommandTx](../../../packages/system-worker/src/AggregateVersionRepo/utils/executeAggregateCommandTx.ts#L38-L66) evaluates/applies under a savepoint; a failure does not leave half-created or half-quoted lines. [applyAggregateOperationsTx](../../../packages/system-worker/src/AggregateVersionRepo/utils/applyAggregateOperationsTx.ts#L21-L48) preserves operationIndex/order and supplies the command's finalizedAt to resource writes. [retainEvaluatedCommandTx](../../../packages/system-worker/src/AggregateVersionRepo/utils/retainEvaluatedCommandTx.ts#L9-L40) commits materializationHead and complete pending evaluated-command publication with those resources. External catalogue/payment requests run outside that resource transaction.
6. **Retry/replay does not change the row's responsibility.** [finalizeCommand](../../../packages/system-worker/src/AggregateVersionRepo/finalizeCommand/finalizeCommand.ts#L56-L108) recovers already-materialized originals without applying them again. [Replay](../../../packages/system-worker/src/AggregateVersionRepo/replayCommands/replayCommand.ts#L37-L54) uses the same materialization boundary, while [prepareAggregateOutput](../../../packages/system-worker/src/AggregateVersionRepo/utils/prepareAggregateOutput.ts#L25-L30) suppresses external re-emission. Committed resource/progress/publication survives interruption; Chain history and pending-delivery acknowledgement remain separate facts.
7. **There is no authored PurchaseItem expiry or deletion policy.** The reviewed release grants creates at checkout and updates at quotation, with no PurchaseItem delete/move operation. Paid, declined and refused Purchases retain their line resources. No pending-delivery acknowledgement prunes them. A future Purchase-deletion design would need an explicit line-deletion order/policy; this review does not invent one or add an archive state.

## Reconciliation and limits

Both independent reviewers retain the table and its eight-column row. They agree that product/quantity and quoted name/price cannot be replaced with current cart/catalogue data, that purchaseId must remain explicit, and that metadata constants already belong to the bound Model under Plan 236. Grouping quote fields into JSON, adding a quote-state discriminator, storing a line total or reconstructing timestamps from a parent would add machinery without removing a real lifecycle responsibility. No ordinary supported-path correctness defect or further implementation task was established for this table.

Only this finding and Plan 151 change. No implementation, tests, fixtures, runners, configuration, storage reset, migration, deployment or data deletion is authorized or performed.
