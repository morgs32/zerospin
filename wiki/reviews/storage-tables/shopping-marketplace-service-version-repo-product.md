# Shopping marketplace ServiceVersionRepo.product

**Reviewed:** 2026-10-17 against current source, with independent lifecycle and column-design reviewers. Exactly the source ServiceVersionRepo.product ownership context is reviewed. Catalogue projections, Nodes/replicas, CartItem and PurchaseItem are dependencies, not additional completed table reviews. All verification remains deferred, including Plans 236/237 implementation verification.

**Verdict: retain the table and all six stored columns.** Product is Marketplace's current catalogue resource and the source of authoritative checkout quotation. Recommend one focused validation repair: **createProduct must refuse negative prices before recording its create operation**, while allowing zero. Current creation permits values that catalogue readers display but quotePurchase refuses. No column removal, rename, new state or SQL schema redesign is recommended. The repair is a recommendation only; this review implements nothing.

## Ownership and row responsibility

[Shopping's System](../../../examples/shopping/src/zerospin/system.ts#L8-L15) lists marketplace@1.0.0. The [marketplace release](../../../examples/shopping/src/zerospin/services/marketplace/marketplaceServiceReleaseV1.ts#L11-L24) owns only product@1.0.0 and registers createProduct/deleteProduct plus read queries. [Product identity](../../../examples/shopping/src/zerospin/services/marketplace/models/product/product.ts#L3-L6) is product with prd-prefixed IDs; [ProductV1](../../../examples/shopping/src/zerospin/services/marketplace/models/product/ProductV1.ts#L5-L13) supplies description, name and price.

The physical ServiceVersionRepo key is `(systemId, serviceName='marketplace', serviceVersion=1)`. [Its name contract](../../../packages/system-worker/src/ServiceVersionRepo/serviceVersionRepoName.ts#L7-L12) and [release-specific database composition](../../../packages/system-worker/src/ServiceVersionRepo/serviceVersionRepoMigratableDORepoConfig.ts#L24-L48) bind exactly that release's Model table alongside materializationHead and complete pending serviceVersionChainOutbox publication. It is one shared catalogue, not a separate authoritative Product per shopper.

Current [Model construction](../../../packages/core/src/models/make/makeModelVersion.ts#L331-L397) uses Plan 236's common row representation: **six SQL fields**—id, createdAt, updatedAt, description, name and price. Full resource envelopes additionally contain bound modelName='product' and version=1, for eight fields. [Plan 236](../../archive/plans/236-plan-model-rows-and-resource-envelopes.md) remains written/unverified; this finding does not verify that cutover.

One row is current resource state, not a retained command, catalogue event, price history, checkpoint or delivery message. Copied Cart display values and frozen Purchase quotes have different owners and lifetimes; neither can replace the catalogue that future quotations read. Seeds are ordinary [createProduct command declarations](../../../examples/shopping/src/zerospin/seeds.ts#L7-L28), not a substitute for runtime Product creation/deletion.

## Lifecycle, authority and deletion

1. **Create/delete are the current mutation surface.** [CreateProductV1](../../../examples/shopping/src/zerospin/services/marketplace/contracts/createProduct/CreateProductV1.ts#L8-L26) records id/description/name/price through the bound Model operation. [DeleteProductV1](../../../examples/shopping/src/zerospin/services/marketplace/contracts/deleteProduct/DeleteProductV1.ts#L8-L20) deletes the exact supplied ID. No update, expiry or soft-delete/status path is registered. The [catalogue Actor](../../../examples/shopping/src/zerospin/services/marketplace/actors/catalogActorV1.ts#L9-L28) authenticates its read-only selection and exposes no mutation contracts; this validation finding concerns a declared createProduct invocation, not a claim that catalogue subscribers may create Products.
2. **Catalogue queries read current resource state.** Marketplace [getProducts](../../../examples/shopping/src/zerospin/services/marketplace/marketplaceServiceReleaseV1.ts#L21-L24), the Actor's Product selection and [ProductList](../../../examples/shopping/src/components/ProductList.tsx#L7-L30) expose the current rows. ProductCard renders name, description and unit price. Product deletion removes current catalogue availability; there is no pending-delivery acknowledgement or history-retention condition for deleting this business resource.
3. **Quotation reads the authoritative catalogue.** [quotePurchase](../../../examples/shopping/src/zerospin/services/marketplace/marketplaceServiceReleaseV1.ts#L26-L83) loads each requested Product by id, refuses missing Products, unsafe/negative prices and invalid quantities, then returns current name/unit price and a safe matching total. [executeServiceQuery](../../../packages/core/src/service/executeServiceQuery.ts#L38-L98) holds ServiceVersionRepo's execution permit while this synchronous query reads the local catalogue. This is a coherent local observation, not a cross-database transaction with the user Aggregate.
4. **Copies have deliberate, independent lifetimes.** CartItem takes client-supplied display snapshots; checkout freezes Product identity and quantity and later installs the Marketplace quote in PurchaseItem. A later Product deletion does not cascade across databases into either copy. A quote requested after deletion refuses the unavailable Product; a previously recorded quotation remains a frozen observation for its continuation. Retaining purchased values does not require a Product tombstone, another source history table or rereading the catalogue at payment time. The prior [CartItem finding](shopping-user-aggregate-version-repo-cart-item.md) and [PurchaseItem finding](shopping-user-aggregate-version-repo-purchase-item.md) remain separate owner reviews.
5. **Materialization is atomic.** [materializeCommandTx](../../../packages/system-worker/src/ServiceVersionRepo/materializeCommandTx.ts#L14-L43) orders admitted input, evaluation, outcome finalization and result retention. [executeServiceOccurrence](../../../packages/system-worker/src/ServiceVersionRepo/utils/executeServiceOccurrence.ts#L36-L66) supplies the synchronous savepoint; source resource changes, [materializationHead and complete pending publication](../../../packages/system-worker/src/ServiceVersionRepo/utils/retainEvaluatedCommandTx.ts#L16-L39) commit together. The same logical finalizedAt supplies resource writes and outcome.finalizedAt. A failed execution does not leave partial Product writes. Source publication acknowledgement deletes pending messages, not the catalogue or retained Chain history.
6. **Recovery preserves the same responsibility.** Already-materialized originals recover committed output rather than creating/deleting again. Ordered replay uses the same materialization boundary; [prepareServiceOutput](../../../packages/system-worker/src/ServiceVersionRepo/utils/prepareServiceOutput.ts#L25-L30) retains model operationIndex/order and suppresses external re-emission. No Product-specific retry, ledger, version counter or cleanup subsystem is required. Hard deletion remains an authored operation; retry of the same retained command is distinct from a new command deleting an already absent row.

## Supported finding: negative prices enter the catalogue

1. [createProduct.payload.price](../../../examples/shopping/src/zerospin/services/marketplace/contracts/createProduct/CreateProductV1.ts#L9-L23) is an integer primitive. That codec [selects the signed SafeIntegerSchema](../../../packages/shapes/src/compileDescriptor.ts#L165-L166), and the program forwards price without a business guard. A negative safe integer therefore satisfies the declared creation path; no SQL nonnegative constraint exists. Catalogue selection and rendering do not filter it out.
2. [quotePurchase](../../../examples/shopping/src/zerospin/services/marketplace/marketplaceServiceReleaseV1.ts#L49-L59) explicitly refuses product.price < 0. Source code therefore allows a catalogue Product that its own checkout quotation cannot sell. This is a concrete validation mismatch, not a claim of incorrect charges: the quotation boundary already prevents payment from using a negative price.
3. **Recommended repair:** declare a typed business refusal on createProduct and reject price < 0 before recording operations.createProduct. Keep zero valid and preserve the existing signed-safe-integer codec's type/range checks. Keep independent quote and continuation validation; moving all responsibility to the writer would weaken the remote observation boundary. Use the existing contract failure/guard facilities, not a new primitive, SQL constraint framework or validation layer. No repair or new test is implemented in this review.
