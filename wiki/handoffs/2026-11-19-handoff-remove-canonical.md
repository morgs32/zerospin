# Implementation handoff for removing Aggregate `canonical` release selection

**Date** 2026-11-19

**Scope** Implement the agreed Aggregate release, initialization, and compaction behavior in the Zerospin worktree on `codex/owner-worker-integration`. The prototype at `037f63258a` still uses canonical adoption and the owner Chain’s finalized position as its initialization cutoff. [PR #176](https://github.com/morgs32/zerospin/pull/176)

## Settled ownership

1. `AggregateChain` orders admissions, dispatches original execution, records finalization, and delivers replay. Local command rows cover pending work and the suffix awaiting compaction. Permanent evaluated history and Archives belong to VersionChains. Each currently listed release continues replaying from the owner Chain. [Glossary](../glossary.md#command-chain)
2. Every Aggregate release after the first declares exactly one of `branchFrom` or `rebuildFrom`, even on empty history. The named earlier release of the same Aggregate stays listed. Its VersionChain supplies the complete prefix, including any inherited commands. [Predecessor decision](../adrs/025-canonical-published-history-handoff.md#aggregate-release-predecessors-2026-11-19)
3. The cutoff for each child release and Aggregate instance is the **named predecessor’s published head, captured on first initialization**. The child performs a bounded pull. Ongoing delivery belongs to the owner Chain. With the owner finalized through 12 and V2 published through 10, a branch from V2 inherits through 10 and evaluates 11 and 12 itself. [Cutoff decision](../adrs/025-canonical-published-history-handoff.md#aggregate-initialization-cutoff-2026-11-19)
4. `AggregateChain` retains each finalized row until **every currently listed release** has acknowledged replay through it. A missing acknowledgement counts as zero. A stalled listed release can fill the existing 64-command suffix and pause new admissions. [Compaction decision](../adrs/025-canonical-published-history-handoff.md#aggregate-compaction-decision-2026-11-19)

On first use, the predecessor’s `getEvaluatedCommandPage({ afterIndex: 0, maxIndex: 0 })` already returns its published head as `lastIndex`. Read it outside SQL, atomically insert the point if absent, and return the stored winner. Persist zero. Remove the owner-finalized cutoff and the forced predecessor Repo catch-up. Resume pages with `getEvaluatedCommandPage({ afterIndex, maxIndex: point })`. Branches restore evaluated commands, rebuilds evaluate admitted inputs, and the child publishes its own prefix. Recover any pending publication before treating that prefix as published. Reuse the bounded pull behavior where it simplifies these calls.
