## Current agreed design

1. SystemRepo owns four required ticket columns: unique `ticketHash`, `sessionFamily`, complete typed `admission` and `expiresAt`. The family selector preserves wrong-family non-spend and matching-family spend before retained-row decoding. No extra status, acknowledgement, retry or ticket-history state is needed.
2. Current admission has four branches: Aggregate Actor, Aggregate Agent, Service Actor and Service Agent. Retain exact owner/release/instance, full lock, actual claims or canonical Origin, Actor path and Node binding as applicable. Session identity comes from the complete lock; Service Actor identity comes from serviceSessionLock. Persist no outer sessionName, Service actorName/actorVersion, physical Chain name or alternate envelope.
3. Ticket-local full lock schemas require nonempty session names and Service Actor name, with the canonical integer declaration version. Shared core locks remain unchanged. Strict issuance preserves kind/Origin/full-lock agreement, current authored capabilities, full claims decoding and canonical Actor path/instance agreement.
4. Agent nodeId is nonempty and binds public observer ticket/resume identity. It is not a browser command producer or automatic Agent producer sequence. Actor nodeId remains nullable. Reject unusable admissions before random generation, hashing or SQL.
5. Issue only after validating retained authority. Generate a 32-byte secret, return its 43-character base64url encoding only after commit, and retain only its SHA-256 hash. One synchronous transaction deletes expired tickets and inserts the new complete admission with a thirty-second deadline. Transaction failure commits neither cleanup nor the new row.
6. HTTP validates method/path, upgrade and one exact ticket query parameter before consumption. Consumption hashes the secret and executes a single family-filtered DELETE RETURNING. That statement arbitrates single use. The row is already spent when full decoding, family consistency and exact deadline are checked. Wrong-family requests retain it; matching expired/corrupt rows, later lookup/forward failures and failed upgrades never restore it.
7. Forward outside SQL to the exact retained family/owner. Remove the complete query and all caller x-zerospin-\* headers, then synthesize the full trusted identity/claims/lock/Node headers from admission plus the physical SystemRepo identity. Consumption must not rebuild locks from current registries. Ticket spend, socket installation/resume, command admission, execution commit and outcome retention are separate facts.
8. Authentication precedes session capability authorization. SystemRepo ticket issuance validates already bound claims and authority; it does not authenticate credentials. Verify generic ServiceApi.admit authentication and strict claims output, then actual authorization/session ticket issuance/forwarding to the bound ServiceActorVersionChain. Fixture credentials are not real Clerk/provider integration. Complete command admission and broader registration remain Plan 222 work.
9. Preserve the fixed-schema hard cutover: empty affected SystemRepo storage is required. Add no fallback decoder, compatibility path, migration, automatic reset or reconstructed envelope. No existing store reset, deployment, publication or commit is authorized. Other reviews and Plan 151 obligations remain separate.
