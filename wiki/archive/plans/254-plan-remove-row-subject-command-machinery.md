# 254 — Remove row-subject command machinery

Status: Complete. Authorized on 2026-10-21. Breaking release and Zerospin Cloud adoption are in scope; unrelated development work and production deployment are not.

## Settled direction

1. Commands carry their authored business inputs in `payload`. Aggregate/service routing and command identity keep their existing distinct responsibilities. There is no generic command-level resource ID or contract row subject.
2. Model operations retain `resourceId`; one command may emit operations for zero, one, or many resources. Contract programs declare their read models, read current rows explicitly, and perform their existing authorization and business checks.
3. Remove the row-subject constructors, callback context, schemas, storage columns, transport fields, validators, readers, exports, Studio assumptions, and automatic wake input conventions. Do not add aliases, fallback decoding, translation migrations, old fields, or a pass-through fix preserving the rejected design.
4. Agent wake declarations identify the ordinary contract and explicitly derive its payload from the selected row. Retain query/scheduling ownership without injecting a second command input channel or guessing payload field names.
5. Authoritative exposed deltas continue to apply recorded model changes directly. Optimistic reconstruction replays only unresolved originals with their original payloads; covered commands are not applied twice.
