# Compact domain workflows: phased redesign of all eight opportunities

Approved in this chat and scheduled for 2026-10-11 at 01:00 America/Chicago. The purpose is to make parent methods a short, obvious sequence of cohesive domain procedures, preserving authority, atomicity, error propagation, and cancellation. Public APIs, protocols, storage and ownership may change where the clearer architecture requires it. This is not a line-count exercise or an extraction-only refactor.

## Scope and decisions

1. Replace superseded paths outright. No aliases, legacy decoders, migrations, new cast exceptions, test files, fixtures, runners or configuration. Preserve existing Storybook content and unrelated WIP. Changed fixed schemas require fresh storage; do not automatically erase existing databases or deploy over an existing backend to bypass an incompatible RPC cutover.
2. Integrate [Channel programs](099-plan-channel-contract-programs.md), [browser lifetime](100-plan-unified-browser-session-lifecycle.md), and [confirmed projection ownership](101-plan-remove-aggregate-server-staging.md). Preserve the separate [aggregate admission plan](102-plan-aggregate-command-admission-orchestration.md). Read existing completion evidence before changing these areas.
3. Use named domain procedures, explicit owner identity and execution release, synchronous transaction boundaries, and direct imports. Keep simple operations inline. Do not introduce generic runners, resolver context bags, forwarding wrappers, second lifetimes, or a generic materializer.
4. Governing authority and retention decisions remain in [ADR 006](../../adrs/006-browser-speculation-and-confirmed-projections.md) and [ADR 004](../../adrs/004-versioned-agent-selected-views.md), clarified with permanent full agent-definition locks. Reconcile source documentation and glossary after implementation; record a new ADR only for a qualifying implemented decision.

## Phases by opportunity

### 1. Actor admission

1. Move selection and claims hashing to shared actorAdmission utilities; delete service duplicates. Capture declaration authentication before asynchronous log acquisition. A service-specific authentication procedure runs the callback once and decodes/encodes complete claims; resolve the actor directly.
2. Share admission auditing and one discriminated SystemLogRepo.beginAdmissionAttempt. Parent order is authenticate, select, hash, encode under audit. Interruption leaves attempts unfinished; completion RPC is mandatory, and completion failure outranks the original error. Storage unchanged.

### 2. System acceptance

1. Hard-rename checkSystemSpec to acceptSystemSpec(): void. Remove Worker-version props/results. Add authenticated getExecutingWorkerVersion(): string | null reading the addressed SystemRepo's own version metadata.
2. Acceptance transaction calls focused aggregate actor, service actor, aggregate release, service release and agent lock procedures. Actor and release uniqueness remain separate guarantees. Add lockedAgentVersions storing full IAgentSpec; same name/version with changed bindings or selections is rejected. registerRepo requires accepted definitions including agents. Preserve removed-release locks. Fresh SystemRepo schema.

### 3. Confirmed projections

1. Do not restore deleted staging. Validate every executed row before duplicate skipping; enforce contiguous progress and exact model identity, rejecting unknown/wrong versions. Apply canonical operations then selection in one synchronous batch transaction.
2. Commit pure graph delta, outbox and {aggregateIndex,executedIndex,executedHash} together. Remove redundant aggregateVersion checkpoint. Snapshot catches up to a bounded canonical prefix, captures resources/checkpoint atomically, drains captured output, then requests Node private outcomes at that captured checkpoint. No RPC within transactions or later graph reread. Fresh projection schema.

### 4. Aggregate socket

1. Share tagged schemas across actor and agent clients. Resume carries nodeId, outcomeIndex, executedIndex and executedHash; replies explicitly identify commands, replay completion, immutable admission receipts, failure or state requirement. Use safe integer indexes and awaiting-resume/replaying/live phases; retain large authority locks separately.
2. Admission validates exact binding, producer/session/contract and server systemName, submits the unchanged singleton ordinary command, and validates receipt identity/position. Claim pending synchronously; release on every exit including interruption; acknowledge committed admission before best-effort telemetry. Remove unused trace link machinery.
3. Replay a fixed tip while publication skips live sends. At handoff inspect current tip and send a bounded tail of at most 64 rows, replay completion, and mark live within one synchronous turn. Larger tails cause another asynchronous fixed segment. Do not buffer arbitrarily or close replaying sockets merely because publication raced. Preserve independent canonical/private cursors, redaction and duplicate recovery.

### 5. Materialization and transactions

1. Native makeTx/withSavepoint preserve full captured Cause after successful rollback and cancel suspended fibers before rollback. SQL wrapper/rollback errors remain transaction errors. No extra synchronous evaluator. Effect.scoped closes business resources inside the savepoint; after rollback retain only a sole AsyncFiberError as program-must-be-synchronous and approved typed/authored refusals. Mixed Causes, defects and interruption abort the outer transaction.
2. Delete captureEvaluation, ExecutionEvaluationCause, side channels and outer recovery wrappers. Minimal occurrence is {command,head,startedAt}; pass owner, execution release and original/replay mode explicitly, deriving next executedIndex. Parent reads occurrence, executes savepoint, finalizes, retains outbox/head. Concrete aggregate/service procedures own binding, input, Channel evaluation, ordered output and application. Remove forwarding execute/replay wrappers. Preserve service lazy genesis and caller policies.
3. Collapse ServiceVersionRepo commands and forwarded final outbox into one full executedCommandOutbox, keyed by executedIndex with unique serviceIndex. Retain source/execution version, caller, finalization and hash. Update page/result/ack/forwarding consumers; after acknowledgement the chain owns final results while async rows remain. Fresh service schema. Audit all four savepoint consumers.

### 6. Browser bootstrap and reconciliation

1. Use completed Plan 100 ownership. Acquire inert scoped connection handles with no discovery, network, worker or callbacks; register release/abort, bind outbox, then start. Repeated start shares the first-use result; currentAttachment stays null until verified. Wake delivery after local commit, verified first/reconnect, restored capability and receipt clearing pending; retry previously uncertain retained work.
2. Full snapshots atomically replace canonical resources/inverse rows, preserve pending journal/session positions/original identity, merge receipts without reapplying covered deltas, and rebase once. Snapshot/subscribe accept pending IDs; the Node gate captures exact receipts/missing partition with resources/checkpoint. Missing acknowledged commands conflict; missing unacknowledged commands stay deliverable. Immutable inputs/positions must match; retain admitted identity and Node epoch, ending the lifetime on epoch change.
3. Replace service isInitialized/sessionStatus/duplicate nullable fields with initialized: IInitializedServiceSession | null across core/React/DevTools. Prepared replica stays private; offline may retain optimism, blocked withdraws capability. Remove redundant serviceVersion props/setSessionId, keeping explicit lifetime sessionId. Extend standalone inert cancellation while preserving explicit reset. Join open/pump work before DB closure, attempting all cleanup phases.

### 7. Deployment

1. Parent loads project, returns generated keys if missing without cloud work, opens scoped Wrangler workspace, stages candidate, opens candidate SystemApi, accepts once before promotion, promotes, polls addressed Worker version read-only, then initializes. Delete literal healthcheck and string-dispatched requestSystem.
2. Replace unstable_DevEnv and listener-source inspection with a child wrangler dev forwarder. Loopback, port zero, noninteractive, generated empty env file; retain remote bindings (no --local). Consume streams, strip ANSI, match real Ready on URL; race early exit and 60-second timeout. Upload secrets via mode-0600 file, inherit Cloudflare credentials, clean scoped files. Decode structured JSONL on failures as well as success; only Cloudflare code 10007 means missing Worker.
3. Explicit initial/stageRequested/staged/promotionRequested/promoted compensation state. Arm before cloud mutation and record invocation message. Require incumbent at 100%; recheck after upload and before promotion. Roll back only owned incumbent-100/candidate-0 stage. If candidate is actually 100% after lost acknowledgement, retain promotion and report incomplete readiness. First install has no deletion rollback. Poll 1 second, bounded 180 seconds; authentication/definitive refusal fatal. Preserve primary failure/interruption while reporting cleanup failures. First incompatible API/schema cutover uses a fresh isolated prerelease backend; no automatic fallback over an old backend.

### 8. Studio

1. One RepoTypeSchema derives IRepoType. Replace 28 per-kind API methods with getRepoRegistrations({repoType}) and getRepoTableRows({repoType,repoName,tableName}). Require registration once; exhaustive concrete Repo resolver parses physical names but uses retained systemId. Concrete Repo validates tables; no arbitrary SQL. Delete superseded methods and refusal variants.
2. One HTTP broker with request decoding/execution, independent cancellation/telemetry/final flush. Preserve repo/error routes; replace local agent RPC with GET IDs query and POST JSON ticket opening. Invalid inputs 400, unknown API routes 404, non-API next. Parse percent encodings inside failure boundary. Return public Success/Failure only, fixed unexpected-defect message, no diagnostic stack/cause/secrets; no-store.
3. Shared abortable fetchStudioJson decodes public outcomes and domain success schemas. Update RepoExplorer, error reader, agent IDs and opening. Preserve SWR identity/cache/dedup/focus/reconnect/no polling.
4. Pure Vite config preserves agents.ts/SystemSpec and current host/port/aliases. openStudioServer returns {url,dispose}, startup requires AbortSignal. Feature-local CLI useStudioServer owns cancellation/late-acquisition disposal. Memoized shutdown stops request admission, aborts/joins local requests, closes Vite and listeners. Remote admitted work remains server-owned. No storage change.
