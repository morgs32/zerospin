# 114 — Native persistent session with one lifetime and handoff owner

1. **Implementation status:** implemented and verified in the approved goal on 2026-10-11.
2. **Method shape:** establish inputs, run named domain steps in order, and return the owned result. Helpers own behavior and invariants; moving an entire monolith to a differently named file does not satisfy this plan.

3. **Problem and evidence**
   1. [makeNativeSession](/Users/morgs32/GitHub/zerospin/packages/native/src/makeNativeSession.ts:1) opens the durable Node client before its cleanup boundary, initializes session storage, duplicates command flushing/retry and failure reporting, and closes Node storage after only synchronous synchronization stop. Repeated dispose returns early rather than sharing its drain; a cleanup rejection can skip later closes. These are real resource and concurrency problems.
   2. Its authored definition accepts an opaque aggregate ID, but initialization later decodes only `acct_` IDs at [line 210](/Users/morgs32/GitHub/zerospin/packages/native/src/makeNativeSession.ts:210). Valid aggregate IDs therefore fail after storage has already opened. This arbitrary legacy prefix is not part of the aggregate identity model.
   3. [openNativeSqlite](/Users/morgs32/GitHub/zerospin/packages/native/src/openNativeSqlite.ts:1) is already a focused host driver; retain it. The native README assigns serialized SQLite/network/crypto/timer execution to the Swift/JavaScriptCore host. Root's complete Swift host review verifies that [JavaScriptExecutor.load](/Users/morgs32/GitHub/zerospin/packages/swift/Sources/Zerospin/JavaScriptExecutor.swift) already acquires a Darwin `flock(LOCK_EX | LOCK_NB)` on `.runtime.lock` across the storage directory and owns one serial DispatchQueue; close releases it. Preserve that real exclusive lifetime rather than introducing another lock.
4. **Proposed owners and scope**
   1. One native session lifetime owns an application runtime, durable Node owner, durable session replica, command handoff and connected transport. Construction runs finite initialization and returns its facade; background work remains owned children. Use the existing session lifecycle semantics and shared replica/handoff owners rather than another native flush/retry loop.
   2. Native persistence is still two distinct files: canonical local Node and application session journal/projection. Preserve their ownership and checkpoint meanings. Persistent session bootstrap opens/validates its existing journal, then reconciles it with the Node under the same core projection transaction used by browser sessions.
   3. The existing Swift executor is the native storage owner; its directory flock covers all Node/session files and its serial DispatchQueue orders JavaScriptCore/SQLite access. TypeScript file owners are children of that lease. `Session.initialize` currently awaits load before setting loaded, so concurrent MainActor calls can start duplicate loads on the same executor. Replace the loaded boolean with one owned initialization Task/promise and explicit idle/starting/active/closing/closed transitions. Concurrent initializes join it; dispose fences/cancels it; late completion cannot publish or retain a replacement context.
   4. `Session` publication currently schedules an unfenced MainActor Task. Capture the current lifetime identity when scheduling, and recheck closing/disposed plus exact lifetime before applying a snapshot. Disposal withdraws publication immediately. `SQLiteHost.open` must close the raw sqlite3 handle on open/PRAGMA failure before it enters the retained database map. Executor load already has catch/close cleanup; preserve it.
   5. Swift disposal currently waits for JavaScript dispose before host cancellation. JavaScript disposal must retire local opaque network/RPC awaits immediately, then drain accepted SQL and close clients, so it cannot wait forever for a remote reply. Swift invokes this finite disposal and always calls executor teardown afterward even if it rejects; host close cancels remaining timers/fetches/sockets/replies, closes SQLite and releases flock. Do not destroy the JavaScript context or close host SQLite before the accepted SQL drain. The 422-line `host.js` contains consumed platform adaptations; retain them and change only necessary cancellation/publication integration.
   6. Native remains aggregate-first with its current supported application-services scope. Do not expand release/authentication/provider features incidentally.
5. **Ideal parent and contracts**

   ```ts
   const initializeNativeSession = Effect.fn('initializeNativeSession')(
     function* (props: INativeSessionProps) {
       const binding = decodeNativeSessionBinding(props);
       const node = yield* openNativeNodeOwner(binding);
       const replica = yield* openPersistentAggregateReplica({ binding, node });
       const handoff = makeSessionCommandHandoff(replica);
       const connection = yield* connectNativeAggregateNode({
         binding,
         node,
         replica,
       });
       yield* reconcilePersistentAggregateReplica({ node, replica });
       return makeNativeSessionControls({ node, replica, handoff, connection });
     },
   );
   ```

   1. `decodeNativeSessionBinding` validates API/definition/claims and exact aggregate identity before any storage is acquired. Aggregate ID follows the existing opaque identity schema; remove the `acct_` restriction. Coordinate the existing [opaque aggregate ID plan](086-plan-opaque-aggregate-ids.md) and mark its native requirement fulfilled only after this implementation. Clone supported mutable binding inputs as required by the authored definition.
   2. `openNativeNodeOwner` runs under the already acquired Swift executor storage lease, opens/initializes the Node DB and returns the same typed Node/quiescence/transport ownership contract as connected browser workers. Startup failure/interruption attempts all acquired cleanup and releases ownership.
   3. `openPersistentAggregateReplica` receives a fixed declaration and the Node owner; opens the exact session file, rejects unsupported nonempty fixed schemas, provisions empty storage, validates stored session identity and returns the typed replica. Preserve the pre-release empty-storage policy; do not translate older rows.
   4. `reconcilePersistentAggregateReplica` uses the actual Node journal/epoch and core snapshot/page reconciliation procedures. Already handed-off originals and authoritative finals remain distinguishable; cached projection reuse cannot bypass binding/checkpoint validation.
   5. `suspend` fences and stops connected work while retaining durable session/Node state; `resume` restarts the owned attempt and handoff. `clearAuthentication` revokes capability before clearing Node authorization and replica publication. `dispose` fences all commands and shares one terminal drain promise: stop connection, drain handoff and Node SQL/subscriber work, dispose execution, close both clients, then let the Swift executor owner release its directory lease after context teardown. Attempt every cleanup, then report the first cleanup failure.
